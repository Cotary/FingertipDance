## 1. 广告位与触发点

| 广告位 | 类型 | 触发点 | 频控/规则 |
|---|---|---|---|
| `hint` | 激励视频 | 每关第一次点「提示」 | 每关首次提示必须看广告，之后免费（`needsAdForHint`）。**次数由后台 `ad.hintFreeUses` 配**：0 = 首次看广告（现行），N = 前 N 次免费、第 N+1 次付一次 |
| `skip` | 激励视频 | 点「跳过」 | 本关每日 1 次（`canSkipToday`/`markSkippedToday`，服务端兜底）；跨关的**每日总上限**由后台 `ad.skipDailyLimit` 配（0 = 不限） |
| `skin_unlock` | 激励视频 | ① 主题页未解锁的 **ad 档主题**（大卡金色按钮）② 皮肤网格里 ad 档皮肤 | 客户端只判「有没有额度」，**真正放行在服务端**：`POST /api/cover/unlock` 复核该 id 的 `unlock.type` 必须是 `ad`，再原子追加到 `users.unlocked_themes` / `unlocked_skins`。重复调用返回 `already: true` |
| `result_interstitial` | 插屏 | 通关结算页入场后 500ms | 60 秒频控（`Ads.lastInterstitialAt`） |
| `skin_banner` | Banner | 进入皮肤页显示 / 离开隐藏 | `openSkins`/`closeSkins` |

### 3.1 「看广告次数」怎么落到后端（2026-11-22）

`users.ad_watch_cnt` 这一列从 001 就有、后台玩家详情页也在读，但**长期没人写过** ——
界面那个「看广告次数」永远是 0。现在两条路都接上了：

```
Ads.showRewarded()
  ├─ completed === true          → noteRewarded()   // 正常看完
  └─ catch（SDK 挂了）           → noteRewarded()   // 兜底发放也算一次
        ↓
   onWatched 回调（main.ts 注册）
        ├─ progress.sync({ adWatchCnt: +1 })      // 本地立刻 +1，界面即时反馈
        └─ POST /api/cover/ad-watch               // 服务端 UPDATE ... +1 RETURNING
              → 用回包覆盖本地值（多设备/重装后收敛到真实值）
```

三条规矩：

- **回调挂在 `Ads` 上，不挂在四个调用点**（提示 / 跳过 / 解锁主题 / 解锁皮肤）。
  漏一处就是「某类广告不计次」，而界面上只看得出数字偏小。
- **兜底发放也计数**：广告 SDK 故障时玩家照样拿了奖励，统计上就是一次曝光。
- **不塞进通关事务**：通关被判路径非法时广告其实已经看完，
  跟着回滚会让「越可疑的请求越不计数」。

## 4. 关键设计决策

1. **广告失败兜底发放**：`showRewarded` 的 catch 返回 `true`，避免玩家点击无响应。
2. **中途退出不批评**：只记 `ad_abort`，不弹提示。
3. **跳过不发皮肤**：跳过走 `/api/skip` 接口（服务端 `applyProgress` 里 `Skipped` 时不发皮肤），与通关 `/api/progress` 分离。
4. **跳过后 `max_level` 仍推进**：否则玩家卡死。
