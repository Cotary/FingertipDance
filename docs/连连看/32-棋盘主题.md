# 32 · 棋盘主题（6 套）

> 目标：把「换皮肤」从**换色相**升级成**换主题** —— 背景、棋盘格、路线、机制图标按同一套语言重画。
> 本文是设计方案，不含实现。日期：2026-11-12

---

## 一、先诊断：现在的「皮肤」到底换了什么

`src/render/skins/index.ts` 里，一个皮肤只有 6 个字段：

```ts
{ id, name, tier, unlockType, unlockValue, hue, sat, light, texture }
```

`paletteOf()` 用 HSL 派生出 `base / light / dark / border / glow` 五色，然后：

| 层 | 现在由谁决定 | 换皮肤时变不变 |
|---|---|---|
| 背景 / 底板 | `clayBackdrop()`、`drawCoverPlate()` 里写死的 `CLAY.*` | **不变** |
| 格子面 | `paletteOf()` 派生 + `paintSkin()` 纹理 | 变 |
| 格线 | `skinClay(p).shade` | 变 |
| 路线 / 线头 | `drawCoverTrail()` 传 `CLAY.terracotta` | **不变** |
| 机制图标（星/钥匙/门/冰/传送/单向） | `drawCoverMarks()` 里写死的 `CLAY.gold / mint / rose …` | **不变** |
| 提示高亮 | `coverBoard.ts` 里写死的暖金 | **不变** |

**结论：16 个皮肤实际只作用于「格子面」这一层，占整个画面不到 40%。**
所以玩家换完皮肤的感受是「格子变色了」，不是「换了个世界」。这就是为什么纯加皮肤条目没有意义 —— 得先有主题包这个概念。

---

## 二、主题包的定义

一套主题 = 5 个通道，缺一个就不成立：

```
BoardTheme {
  backdrop   背景层      宫格外的世界（远山 / 极光 / 天空 / 星海 / 糖霜 / 水光）
  plate      底板        格子缝隙、VOID 缺口露出的那层料
  cells      格子材质    明格 / 暗格 / 障碍 / 冰面（4 种表面）
  icons      图标语言    9 类机制图形（形状族 + 配色）
  trail      线的语言    已走线 / 线头 / 终点环
}
```

### 为什么图标必须独立成一层

图标现在是「黏土筹码 + 符号」，形状语言统一：圆盘底、奶油色、深色描边。
到了霜之国，星应该是**冰雕的六角雪花**，不是「金色圆盘上画个星」。
到了青竹，钥匙应该是**铜锁 + 朱砂绳**，不是「圆盘上画个钥匙」。

**只换颜色不换形状，主题一定穿帮。**
这是这次改造里工作量最大、也最值钱的一块。

## 三、三条硬约束（任何主题都不能破）

这三条是评审门槛，不是建议。

### 1. 线必须压得住格子

Cover 玩法的全部信息都在「线走到哪了」。所以每套主题必须留一个**与格子色相差 ≥ 120° 或明度差 ≥ 35%** 的线色：

| 主题 | 格子色 | 线色 | 对比方式 |
|---|---|---|---|
| 青竹 | 竹青 | 朱砂 `#C0392B` | 补色 |
| 霜之国 | 冰白 | 极光青 `#5FD8D8` | 明度 + 冷光 |
| 水管乐园 | 砖红 | 亮红 `#E63946` + 白描边 | 饱和度 |
| 夜航星图 | 深蓝 | 暖金 `#FFC95C` | 冷暖对立 |
| 糖霜铺子 | 马卡龙 | 可可 `#7A4A3A` | 明度差 40% |
| 深海遗迹 | 青石 | 珊瑚 `#FF7A59` | 补色 |

**反例**：糖霜铺子如果用粉色线，铺在粉格上等于没画。这是最容易翻车的一套。

### 2. 明暗格差 ≥ 8% 明度

低于 8%，手机上格线糊成一片，玩家数不清格子 —— 而 Cover 要求「铺满」，数不清格子等于玩不了。
夜航星图是最危险的：深底上两个深蓝，差值必须靠 `#24365E` vs `#1B2A4E` 这种精确的 6~10% 卡住。

### 3. 图标必须过剪影测试

格子在小屏上约 28 CSS px。图标设计完必须缩到 28px 转纯黑，还能认出是什么。
过不了就加**轮廓特征**，不能靠颜色区分 ——「金色的是星、蓝色的是冰」这种规则色盲玩家直接失效。

> 特殊项：冰面 `ICE` 是最容易和普通格混淆的。规定：冰面必须比同主题普通格**更亮 + 更透 + 有裂纹**，三条至少占两条。

## 四、六套基础主题（**已裁掉**，保留备查）

> 这一节保留的理由只有一条：以后有人想「再补几套基础档」时，先看这里为什么被砍。
>
> 2026-11-13 的决定：**只做四套典藏（玻璃 / 圆格 / 黑曜 / 金线），六套基础全部删除**。
> 判据就是第五节那条 —— 把颜色抽掉只看灰度，六套认不出彼此，
> 那只是换了色板。做出来玩家会问「这不都一样吗」，多一个入口只多一次失望。

### 1. 青竹 · 水墨棋院

最耐看的一套，也是最安全的默认值。

- 背景：宣纸米白 `#F3EAD8`，远山淡墨，右下角一枝竹影
- 底板：深墨绿 `#2C4034`（像砚台）
- 格子：竹青 `#A8C39A` / 浅竹 `#C6DAB6`，格线细如竹节
- 线：朱砂 `#C0392B`，线头是白瓷小环
- 图标：**印章语言** —— 方形朱红底、白文浮雕；星 = 梅花，钥匙 = 铜锁，门 = 月洞门，冰 = 霜裂
- 卖点：和「一笔画走遍全图」的书法气质天然咬合；不抢线，长时间玩不累

### 2. 霜之国 · 极光冰原

冰雪奇缘的**气质**（北欧极夜 + 极光 + 冰晶），不是它的角色。

- 背景：深蓝夜 `#16324D` → 极光青绿，缓慢流动的光带 + 飘雪
- 底板：冰裂缝 `#0E2438`
- 格子：半透明冰砖 `#DCEFFA` / `#BFE1F7`，边缘一道霜光；暗格带内裂
- 线：极光青 `#5FD8D8`，微发光
- 图标：**冰雕语言** —— 六角雪花（星）、冰钥匙、冰拱门、冰面 = 厚冰层（比普通格更亮更透）
- 卖点：`ICE` 机制和主题天然咬合，冰面格不用额外设计就自洽；截图最惊艳

### 3. 水管乐园 · 蘑菇谷

马里奥的**类型语言**（天蓝 + 砖块 + 问号块 + 绿水管），原创表达。

- 背景：经典天蓝 `#5C94FC` + 白云 + 远处绿丘
- 底板：草绿 `#3AA03A`（格子缝里露出草），VOID 缺口露砖土 `#8B5A2B`
- 格子：红砖 `#C86B3C` / 亮砖 `#D9814F`，砖缝错位；障碍 = 石砖，单向门 = 箭头砖
- 线：亮红 `#E63946` + 1px 白描边（像素游戏的路面感）
- 图标：星 = 无敌星（五角 + 眼睛）、钥匙 = 小铜钥匙、门 = 城堡门、冰 = 蓝砖
- 卖点：最强的「熟悉感」，一眼就懂怎么玩

### 4. 夜航星图 · 星尘航线

和玩法叙事最贴的一套：铺满 = 把星座连完。

- 背景：深靛 `#0B1230` + 星点 + 一抹银河
- 底板：更深的靛 `#070C22`
- 格子：暗蓝玻璃 `#24365E` / `#1B2A4E`，四角一点星尘
- 线：暖金 `#FFC95C`，带外发光
- 图标：**星座语言** —— 星 = 四点星芒、钥匙 = 罗盘、门 = 星门环、传送 = 双星连线
- 卖点：深色背景下线路发光，视觉冲击最强；适合做分享图

### 5. 糖霜铺子 · 马卡龙拼盘

- 背景：奶油粉 `#FFE3EC` + 糖霜颗粒 + 顶部一抹打发的奶油
- 底板：草莓酱 `#F2C6D8`
- 格子：薄荷 `#A8E6DA` / 草莓 `#FFC2D6` 交替（也可三色循环：+ 柠檬 `#FFEFA8`）
- 线：可可 `#7A4A3A`（**必须深色**，粉色线会消失）
- 图标：软糖星、饼干钥匙、糖霜门、冰 = 透明果冻块
- 卖点：女性向、轻松；分享图好看

### 6. 深海遗迹 · 沉船石板

- 背景：深青 `#0E3B4A` + 斜射光柱 + 上升气泡
- 底板：珊瑚砂 `#C9A87C`（石板缝里露出沙）
- 格子：湿石板 `#4E7C7A` / `#436F6D`，带苔痕和贝壳刻纹
- 线：珊瑚橙 `#FF7A59`，带一点水下折射的抖动
- 图标：**遗物语言** —— 星 = 海星、钥匙 = 贝币、门 = 珊瑚拱、传送 = 漩涡
- 卖点：色彩最「高级」，和现有黏土绘制技法兼容度最高（都是厚涂块面）

## 五、高级档：换语法，不是换色板

### 5.1 为什么前六套「大差不差」

它们共用同一套**构成语法**：

```
双色棋盘格（同尺寸圆角方块） + 一条纯色圆头线 + 同款单色图标 + 深色底板
```

变的是**词**（色相、名称、纹理），没变**句法**。
这跟我上面批评的「旧皮肤只换色相」是同一个错误，只是抬高了一层。

基础档这样没问题 —— 基础档的职能是「稳、耐看、不抢线」，六套确实做到了。
**但高级档如果也只是换色，那它就不该叫高级。**

### 5.2 高级感 = 约束 + 材质 + 光

不是「更多颜色、更多特效」。判据只有一条：

> **把颜色抽掉、只留灰度，还认得出是哪一套吗？**

认得出 = 换的是语法；认不出 = 只是换了色板。

### 5.3 六条轴，一套只占一条

| 轴 | 换掉的是什么 | 主题 |
|---|---|---|
| **材质** | 格子从「实心块」变成「透光块」 | 玻璃穹顶 |
| **几何** | 格子从「方格」变成「圆心」 | 圆格罗盘 |
| **光源** | 光从「外面打进来」变成「从线里发出去」 | 黑曜熔岩 |
| **秩序** | 格子从「有色块面」变成「只有线」 | 金线装饰 |
| **笔触** | 格子从「矢量块」变成「手作印痕」 | 浮世绘版画（待定） |
| **空间** | 平面 → 有高度和投影 | 折纸立体（待定） |

一套主题**只能占一条**。占两条就会变成「特效堆」，反而廉价。
这是硬规则，评审时按这条打回。

### 5.4 四套已出图

#### 玻璃穹顶 · 材质轴

- 底板 `#0E1E2E`，格子是**圆角更大的半透块**（r≈26% 格宽），块间留缝
- 关键：格子颜色不是纯色，是**底色 + 一层白**，四档明度错开，读作「厚玻璃叠在一起」
- 一道斜向的白色低 alpha 光带横穿整块板 —— 这道带子是全图的灵魂，没有它就是一盘蓝方块
- 线：冷白 `#EAF6FF`，比任何格子都亮，像光在玻璃里走
- 图标：透明材质 + 白色描边，不做填充

> **手机上的现实**：格子约 28 CSS px，真实折射完全看不见。
> 所以「玻璃感」只能靠三件事表达：**块间留缝、四档明度、一条大尺度光带**。
> 细节纹理（气泡、反射）一律放弃 —— 缩到 28px 就是噪点。

#### 圆格罗盘 · 几何轴

- 格子是**圆**（r≈38% 格距），格与格之间只有虚空
- 线变成一条**缎带**，穿过圆心，圆心留一个底色小点 —— 读作「珠子穿在绳上」
- 这套的杀手锏是：**路线不再受格子边界约束**，视觉上是一条连续的绳
- 线头是一个空心环，不是实心点

> **风险**：圆与圆之间没有边界，玩家可能读不出「哪两格相邻」。
> 补救：底色留极淡的方格暗纹（2% 明度差）+ 圆心小点定位。
> 这条必须在真机上验，验不过就退回「圆角方块」。

#### 黑曜熔岩 · 光源轴

- 底板接近纯黑 `#0A0908`，格子是**带裂纹的火山岩**，几乎不发光
- 光全部来自**线**：四层描边（外辉 16% → 中 55% → 亮 6px → 芯 2.5px 近白）
- 这套的语法是「**黑暗里只有你走过的路在燃烧**」—— 和 Cover 的叙事完美咬合
- 图标用余烬色，不做描边，像刚冷却的岩浆

> **风险**：自发光最容易过曝。线芯必须够亮、外辉必须够淡，
> 中间只要有一层偏亮就会糊成一条橙色香肠。四层的宽度比要卡死（24 / 13 / 6 / 2.5）。

#### 金线装饰 · 秩序轴

- **没有格面**。底板一整块深翡翠 `#0F2E28`，只有 1px 金线画格
- 线是 4px 金线，**每个转角放一颗菱形** —— 像珠宝的镶爪
- 四角有极小的装饰切口
- 这套一个特效都没有，最贵，因为**克制**

> **风险**：没有格面填充，「已走 / 未走」的对比只剩线宽和线色，铺满感会弱。
> 补救方案（二选一，需实测）：
> a) 已走格加 3% 暖白填充 —— 几乎看不见但能读出「这块被占了」
> b) 不加，靠线的密度表达 —— 纯靠克制，但小屏可能读不出进度

### 5.5 另外两个方向（先不做，留给第二批）

- **浮世绘版画**：平涂色块 + 粗墨线 + 纸纹 + 故意错位的套色。零渐变，靠「印」的质感。技术上最便宜（全是不透明块），风格最独特
- **折纸立体**：格子有厚度和投影，整盘像一张折起来的纸，路线是折痕。视觉最惊艳，但要处理光照方向一致性问题，工作量是前四套之和

**建议砍掉折纸**：收益/成本比最差，且和「平面棋盘」的玩法认知冲突。

### 5.6 为什么这些特效在手机上跑得起

已经有现成的地基：`coverBoard.ts` 里的 `buildPlate()` / `newPlateCanvas()`
会**把整块底板烘焙进离屏 canvas，整关只算一次**。

所以：

| 主题 | 烘焙进 plate（一次） | 每帧只画 |
|---|---|---|
| 玻璃 | 格子块 + 光带 + 四档明度 | 线、线头、图标 |
| 圆格 | 全部圆 + 圆心暗纹 | 缎带、环、图标 |
| 熔岩 | 石纹 + 裂纹网络 | 4 层线、图标 |
| 金线 | 整张金网格 + 角饰 | 线、菱形、图标 |

**四套的每帧开销都不高于现在的黏土版**（金线甚至更低：画 8 条线 vs 画 100+ 个格块）。
高级感不花性能，花的是**设计约束**。

### 5.7 解锁梯度

| 档 | 主题 | 解锁 |
|---|---|---|
| 基础 | 6 套（青竹 / 霜之国 / 水管乐园 / 夜航星图 / 糖霜铺子 / 深海遗迹） | 默认 + 广告 |
| 高级 | 玻璃穹顶 / 圆格罗盘 / 黑曜熔岩 / 金线装饰 | 通关 200 / 400 / 700 / 900 |

高级档不放广告 —— 广告解锁的东西不配叫典藏。这一点和现有 `tier: premium` 的规则一致。

### 5.8 先做哪套

**金线装饰**。理由：绘制量最小（比现在还少）、差异最大（没有格面，一眼就不同）、
且它最能验证「主题包」接口是否真的解耦 —— 如果连「不画格面」都能塞进同一套接口，其余三套都是填表。

第二套做**黑曜熔岩**：分享图效果最好，适合先攒传播素材。

## 六、关于「马里奥 / 冰雪奇缘」这类 IP

**直接做会出事。** 需要区分三件事：

| | 能不能用 |
|---|---|
| 玩法类型（平台跳跃砖块、三消、跑酷） | ✅ 可以 |
| 视觉**风格**（天蓝 + 砖块 + 问号方块；北欧冰雪 + 极光 + 六角雪花） | ✅ 可以，这属于通用视觉语言 |
| 具体**角色**（红帽水管工、蓝裙公主）、标志性 logo、专属配色组合 + 角色同框 | ❌ 侵权 |

所以第 2、3 套的设计原则是：**拿题材，不拿角色。**

- 可以做：绿水管、砖块地台、问号方块、无敌星（五角星是通用符号）
- 不要做：红帽胡子的小人、印着 M 的帽子、蓝色冰裙 + 麻花辫的公主形象、任何「冰雪奇缘」字样

风险最高的其实是**名字**。所以清单里用的是「水管乐园」「霜之国」，副标题也刻意避开原名。
如果只是想借势，可以在商详页写「致敬 8-bit 平台跳跃」，而不是写 IP 名。

> 需要法务确认的话，这条得单独过一遍；我给的六套都按「原创 + 类型致敬」设计，不依赖授权。

## 七、落地路径

分三步，每步都能单独上线：

### 第一步：主题包抽象（不动视觉）

```ts
// src/render/themes/types.ts
export interface BoardTheme {
  id: string; name: string; tier: SkinTier; unlockType: UnlockType; unlockValue: number;
  backdrop: { sky: string; mid: string; ground: string; motif: MotifKind };
  plate: ClayColor;
  cells: { light: ClayColor; dark: ClayColor; block: ClayColor; ice: ClayColor };
  icons: { family: IconFamily; ink: string; chip: ClayColor };
  trail: { line: string; outline: string; head: string };
}
```

`Skin` 保留兼容（旧档位数据不用迁移），`BoardTheme` 作为它的超集：
`themeOf(skin)` 先查主题表，查不到就回退到「HSL 派生」的旧行为。

改动点：`board.ts`、`coverBoard.ts`、`coverTrail.ts`、`clay.ts` 里所有 `CLAY.*` 常量改成从 theme 取。

### 第二步：图标族抽象

## 十、金线装饰 · 首版实测记录（2026-11-12）

通过画廊 `?theme=gilded` 挂载，`coverBoard.ts` / `coverTrail.ts` / `main.ts` 一行未改。

### 10.1 怎么跑

```

                        &hint=1        叠一条提示窗口
                        &zoom=2.4&fx=270&fy=560   放大审图
```

### 10.2 四个设计假设，验完三个、修了一个

| 假设 | 结果 |
|---|---|
| 不画格面，光靠金线也能数清格子 | **成立**。1px 金线在 9×9（格约 75 设计 px）上清清楚楚，不需要兜底填充 |
| 金箔能表达「已铺进度」 | **初版失败**。8.5% 的金铺上去几乎看不见，45/90 读起来像没铺。提到 **23%** 才立得住 |
| 图标可以直接画在金箔上 | **失败**。金线图标落在金箔上是金压金，707 的门直接消失。必须加暗色镶座 |
| 虚框能替代脉动环做提示 | **成立**。5 格虚金框由亮到暗，和整盘同源，不引入新形状 |

### 10.3 踩到的三个坑

1. **柔光镶座 = 一团脏**
   第一版用径向渐变做图标底盘，2.2 倍放大后是一团发糊的阴影，读作「脏」。
   改成**硬边暗盘 + 一道细金环**（宝石是嵌进去的，不是晕开的）才干净。
   这条对后面所有深色主题都适用：**深底上不要用柔光做隔离，要用硬边。**

2. **以为格线被金箔盖住了，白改了一轮**
   实拍发现已走区域糊成一整块浅色，判断是 `drawGrid` 在金箔之前画。
   把顺序对调后截图 **md5 完全一致** —— 因为金箔是 `fillRect(px+1.5, …, cell-3)`，
   内缩 1.5px 本来就压不到格线。改了个寂寞。
   教训：改画序前先看填充矩形是否内缩，否则会在「已经正确」的地方反复折腾。

3. **画框与盘面撞车**
   背景画框原先在 26/34，而 `computeLayout` 的 `BOARD_SIDE = 40`，
   内框线离盘面只剩 6px，挤在一起。画框收到 16/24 才让出呼吸。

### 10.4 这套验证了什么

- 主题包接口**能容纳「不画格面」这种极端语法** —— 反过来证明第五节 5.3 的六条轴是可行的，
  不是纸上谈兵。
- 深色主题**额外需要一条规则**：任何图标都需要「隔离层」（硬边暗盘 / 描边 / 副底色），
  否则会和底色或金箔糊在一起。这条要写进 `BoardTheme` 的接口约束里。
- 每帧开销与黏土版持平（都是几十次 stroke + 十几次 fill），没有引入 `filter` / `shadowBlur`。

### 10.5 已知未做

- 起终点用「圆 + 内接三角 / 方框」，在 5×5 大格上三角容易被读成「播放键」。可换成菱形 / 双环
- 传送门的跳段目前是断线 + 两端菱角；正式版要不要画弧线还没定
- 未做 OpenGL 分离，仍在主 canvas 上画（验证用，够用）

## 十一、最终交付：四套 + 皮肤页入口（2026-11-13）

### 11.1 留下了什么，删了什么

| | 内容 |
|---|---|
| 保留 | `glass` 玻璃穹顶 / `orbit` 圆格罗盘 / `obsidian` 黑曜熔岩 / `gilded` 金线装饰 |
| 删除 | 六套基础主题（`specs.ts` 206 行数据 + `family.ts` 747 行通用渲染器） |
| 删除 | `glyphs.ts` 里只为基础档存在的 `pixel` / `candy` / `relic` 三套笔触 |

删除后 `glyphs.ts` 从「9 几何 × 6 笔触」收敛到「9 × 3」，
注册表从 10 套降到 4 套，构建产物 gzip 91.6KB（含主题，+10KB）。

### 11.2 皮肤页长成了「皮肤 / 棋盘」两页签

同一条骨架（页签 → 展台 → 铭牌 → 陶片），台面上的东西不同：

- **皮肤页**摆的是「一块料」（黏土样品板）
- **棋盘页**摆的是「一整块盘面」，而且是**真渲染**，不是截图

真渲染这条是硬要求：主题的价值全在渲染器里（背景光带、图标族、线画法），
静态图会随主题改动过期，而真渲染永远和游戏内一致。

- 展台：6×6 假盘面，`cell≈73`，六种机制各摆一个，路线铺三行
- 陶片：**4×4 小盘**（不是把 6×6 缩小）。116px 宽里塞 6 列，每格只剩 16px，
  图标糊成噪点、格线黏成一片，五块陶片看起来一模一样
- 0 号陶片是「经典」= 不启用主题，手画一块 4×4 黏土砖盘 + 陶土线
  （只铺一块蓝色底会被读成「没加载出来」）

### 11.3 主题必须接管界面，否则只换了一半

实测金线主题进关后：盘面深翡翠，黏土 UI 直接失效 ——

| 部件 | 失败表现 |
|---|---|
| 关号胶囊 | 陶土橙压在深绿上，像贴错了图 |
| 返回 / 跳过 | 奶油色块成了全屏最亮的东西 |
| 「起点自由」小字 | 深棕墨色，在深底上**几乎看不见** |
| 进度条槽 | 「压进桌面的沟」这个隐喻失去底面，读作一根棕棒 |

所以 `BoardTheme` 加了 `chrome`（10 个颜色：pill/primary/ghost/ink/groove/fill…），
`drawHud` / `drawButton` / `drawProgressBar` / `drawCoverFreeStartHint` 全部接受它。
**不传 = 黏土**，经典盘面零变化。

### 11.4 三个新踩的坑（都不是「调个色」能解决的）

1. **深色基色不能按浅色的比例提亮**。`clayBlock` 要 4 个色阶，为省事写了
   `clayFrom(基色)`：亮面往白推 26%。中灰上只是「亮一点」，近黑上直接跳到中灰 ——
   深色主题的按钮实测变成一片脏灰，玩家读作「禁用」。
   改成按亮度分档：`luma < 96` 只推 13%。

2. **真正把按钮洗白的是那两圈哑光反光**，不是色阶。`clayBlock` 里有
   `rgba(255,255,255,0.14)` + `0.09` 两个大椭圆，是按浅色黏土调的。
   同样的白光打在深色块上就是一层奶。加 `ClayOpts.gloss` 倍率，主题传 0.28。

3. **圆格主题的「相邻」必须靠暗纹兜底**。圆与圆之间没有边界，
   11×11 上读不出哪两格相邻就等于玩不了。`drawPlate` 里那层 4.5% 白方格暗纹
   不是装饰，是这条玩法的保险 —— 真机验不过就退回圆角方块。

### 11.5 已知未做

- 主题下的提示高亮是「一次性 5 格」，没有黏土版那套 70ms 错峰点亮
  （`litAt` 没有透传给主题）。功能一致，节奏差一点。
- 结算页仍是黏土面板（弹层可以中性，暂不改）。
- 解锁梯度 200 / 400 / 700 / 900，**调试构建全解锁**（`themeAllUnlocked`），
  否则测试环境要先打通 900 关才看得到金线。

## 十二、主题音效：四个世界，四种耳朵（2026-11-13）

### 12.1 问题：画面换了四个世界，耳朵还站在同一个房间

旧 `audio.ts` 一共 65 行，四个方法全是同一个形状：

```ts
light()  → tone(880, 30, 'square', 0.15)
break()  → tone(220, 120, 'square', 0.18)
win()    → 523 / 659 / 784 三角波
unlock() → 1046 / 1568 正弦
```

主题接管了背景、格子、图标族、路线、UI 配色之后，玩家**看到的**是四个世界，
**听到的**还是同一句方波。这比「没做主题」更糟：一半换了，另一半没换，
大脑会把它读成「这个换肤是假的」。

判据沿用画面那条，改成听觉版：

> **抽掉音高、只留音色与包络，还认得出是哪一套吗？**

把 880 改成 1046 不算 —— 那是换音高，和「只换色板」是同一个错误。

### 12.2 拆成三层

| 文件 | 职责 | 为什么这样切 |
|---|---|---|
| `render/voice.ts` | 四套音色的**纯数据**：给定第几步，吐出 `SoundNote[]` | 纯函数才能单测：`AudioContext` 在 node 里根本不存在 |
| `render/audio.ts` | 合成引擎：只认 `SoundNote`，负责振荡器 / FM / 滤波 / 混响总线 | 引擎不认识任何一套主题 |
| `main.ts` | 调度：什么时候推进乐句、什么时候只轻触 | 玩法节奏属于游戏层，不属于音色 |

音色层返回数据而不是自己操作 AudioContext，还带来一个好处：
四套的差异在代码里是**并排的四段数据**，可以静态审阅。
写成四段过程的话，越写越像，而且看不出来。

### 12.3 四套各占一条轴（与画面严格对齐）

| 主题 | 轴 | 合成结构 | 起音 | 空间 |
|---|---|---|---|---|
| 玻璃穹顶 | 材质 | 非谐波 FM，调制比 **3.52**；叠一层 2 倍频 90ms 正弦当「指甲划过杯口」 | **1.5ms** | 2.6s / 7kHz 阻尼（大厅） |
| 圆格罗盘 | 几何 | 三角波 140ms 拨奏 + 八度泛音；音高**往返** 0-1-2-3-4-3-2-1，每 8 步升八度 | 2ms | 1.9s / 5kHz（木厅） |
| 黑曜熔岩 | 光源 | 次低频**下扫** `f×2.6 → f` + 46Hz 体感层 + 噪声层（亮度 900→2400Hz 随连击上升） | **8ms** | 0.85s / 1.6kHz（洞穴） |
| 金线装饰 | 秩序 | 钟的模态比 **1 : 2.76**，900ms 长尾；每步两响（主钟 + 五度弱钟），奇数步再加八度 sparkle | 2ms | 2.2s / 4.5kHz（石厅） |

两处值得单独说：

- **调制比必须是非整数**。3.52 出玻璃，2.76 出钟；换成 3 或 4 就退化成普通泛音，
  听起来像玩具琴 —— 这是「材质」和「音高」的分界。
- **起音时间就是材质本身**。1.5ms 是硬的（玻璃、金属），8ms 是粘的（岩浆先鼓再破）。
  单这一个参数就把熔岩和「低音版玻璃」分开了，比改十个频率都有效。

### 12.4 混响是门槛，不是装饰

干声听起来永远是掌机蜂鸣器。四套的空间衰减差了三倍多（0.85s ↔ 2.6s），
这才是同一个音高听上去属于两个世界的真正原因。

IR（脉冲响应）是**代码生成**的，不用 wav：

```
噪声 × (1-t)^2.4 × 一阶低通(damp) → 12ms 预延迟 → 限幅到峰值 0.5
```

- 用幂次而不是线性：线性衰减听着像「被人掐断」，室内混响是幂次的
- 按 `damp` 算一阶低通系数 `k = 1 - e^(-2π·fc/sr)`：fc 越低尾音越暗，熔岩的洞穴感就靠它
- **限幅必须做**：暗的 IR 能量更低，不限幅的话反而「洞穴比大厅响」，`space.wet` 的比例全部失效
- 不用 wav 的理由：四套 × 2ch × 2.6s 是几百 KB，而指数衰减噪声在这个用途上听不出差别

### 12.5 连击是乐句：让「别断线」有听觉代价

`light()` 会推进 `step`，`break()` 把它清零。同一个动作，第 1 格和第 8 格不是同一个音：

| 主题 | 连击怎么走 |
|---|---|
| 玻璃 | 利底亚六声（含 #4）往上爬，封顶一个八度 |
| 罗盘 | **往返**，走远了被绳拉回来 —— 唯一不往上走的 |
| 熔岩 | 弗里吉亚（b2 贴主音）爬，噪声层越来越亮 |
| 金线 | 五声上行，奇数步多一记 sparkle（两响 = 线，三响 = 节点） |

断线时整条旋律归零。玩家不需要读任何文字，就能听出「我断了」。

配套的一条硬规则：**UI 声音和玩法声音必须分开**。
点页签、点陶片走 `tap()`，它**不推进乐句** —— 否则挑主题的过程会把旋律推高好几格，
进关时第一声就已经是高音区了。

### 12.6 换主题 = 换耳朵，发生在按下「装备」那一刻

- 装备：`preview(id)` = 切音色 + 播**签名动机**（1.2s，三到四个音）。
  玩家不用进关就知道这套是什么味道。
- 点陶片：`probe(id)` = 切音色 + 只播一声。连着点四套时播完整动机太吵。
- 展台铭牌加一行 `♪ 玻璃钟 · 2.6s 大厅` —— 音效是这套主题的一半，
  但玩家在展台上没有任何别的途径知道。这一行把隐藏卖点变成可见卖点。

`preview` 内部顺带调 `setVoice` 是有意的：装备和换音色本来就是同一件事，
拆成两步一定会有人忘了第二步。

### 12.7 顺手修掉的两个历史 bug

1. **「我的 · 音效」是个死开关**。`profilePage.soundOn` 改了，`audio` 从来没读过它 ——
   玩家以为静音了，进关照样响。这比没有开关更糟。现在 `setEnabled` 直接控 master 增益，
   并落盘到 `sound_off`（**不进 ProgressStore**：那份数据会被服务端回包整体覆盖）。
2. **通关音效不知道「完美」**。现在 `win(perfect)`：一次没撤销会多一声高八度闪光。

### 12.8 踩的坑

| 坑 | 表现 | 结论 |
|---|---|---|
| `exponentialRampToValueAtTime(0, …)` | 抛 RangeError 后**整条链静默**，不报错只是没声 | 终点只能是 0.0001 |
| 起音写 0 | 爆音 | 下限 1ms，且不超过音长的一半 |
| 每帧重建 IR | 2.6s × 48kHz × 2ch = 25 万次循环，明显掉帧 | `irFor` 记住烘过哪一套，只在换主题时重建 |
| 一帧连亮三格 | 9 个振荡器同时起振会削波 | 70ms 窗口内最多 3 次，超出丢弃 |
| 玻璃音阶爬到 14kHz | 手机上只剩刺耳电流味 | 封顶一个八度（2093 → 4186） |
| headless + `ConvolverNode` | `startRendering()` **永不 resolve** | 自检时把卷积换成直通，湿声连接由单测保证 |
| headless 节点一多就超时 | 玻璃 / 金线 5/5 卡死 | 自检降到 1.4s × 2 音，脚本最多重试 6 次 |

### 12.9 怎么验证（听不见也要能验收）

**单测 37 条**（`test/voice.test.ts`）：

- 音符合法性：时长 / 增益（≤0.25 削波线）/ 起音 > 0 且 < 半长 / 湿声 0..1
- 四套的**包络指纹两两不同**（这就是「不是只换音高」的机器判据）
- 每条轴都能被断言：玻璃 FM 比非整数、熔岩首音必须下扫、罗盘第 6 步必须回落、
  金线每步至少两响、熔岩起音是四套里最慢的
- 长连击不爬进超声波（第 39 步 < 12kHz）
- **假 AudioContext 跑真建图**：验「振荡器真的 start 了 / 有 stop」「FM 调制器接在载波 frequency 上」
  「噪声走 bufferSource」「增益斜坡没落到 0」「换主题会重烘 IR」

**离线渲染自检**（`npm run audio:check`，真 Chrome + `OfflineAudioContext`）：

```
ok   clay      peak=0.257 rms=0.0092 zcr=100Hz
ok   glass     peak=0.458 rms=0.0285 zcr=1641Hz
ok   orbit     peak=0.308 rms=0.0123 zcr=171Hz
ok   obsidian  peak=0.307 rms=0.0207 zcr=37Hz
ok   gilded    peak=0.338 rms=0.0349 zcr=2489Hz
ok   静音       peak=0.00e+0
```

`zcr`（过零率）是客观的亮度读数：100 / 1641 / 171 / 37 / 2489 五个数相差一个数量级，
说明 `setVoice` 真的换掉了音色，而不只是换了个音量。

### 12.10 已知未做

- **没有背景音乐**。有意不加：休闲品类里循环 BGM 的疲劳阈值很低，
  而且四套各一段会显著加包体。音效承担世界观已经够。
- **微信端只有震动**。小游戏没有 WebAudio，`ensure()` 返回 null，整条链静默降级。
- **没有音量滑杆**，只有开 / 关。真要做应该分「音效 / 音乐」两路。
- 结算页、提示按钮的声音已经走主题，但**提示高亮的那 5 格**仍是「一次响完」，
  没有黏土版那套 70ms 错峰（和 11.5 同源问题：`litAt` 没有透传）。
