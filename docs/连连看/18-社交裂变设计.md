# 社交裂变设计（实现落盘）

> 本文件是 T20「分享挑战」的设计与实现落盘。

## 1. 分享漏斗埋点

| 埋点 | 触发点 | 位置 |
|---|---|---|
| `share_click` | 点「分享」 | `src/main.ts` `doShare()` |
| `share_success` | 分享成功回调 | 预留（`platform.share` 成功分支） |
| `challenge_start` | 好友通过分享进入（`parseChallenge` 命中） | 预留（`boot()` 命中挑战时） |
| `challenge_result` | 挑战通关结算 | `src/main.ts` `onChallengeWin()` |

## 2. 挑战模式完整链路

```
好友 A 通关第 N 关 → 点「分享」→ 打开分享抽屉（可预览海报 / 换文案 / 选渠道）
  → POST /api/cover/share { levelIdx: N, undos?: M }   ← 服务端落一条挑战，返回 token
  → platform.share({ title, query: "l=N&undos=M&c=TOKEN&uid=..&name=.." })
好友 B 点开 → parseChallenge() 读 query
  → GET /api/cover/challenge/TOKEN（免鉴权）校正「谁在挑战我、当时什么成绩」
  → 进入第 N 关，顶部横幅「A 的挑战 · 第 N 关」
  → B 通关 → onChallengeWin → POST /api/cover/challenge { ..., token }
  → **服务端按 token 取出 A 的成绩判胜负**，响应带 challenge.win
  → 结算面板「挑战成功/惜败 + 我的重来次数 vs 他的重来次数」
```

### 2.1 为什么胜负必须有服务端记录

早期版本的对手成绩**只存在于分享链接的 query 里**（`?undos=0`），
客户端自己比 `myUndos <= fromUndos` 就宣布输赢。这有三个问题：

1. **可以伪造** —— 好友把 URL 里的 `undos` 一改就「挑战成功」。
   胜负成了一个由链接参数决定的量，那它就不是成绩，只是一句话。
2. **发起人可以事后否认** —— 服务端没有任何记录能证明
   「88214 确实在第 47 关拿到过 0 次重来」。
3. **链路断了没法追** —— 只知道「有人点了分享」，不知道
   「这条分享后来被谁挑战了、结果如何」。

现在分享先落 `challenges` 表，链接里只带一个不可枚举的 token；
结算时服务端按 token 取对手成绩。**客户端上报的任何对手分数都不采信**
（请求体里根本没有这个字段）。

### 2.2 两个哨兵值，别混

| 值 | 含义 | 场景 |
|---|---|---|
| `undos = 0` | 一次都没重来，**最好的成绩**（三星） | 通关结算分享 |
| `undos = -1` | **不宣称成绩**（纯邀请） | 我的页邀请 / 地图选关 |

用 `0` 表示「没带成绩」会把一次邀请写成「我零重来通关」——
好友看到的是一个我根本没拿到的分数，而且他几乎必输。

### 2.3 接口

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/cover/share` | 需登录 | 记录分享，返回 token。同一人+同关+同成绩**复用**已有 token |
| `GET /api/cover/challenge/:token` | **免鉴权** | 好友打开链接时查上下文。token 不可枚举，返回的只有关号/昵称/成绩 |
| `POST /api/cover/challenge` | 需登录 | 提交挑战成绩。带 `token` 时响应多一个 `challenge`{win,myUndos,rivalUndos,fromName,hasScore} |

### 2.4 判定规则

- `我 <= 他` 即胜（**平手算赢**，与好友一样好也是一种赢）
- **挑战关号必须与提交关号一致** —— 不一致不判定
  （否则拿 A 关的成绩去比 B 关的对手，毫无意义）
- 查不到 token（被改坏 / 老链接）**不影响通关**：
  照常写成绩、推进度，只是这次不算挑战

## 3. 分享文案池

`src/ui/share.ts` 的 `COPY_POOL`（4 条，`Math.random()` 随机）：

- 我卡在第 {lv} 关，你能连过去吗？
- 这关我用了 {steps} 步，你呢？
- 敢不敢试试我的皮肤？
- 第 {lv} 关，我不信你过得去

测试方法：A/B 测分享率，替换表现最差的文案。

## 4. 好友榜（开放数据域）与服务端好友的关系

| 数据源 | 用途 | 说明 |
|---|---|---|
| 开放数据域 `wx.getFriendCloudStorage` | 好友榜排名 | 只返回互为好友的用户，免后端 |
| 服务端 `/api/friends` | 好友进度统计面板 | 好友数/平均进度/最高进度/我的名次 |

两者可能不一致：开放数据域画榜，服务端算统计，各司其职。

## 5. 裂变健康度指标

- 分享率 > 5%
- 点击 → 首局完成转化率 > 50%
