## A. 阻断上线

### A1. 广告位 ID 还是占位符 —— 广告一分钱都赚不到

**现状**

```
games/line/src/platform/wechat.ts:202   let rewardedAdId = 'adunit-placeholder';
games/line/src/platform/douyin.ts:36     let rewardedAdId = 'adunit-placeholder';
server/cmd/http/main.go:138              ConfigHandler(line.DefaultSkins(), "adunit-mock")
```

服务端 `/api/config` 下发的 `ad.rewardedVideoId` 硬编码是 `"adunit-mock"`，
`interstitialId` 是空串。客户端拿到后就 `configureAds()` 覆盖占位符 ——
**等于用了一个假的广告位 ID**。

**后果**：`wx.createRewardedVideoAd({ adUnitId: 'adunit-mock' })` 会失败，
但代码里有「加载失败兜底发放」（`finish(true)`）—— 所以**玩家能正常拿到奖励，
我们一分钱收不到，且日志里只有一句 warn**。这是最难发现的那类问题：
游戏一切正常，只是没有收入。

**缺什么**
1. 微信/抖音后台各创建激励视频 + 插屏 + banner 广告位
2. `/api/config` 的 `ad` 字段按平台分开下发（现在只有一套，抖音端根本拿不到自己的）
3. 配置项进 `deploy/config.{local,prod}.yaml`，不要硬编码在 `main.go`

**工作量**：小（后端加字段 + 配置；客户端已支持，只需按平台取对应字段）

### A2. 抖音端的广告位配置完全没接

**现状**

```
server/internal/games/line/handler.go:40-43
  "ad": { "rewardedVideoId": adID, "interstitialId": "" }
```

只有一个 `ad` 对象，没有平台维度。而客户端 `configureDouyinAds()`
（`douyin.ts:41`）写好了却**从来没被调用** —— `main.ts:2825` 只在
`platform.name === 'wechat'` 时调 `configureAds`。

**后果**：抖音端广告位永远是 `adunit-placeholder`，所有激励视频都走兜底发放。

**缺什么**
- `/api/config` 返回 `ad: { wechat: {...}, douyin: {...} }`
- `main.ts` 按平台分别调 `configureAds` / `configureDouyinAds`

**工作量**：小

### A3. 微信分享卡片没有 5:4 配图 —— 卡片会被裁掉一角

**现状**

```
games/line/src/main.ts:1512-1515
  // 微信卡片最佳比例是 5:4，9:16 的海报直接当 imageUrl 会被裁得很难看。
  // 这里**不传** imageUrl：宁可让微信用它自己的默认图...
```

**这是当初的诚实妥协，不是最终方案。** 不传 `imageUrl` 的结果是
微信用小游戏的默认 logo（很小、很没辨识度），分享点击率会明显低于有图卡片。

**缺什么**：一张 **500×400（或 1080×864）** 的卡片图生成器。
海报是 750×1334（9:16），**不能直接缩** —— 比例差太远。
需要另画一版：横构图，左 045 大关号 + 右文案，或直接用当前棋盘截图裁 5:4。

**工作量**：中（新增一个 `renderShareCard()`，与 `renderPoster` 共用色板）

### A4. 海报二维码仍然留白

**现状**

```
games/line/src/ui/share.ts:39-46
  设计稿的海报右下角有一枚二维码。本项目目前**没有生成小游戏码的能力**
  （服务端没有 wxacode.getUnlimited，也没有离线 QR 编码器），
  所以这里做成可选参数 `qr`：传了就画，不传就留白
```

**后果**：海报不能扫码进游戏，只能靠链接（而链接在图片里点不了）。
分享海报的核心价值（「看到图 → 扫码就玩」）断了一环。

**两条路**
| 方案 | 优点 | 缺点 |
|---|---|---|
| 服务端接 `wxacode.getUnlimited` | 微信原生、能带 scene 参数 | 需要 access_token + 小程序已发布；抖音要另接 |
| 引入离线 QR 编码器（纯 TS） | 两端通用、不依赖平台 | 多一个依赖（约 15KB） |

**工作量**：小~中（后端调接口缓存，或前端引一个 qrcode 库）

## B. 功能空洞（入口在，但点了没效果）

### B1. **看广告解锁主题/皮肤 —— 标签写了，功能没做**（最该补的一个）

**现状（分两层，都缺）**

**第一层：主题页（玩家实际看到的那个页面）**

```
games/line/src/ui/skins.ts:404
  case 'ad': return '看广告解锁';
```

`themeUnlockLabel()` 会给锁着的主题打上「**看广告解锁**」这行字 ——
**但我们根本没有这个交互**。皮肤页（底栏「主题」tab）的按钮只有：

```
games/line/src/ui/skins.ts:295
  label: '使用', kind: 'primary', id: 'equipTheme'
```

`drawFeatured()` 在未持有时直接 `return []`（`:287`）——
也就是说**锁着的主题点上去毫无反应，连按钮都不画**。
玩家看到「看广告解锁」四个字，却找不到任何能点的地方。

**第二层：16 套皮肤（`SKINS`）**

```
games/line/src/render/skins/index.ts
  16 套，其中 11 套 unlockType: 'ad'
```

- `ads.ts` 定义了 `Placement = 'skin_unlock'`，但**没有任何地方调用**
- 服务端**没有皮肤解锁接口**（`grep -rn "skin" server/cmd/http/main.go` 无结果）
- 客户端也没有皮肤列表页（主题页展示的是 `themes`，不是 `SKINS`）

**后果**：玩家在主题页看到「看广告解锁」，点了没反应。
这是**最容易撞上的死路**，而且文案主动承诺了能力却兑现不了 ——
比什么都不写更糟。

**缺什么**
1. 主题页：锁着的主题 → 画一个「看视频解锁」按钮（现在 `return []` 是空的）
2. 客户端：`ads.showRewarded('skin_unlock')` → 成功后调后端
3. 服务端：`POST /api/themes/unlock` 或 `/api/skins/unlock`
   （校验 + 写 `unlocked_skins` / 主题解锁状态 + 幂等）
4. 埋点：`skin_unlock`（现在 0 处上报，见 C1）
5. 决定 `SKINS` 那 16 套怎么办：**要么给它们一个入口，要么删掉**
   （现在它们是死数据 —— 定义了、有解锁类型、但玩家永远看不到）

**工作量**：中（四处都要动，但逻辑清晰）

### B1b. 16 套皮肤（`SKINS`）是**死数据** —— 玩家永远改不了它

**这是比 B1 更隐蔽的一层，单独列出来。**

**现状**

`games/line/src/render/skins/index.ts` 定义了 16 套皮肤
（原木/薄荷/石墨/青岩/藕粉/琥珀/大理石/金属拉丝/冰晶/霓虹/黄金/星尘/星河…），
每套有 hue/sat/light/texture，`paintSkin()` 能真的把它们画出来。

**但它们没有任何入口：**

| 用途 | 现状 |
|---|---|
| 主题页（底栏「主题」tab） | 展示的是 **themes**（秘色天青等 7 套板面主题），**不是 SKINS** |
| `progress.currentSkin` | 仍被读取（`main.ts:2390`、`2479`、`share.ts` 的海报），**但没有 UI 能改它** |
| `SKIN_LEVELS`（`mapview.ts:433`） | 只用来在地图上给第 200/500/900 关画一个「◆ 主题奖励」标记 |
| `unlockType: 'ad'`（11 套） | 永远解不开（见 B1） |
| `unlockType: 'milestone'`（3 套：黄金 200 / 星尘 500 / 星河 900） | 服务端 `grantSkinForLevel` 会真的发，**但玩家看不到在哪换** |

**后果**

- 玩家打通第 200 关，服务端真的把「黄金」皮肤写进了 `unlocked_skins`，
  结算页会显示「已解锁新主题 · 黄金」——
  **然后玩家在整个游戏里找不到任何地方能装备它**。
- 地图上那个「◆ 主题奖励 200/500/900」的图例，指的是一个用不了的东西。
- 海报里的棋盘预览用的是 `currentSkin`，永远是「原木」。

这是「奖励发了但兑现不了」的典型问题 —— 比不给奖励更伤玩家信任。

**两种处理方式（要选一个）**

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 给 SKINS 一个入口** | 主题页加一个 tab / 分段：「板面主题」/「棋子皮肤」 | 中（要改主题页结构） |
| **B. 砍掉 SKINS** | 删除 16 套皮肤，地图不再标「主题奖励」，服务端不再发皮肤 | 小~中（但丢掉已有的美术工作） |

**建议 A**：皮肤是已经画好的资产（`paintSkin` 能用），
而且 cover 模式的格子是玩家**注视时间最长的东西**，
换棋子皮肤的体感比换板面主题更直接。

**工作量**：中（方案 A）

### B2. 排行榜写死只取前 100 名，没有翻页

**现状**

```
server/internal/modules/leaderboard/leaderboard.go:62
  zs, err := rdb.ZRevRangeWithScores(ctx, KeyGlobal, 0, 99).Result()
```

接口不接受 `offset`/`limit`，`fetchLeaderboard()`（`api.ts:373`）也不传参。

**后果**
- 第 100 名之后的玩家在总榜上**永远看不到自己**
- 「我的名次」底栏能显示真实名次（`myRank` 单独算过），但玩家翻不到自己附近的人
- 1000 关的游戏，玩家会想看「和我差不多的人」，现在看不到

**缺什么**：接口加 `offset`/`limit`，前端加「加载更多」或分页控件。

**工作量**：小~中

### B3. `skin_equip` / `level_fail` 两个埋点从没上报过

**现状**

```
games/line/src/analytics/tracker.ts:25-26   （类型里有）
grep "reportEvent('skin_equip'" → 0 处
grep "reportEvent('level_fail'"  → 0 处
```

**`level_fail` 为什么是空的**：cover 模式**没有失败状态** ——
铺不满就继续拖，松手只是定住线。所以严格说这个事件是「设计上没有」，
不是「忘了写」。但它的**类型还留着**，会让人以为有这个数据。

**`skin_equip` 缺失是真遗漏**：换皮肤是核心行为，不埋点就答不了
「哪套皮肤最受欢迎 / 换了皮肤的人留存更高吗」。

**缺什么**
- `skin_equip` 补上报点（`main.ts` 里 `equipTheme` 分支附近）
- `level_fail` 从类型里删掉，或改成 `level_stuck`（记录「同一关重试 N 次仍没过」）

**工作量**：小

### B4. 首日引导 / 新手教学 —— 没有

**现状**

```
grep -rn "tutorial|onboarding|新手|引导" games/line/src
→ 只有两处注释提到「将来若要加引导」
```

**后果**：cover 玩法（铺满全盘、冰块滑行、钥匙门、传送门、星屑顺序）
**规则相当复杂**，但新玩家进来直接看到一张棋盘，没有任何解释。
唯一的帮助是机制图例（`drawPlayLegend`，7 枚图标 + 名字），
但图例只回答「这是什么」，不回答「怎么玩」。

**这不是必须的**（很多休闲游戏靠试错上手），但 cover 的
「必须铺满 + 终点像石障一样挡住」很容易让人一上来就困惑。

**缺什么**：第 1 关的轻量引导（3 步提示：按住起点 → 拖动 → 铺满），
或首次进关时一个可关闭的规则卡片。

**工作量**：中

### C2. 后台缺「留存曲线」与「关卡流失漏斗」

**现状**：`/admin` 总览只有**次日留存一个点**（`stats.go:LoadOverview` 里的

**缺什么**（都不是必须，但运营会很想要）

- **分享裂变漏斗**：`share_click` → `challenge_start` → `challenge_result` 的转化率
  （这三条埋点都有了，后台还没做出视图）

### C3. 广告数据的真实凭证一个都没配

**现状**

### D5. 断线重连只做了「切后台回来刷进度」


**做得对**（不会出现「切回来黑屏」或「点了没反应」），但：

- 通关上报失败时只有 `console.error`，玩家看到的是「结算了但关卡没解锁」

**缺什么**：上报失败的可见反馈 + 重试入口（`showToast` 已有，接上即可）。

## 建议的动手顺序

1. **A1 + A2**（广告位）—— 不配就是白跑一个月，且**完全无感**
   （广告失败时会静默兜底发放，游戏完全不报错，只是没有收入）
2. **B1 + B1b**（解锁交互 + 皮肤入口）—— 这是**同一条链上的两个洞**：
   「看广告解锁」文案在，交互不在；16 套皮肤解锁了，换装入口不在。
   一起做，否则会出现「奖励发了但兑现不了」
3. **A3**（5:4 分享卡图）—— 直接影响获量
4. **A4**（二维码）—— 同上
5. **C3**（广告凭证申请）—— 纯流程工作，越早提交审核越好（有等待期）
6. **B2**（排行榜翻页）—— 1000 关的游戏，前 100 名之外的人看不到自己
7. 其余按需
