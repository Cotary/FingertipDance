## A. 阻断上线

### A1. 广告位 ID 还是占位符 —— 广告一分钱都赚不到

> **2026-11-21 更新**：下发链路已经做好（`/admin/config` 双平台表单 +
> `/api/config?platform=` 按平台下发，见 `43-双平台与数据后台设计.md` §七）。
> **现在只剩运营动作**：把微信/抖音后台创建的真实广告位填进后台配置页。
> 没填之前仍是 `adunit-mock`，行为和下面描述完全一样。

**现状**

```
games/line/src/platform/wechat.ts:202   let rewardedAdId = 'adunit-placeholder';
games/line/src/platform/douyin.ts:36     let rewardedAdId = 'adunit-placeholder';
server/internal/games/line/platform_config.go  DefaultPlatformConfig().Ad.RewardedVideoID = "adunit-mock"
```

服务端 `/api/config` 下发的 `ad.rewardedVideoId` 默认是 `"adunit-mock"`，
`interstitialId` 是空串。客户端拿到后就 `configureAds()` 覆盖占位符 ——
**等于用了一个假的广告位 ID**（后台没填之前）。

**后果**：`wx.createRewardedVideoAd({ adUnitId: 'adunit-mock' })` 会失败，
但代码里有「加载失败兜底发放」（`finish(true)`）—— 所以**玩家能正常拿到奖励，
我们一分钱收不到，且日志里只有一句 warn**。这是最难发现的那类问题：
游戏一切正常，只是没有收入。

**缺什么**
1. 微信/抖音后台各创建激励视频 + 插屏 + banner 广告位
2. 把三组 ID 填进后台「配置」页（`/admin/config`，微信 / 抖音各一张卡）
3. ~~配置项进 yaml~~ —— **改为进数据库**：广告位是运营参数不是凭证，
   改一次不该等发版。appid / secret 仍在 yaml + 环境变量。

**工作量**：小（只剩填表，代码链路已通）

### A3. 微信分享卡片没有 5:4 配图 ✅ 已完成（2026-11-23）

**原来的样子**

```
games/line/src/main.ts  sendInvite()
  // 这里**不传** imageUrl：宁可让微信用它自己的默认图...
```

`renderShareCard()`（1080×864）其实早就写好了，但**没有任何调用方** ——
函数躺在 `share.ts` 里，注释写着「要出真正的 5:4 卡图是另一件事」。
于是分享出去的卡片一直是微信默认 logo。

**已做**

- `sendInvite()` 出图 → `platform.exportCanvas()` → `platform.share({ imageUrl })`
  （`wx.shareAppMessage` 只吃本地文件路径，dataURL 会被静默忽略）
- **只对「发给朋友」出图**：朋友圈走系统菜单，微信不接受定制内容
- 出图失败 `try/catch` 兜住，**不挡分享** —— 退回默认图也比「点了没反应」强
- 卡图按 `关卡 + 文案 + 用户 + 链接` 缓存：玩家常常连点两三次，
  每次都重画 1080×864 + 落盘是几百毫秒的卡顿
- 顺手修了 slogan：深釉底上用了 `i700`（#454038），对比度约 1.9:1，
  **渲染出来基本看不见**；与落款副行统一到 `i500`

**验证**：`test/share-card.test.ts`（9 条）锁住「imageUrl 真的传进 share」、
「只对 friend 出图」、「失败不挡分享」、「缓存命中」、「卡图是 5:4」；
画廊新增 `?p=shareCard` 与 `?p=poster` 两屏目视核对。

### A4. 海报二维码仍然留白 ✅ 已完成（离线编码器）

**已做**：`src/core/qr.ts`（纯 TS，自带 RS 纠错），海报落款右侧与
5:4 卡图的右边都是真二维码，**两端通用、不联网**，不需要服务端
`wxacode.getUnlimited`，也不受「小程序未发布」限制。

码里放的是**不带 token 的分享链接**（`?l=47&undos=0`）——
每次生成不同 token 会让「图上的码」和「发的链接」指向两次不同的挑战。
好友扫码进去照样能玩，只是胜负退回和自己的历史最佳比。
这是有意的取舍：**图上能扫进去**比**图上带战绩**重要。

## D. 打磨项（上线后补）

### D1. 保存海报到相册 ✅ 已完成

`platform/saveImage.ts`：`canvasToTempFilePath` → `saveImageToPhotosAlbum`，
三态返回（存好了 / 拒绝授权 / 这端不支持 / 其它失败），调用方据此给不同提示；
Web 端退回 `<a download>`。原来那句「请长按海报保存到相册」是**假承诺** ——
canvas 像素不是 DOM 节点，没有长按菜单，玩家按半天什么也不会发生。

**同一类问题还修了一处**：`copyInviteLink()` 原来直接调
`navigator.clipboard.writeText` —— 小游戏端没有 `navigator`，会抛
`ReferenceError`，落到「长按上面的链接试试」这句同样做不到的提示上。
也就是说**「复制链接」在发行端从来没成功过**。现在走
`platform.clipboard`（`wx/tt.setClipboardData`，web 用 clipboard API +
`execCommand` 兜底），失败时只说「复制没成功，稍后再试一次」。

抖音独有能力：录一段游戏过程直接投稿到抖音。
对抖音端是**明显的流量红利**（这是抖音小游戏的主要获量方式之一）。

**工作量**：中（要处理录制时长、停止时机、分享回调）

### D3. 排行榜只有总榜前 100 + 好友榜，没有「我的段位」

玩家看不到「我和我附近的人」。1000 关的游戏里，前 100 名都是几百关的老玩家，
新手进榜页只看到一堆遥不可及的名字。

**可选做法**：显示「我的名次 ±5 名」那一段。

### D4. 关卡表没有分包 / 外置

**现状**：`line-wx/dist/game.js` 是 **473KB / gzip 120KB**，
关卡表（1000 关）打在主包里。

**目前完全够用**（微信主包 4MB、抖音 4MB），**不需要动**。
记录在这里只是为了将来：如果关卡涨到 5000 关或者加了大量美术资源，
再考虑走 `/api/levels-v3` 外置（接口本来就有）。

### D5. 断线重连只做了「切后台回来刷进度」

- 通关上报失败时只有 `console.error`，玩家看到的是「结算了但关卡没解锁」

**缺什么**：上报失败的可见反馈 + 重试入口（`showToast` 已有，接上即可）。

### F1. 抖音端**整个触摸是断的** ✅ 已完成（2026-11-23）

**原来的样子**

```ts
// games/line/src/main.ts（改前）
const wx = (globalThis as { wx?: {...} }).wx;
wx?.onTouchStart?.((e) => { const t = e.touches[0]; if (t) onDown(t.clientX, t.clientY); });
```

非 Web 分支只读 `globalThis.wx`。抖音小游戏的命名空间是 `tt`，**没有 `wx`**
—— 可选链静默短路，`onTouchStart` 永远不被调用。

**已做**

- `platform/types.ts` 新增 `PlatformTouch` 与 `Platform.onTouch?()`
- 微信实现走 `wx.onTouchStart/Move/End/Cancel`，抖音走 `tt.*`，取不到就 `return`
- 坐标容错：`touches[0]` 为空时退到 `changedTouches[0]`（抬手那一帧常见）
- `main.ts` 改为 `platform.onTouch?.(...)`，调用方不再认识命名空间

**验证**：`test/platform-input.test.ts`（16 条）锁住「抖音从 tt 进来」「抖音不读 wx」

### F10. 令牌过期后**永不重登**：所有功能静默失效 ✅ 已完成（2026-11-23 深夜）

**这是本轮复查里最该先修的一条**，因为它到第 4 天才发作，测试和白天验收都发现不了。

服务端 JWT 有效期 **72 小时**（`config.prod.yaml` 的 `jwt.ttl_hours`）。第 4 天起，
**所有**带鉴权的请求一律返回 `4001`，而每个调用点都在自己的 `try/catch` 里
把它当「网络问题」吞掉：

| 调用点 | 表现 |
|---|---|
| `refreshProgress`（切后台回来） | `catch {}` 空的 → 进度不再同步，界面数字就是不动了 |
| 通关上报 `/cover/progress` | 失败走「乐观更新本地」→ 玩家以为过了，**下次登录被服务端冲掉** |
| 排行榜 / 好友榜 | 空白（`loading` 永远转） |
| 分享挑战 | 拿不到 token，胜负退回"和自己比" |

没有一条会报错，只有 `console.warn`，而真机上没人看得到。

**已做**（`net/api.ts` 的 `authed()`）

- 捕获 `4001` → 清旧令牌 → `login()` 重拿 → **重试原请求一次**
- **只重试一次**：重登后仍 4001 说明不是过期（签名错 / secret 换了 / 账号被封），
  再试就是死循环
- **并发去重**：令牌失效那一刻往往几个请求同时在飞（进度、星级、好友榜、埋点补传）。
  各登一遍会让 `wx.login` 换多次 code、多走几次 code2session，还可能撞平台频控 ——
  共用一个 Promise
- 非 4001（网络故障 / 4008 路径非法）**不重登**，照常抛给调用方
- 用 `isApiCode(e, code)` 做结构化判断而不是 `instanceof`：后者在打包分包 /
  `vi.resetModules()` 之后会静默失效（两份类实例），断言会假绿

**验证**：`test/auth-renewal.test.ts`（5 条：重试带新令牌、只重试一次、并发只登一次、
网络错误不重登、业务拒绝不重登）。

### F11. 客户端「今天」用 UTC，服务端用东八区 —— 每天错 8 小时 ✅ 已完成（2026-11-23 深夜）

每日额度在两边各算了一遍：

- 客户端：`ad_rewarded_<day>`、`skip_count_<day>` 本地键，用
  `new Date().toISOString().slice(0,10)` → **UTC**
- 服务端：`skips` 表按 `day` 列数当日行数，`time.Now().Format("2006-01-02")`
  配 `TZ=Asia/Shanghai` → **东八区**

于是每天 **00:00~08:00** 这八小时两边不同日（东八区已是 24 日，UTC 还停在 23 日）：

- 玩家凌晨 1 点跳关：客户端记进 23 日的键、服务端记 24 日 → 客户端以为额度用完了
  **拦着不让点**，服务端其实还有；
- 或反过来：客户端额度还在、服务端按新一天算，看完广告仍被 `4007` 拒绝。

只在凌晨复现，白天验收全绿。而且 `todayKey()` 在 `ads.ts` 与 `rewardRules.ts`
**各写了一份**，两份都错、改一处必漏一处。

**已做**

- 新建 `core/dayKey.ts`：`dayKeyCN()`（UTC 毫秒 + 8h 偏移，再按 `getUTC*` 读）+
  `adRewardedKey()` / `skipCountKey()` / `skipLevelKey()` 三个键生成函数
- **不用 `toLocaleDateString()`**：依赖环境 locale，小游戏里不同机型返回
  `2026/11/23` 或 `11/23/2026`
- `ads.ts` / `rewardRules.ts` 删掉各自的 `todayKey`，全部改走它
- `markSkippedToday` 的两个键**来自同一次**调用，避免跨零点写出「昨天的关 + 今天的计数」

**验证**：`test/day-key.test.ts`（10 条：凌晨 0 点即新一天、7:59 仍当天、8:00 不换天、
跨年、闰年、补零、与环境时区无关）；顺手修了 `platform-config.test.ts` 里
自己手拼 UTC 键的那条（它会掩盖口径变更）。

### F9. 资质与后台（**不是代码**，但没有它包传不上去）

> **顺手修掉的一条**：`deploy/docker-compose.prod.yml` 的 `postgres` 服务原本没设时区
> （默认 UTC），而 App 容器是 `Asia/Shanghai`。业务按东八区写 `skips.day`，
> 后台统计按 `created_at::date` 读 DB 会话时区 —— 凌晨 0~8 点的数据会被算进前一天，
> 两边的「今日」永远差 8 小时，且**不会报任何错**。已补 `TZ` + `PGTZ`。
