# 25 · Cover 棋盘视觉重构（诊断 + 规范 + 实施计划）

> 触发：cover 玩法接入后 UI 明显变丑。本文先说清**丑在哪、为什么丑**（都带证据），
> 再给可落地的视觉规范与分阶段实施计划。改后的原型截图在 `out/shots/proto3-*.png`，
> 改前在 `out/shots/cover-cur-*.png`，两者同关、同进度，可直接对比。

---

## 0. 一句话结论

**丑的根因不是配色，是「棋盘不再是一个整体」。**
经典模式是「一块板 + 压在板上的凹坑」，cover 模式把它变成了
「一块矩形板被挖了几个洞（洞还挖穿了背景）+ 一堆浮在上面的绿色方块 + 一条根本没画出来的路径线」。
三件事叠加，玩家看到的是「坏掉的图」，不是「一局游戏」。

## 1. 诊断（6 条，按严重度）

### P0-1 路径线从来没渲染出来（核心反馈缺失）

`src/render/coverTrail.ts` 的 `segmentPath()` 把**每一个相邻步**都切成「只有一个格」的段：

```ts
if (kind === 'ice' && cur.kind === 'ice') cur.cells.push(cell);
else { if (cur.cells.length > 0) out.push(cur); cur = { cells: [cell], kind }; }
//                                                        ↑ 丢了 prev，段只剩 1 格
```

而绘制它们的循环有 `if (seg.cells.length < 2) continue` —— 于是**所有段都被跳过**，
一条线都不画，只剩每格一颗「转折珠」。
所以线上看到的是一盘**橙色小圆点**，玩家完全看不出方向、顺序、自己走到哪。

> 这是「变丑」里最致命的一条：cover 模式的全部反馈都在这条线上。

### P0-2 底板用 `destination-out` 挖洞，把背景一起挖穿

`coverBoard.ts:130` 画完整块矩形后用 `destination-out` 抠 VOID：

- 画布是**透明的**，抠掉的不只是板，还有先画上去的 `clayBackdrop` 背景层；
- Web 端露出 `<body>` 的米色，微信端（无 CSS 背景）露出一块**黑斑**；
- 洞是**直角矩形**，与板的圆角轮廓撞在一起，读作「板被啃了」。

### P0-3 轮廓永远是矩形，不跟形状走

板 = `w×h` 的外接矩形。缺格越多，「矩形 + 洞」越像渲染错误。
玩家看到的是「一张有缺口的表格」，而不是「一个形状」。

### P0-4 格子用了两套色相（奶油白 vs 皮肤绿）

未走 = `CLAY.cream` 凹坑（很亮），走过 = 皮肤色（薄荷绿）。
两个高明度、不同色相的面并置 → 整盘读作**拼图**。
而 cover 的语义是「同一块板正在被填满」，进度应该靠**填色面积**读，
现在却要靠玩家自己数格子。

### P0-5 机制标记没有统一规格，小尺寸不可读

| 机制 | 现状 | 问题 |
|---|---|---|
| 单向门 | 8px 三角 | 在 60px 格上小到看不清方向 |
| 星屑 | 星形，无编号 | **「顺序必经」是核心规则，但 UI 完全没表达顺序** |
| 钥匙/门 | 钥匙形 + 锁 | 底色与格子同色系，混在盘里 |
| 传送门 | 双圈 | 与「未走格」的圆角矩形轮廓近似，误读 |
| 冰面 | 半透白块 | 在奶油底上直接读成「空格子」 |
| 石头 | 深色块 + × | × 在 20px 以下是一块脏点 |

### P0-6 `cell` 尺寸跨度过大，但没有密度分级

按 `computeLayout`：

| 盘面 | cell |
|---|---|
| 5×5 | 134 |
| 6×6 | 111 |
| 7×7 | 95 |
| 8×8 | 83 |
| 9×9 | 74 |
| 10×10 | 67 |
| 11×11 | 60 |

134 → 60，**同一个绘制函数要服务 2.2 倍的尺寸跨度**。
每格都带高光 + 阴影 + 颗粒，在 60px 上就是「华夫饼 / 一锅芝麻」。

## 2. 三条设计原则（改法的依据）

### 原则一：一块板（One Slab）

> **棋盘先是一块黏土板，格子只是板上的痕迹。**

- 板 = 「属于板的格子」的**并集**，不是外接矩形。
- 板只有**一层**投影（整块板投一次），不是每格投一次。
- 缺口 = 板不覆盖那里（自然露桌面），**绝不挖穿画布**。

### 原则二：只靠明度分级，不靠色相

> **未走 = 板上的浅刻线；走过 = 皮肤色凸起；当前 = 白环。**

未走格几乎融进板里（只留 1px 刻线 + 一丝内影），
让「已铺的彩色」成为画面里唯一跳出来的东西。
进度 = 彩色面积，扫一眼就知道铺了多少。

### 原则三：符号优先于颜色

> **能加编号就加编号，能加形状就不只给颜色。**

色弱玩家、小屏、缩略图 —— 三个场景下颜色都会失效。
所以：星屑带 `1/2/3` 徽章、起终点用三角/方框、门用「锁」而不是「红色」。

## 3. 视觉规范

### 3.1 底板

| 项 | 规范 |
|---|---|
| 构造 | 属于板的格子（除 VOID 外）→ 方角矩形并集（外扩 `pad`）→ 用 `lineJoin:'round'` 描同路径（线宽 `2R`）+ 填充 = **并集膨胀 R 的圆角轮廓** |
| `pad` | `max(3, cell × 0.06)` |
| `R`（外轮廓圆角） | `max(6, cell × 0.22)` |
| 厚度 | `max(3, cell × 0.06)`：暗色整体上移，底边露出暗色 = 板厚 |
| 颜色 | 顶面 `CLAY.board.base (#8CA6BA)`，厚度/暗边 `board.dark (#6B8799)` |
| 投影 | **整块板一次**，`blur 8px`、`alpha .30`、下移 `max(4, cell×0.07)` |
| 缓存 | 板是静态的 → **离屏画布缓存，key = 关卡号**（禁止用 `grid.join('')` 当 key，每帧拼字符串比画还贵） |

> 实现注意：顶面**只能 fill 一次**。第一版我叠了「亮色再 fill 一次」想做出轮廓光，
> 结果整块板被刷成亮色，黏土的重量感全丢了（见 `proto2` 截图）。

### 3.2 格子三态

| 态 | 画法 | 说明 |
|---|---|---|
| 未走 | 无填充，1px 刻线 `rgba(74,51,39,.13)` + 内侧 1px `rgba(255,251,243,.18)` | **不做凹坑**：cell≥90 时凹坑是一排「碗」，整盘读作一排洞 |
| 已走 | 皮肤色 `clayBlock`，`depth: 2~3`，`radius: size×0.20`，`cell<90` 时关掉亮面 | |
| 当前格 | 白环 `rgba(255,251,243,.92)`，线宽 `clamp(2.5, size×0.045, 4)` | **必须画在连线之后**，否则被线盖掉 |

### 3.3 路径线（四层体积语言，与经典模式一致）

| 层 | 颜色 | 线宽 | 偏移 |
|---|---|---|---|
| 压痕 | `rgba(74,51,39,.20)` | `cell×0.30` | 0 |
| 侧暗 | `terracotta.dark` | `cell×0.215` | 0 |
| 主色 | `terracotta.base` | `cell×0.175` | `-cell×0.020` |
| 亮芯 | `terracotta.light` | `cell×0.048` | `-cell×0.020` |

- 拐角珠**只在真转弯处**（前后同排/同列则跳过）。旧版每格一颗，11×11 就是一盘麻子。
- 冰块段：整段叠一层 `rgba(216,238,252,.72)` 细线，表达「滑过去的」。
- 传送门：虚线弧（起终点不相邻时）。

### 3.4 机制筹码

统一「圆形纸白底盘 + 单色符号」，`r = cell × 0.26`（compact 档 `0.23`）：

| 机制 | 底盘 | 符号 | 编号 |
|---|---|---|---|
| 星屑 | 纸白 | 星（收集后转 mustard 亮起） | **必带** `1..3` 徽章 |
| 单向门 | 纸白 | 粗箭头（`ink`） | — |
| 钥匙 | 纸白 / 已持有转 mint | 钥匙（`ink`） | — |
| 门 | 锁定时 rose，开启后 mint | 锁 | — |
| 传送门 | 纸白 | 双环（同组同色） | 徽章 |
| 冰面 | 不套筹码 | 玻璃砖：淡蓝底 + 白色反光斜带 + 2 条裂纹 + 冰蓝描边 | — |
| 石头 | 不套筹码 | 深色块 + 顶部哑光椭圆，**去掉 ×** | — |

> **compact 档（cell < 70）编号不上棋盘**：60px 格上徽章只有 5px，等于没有。
> 改成 HUD 显示「下一个 ★2」，棋盘只留星形。

### 3.5 密度三档

| 档 | 触发 | 差异 |
|---|---|---|
| rich | `cell ≥ 90`（5×5~7×7） | 每格亮面 + 徽章 + 完整筹码 |
| standard | `70 ≤ cell < 90`（8×8~9×9） | 每格亮面保留，颗粒关闭 |
| compact | `cell < 70`（10×10~11×11） | 关亮面、筹码 `0.23`、编号移到 HUD |

### 3.6 HUD 与构图

- 关号胶囊保持（现有视觉资产好，不动）。
- 进度文案改成**两个数并列**：`52 / 86` 加粗 + `剩 34` 弱化；不要只写「已铺 52 / 86 格」。
- **皮肤名从游戏内移除**（属于皮肤页），右侧「薄荷」那行删掉。
- 小盘（5×5~7×7）棋盘按宽度撑满后，纵向会空出 300px 桌面：
  在棋盘下方放「本关机制说明」条（首次遇到某机制时出现），而不是让桌面空着。

## 5. 三处拍板（已定）

1. **未走格改成「板上浅刻线」** —— 采用。整盘统一、进度靠填色面积读，
   放弃经典模式那套奶油凹坑（在 cover 里它是「一排碗」）。
2. **11×11 的星屑编号搬到 HUD** —— 采用「compact 档不上编号 + HUD 文字」，
   不用「大小递减」：大小差在 60px 格上分不出来，反而和「已收集」的放大态混淆。
   rich / standard 档（cell ≥ 70）仍在棋盘上带徽章。
3. **D=0 关卡补常驻一行小字** —— 采用「起点自由 · 任意格都能起手」，
   放在桌面空位更大的一侧（上方或下方），两侧都塞不下（11×11 撑满）就不画。
   不做首关蒙层：蒙层只在第一次出现，而 D=0 关卡会反复出现。

### 顺手修掉的四个 bug

| # | 现象 | 根因 |
|---|---|---|
| 1 | 连线从来没画出来，只剩一盘橙点 | `segmentPath` 的 else 分支丢 `prev`，每段只有 1 格，被 `length < 2` 全部跳过 |
| 2 | 缺口处露出一块黑斑（微信端） | 底板用 `destination-out` 抠洞，把先画上去的背景层一起擦掉 |
| 3 | 单向门箭头方向错 | `DIR` 是 `0=上 1=下 2=左 3=右`，**不是**顺时针序，`dir * π/2` 把「下」画成「右」 |
| 4 | 门（锁）糊满全屏 | `clayLock` 第三参是**缩放系数**（基准宽 24px），传 `chipR` 等于放大 20 倍 |

另外三处小修：星屑「下一个」在一颗都没收时是 `-1`（HUD 不显示 `★1`）；
门的底盘与锁同色导致锁体消失；锁的 `keyhole` 在 10px 上是一个点，改用纸白底盘 + 染色锁。

## 7. 附：画廊怎么跑

```bash
npm run dev -- --port 5177
# 打开
#   /tools/cover-gallery.html?idx=705&fill=0.6        ← 线上实现（已重构）
#   /tools/cover-proto-gallery.html?idx=705&fill=0.6  ← 重构原型（对照物）
```

`idx` 取 1 / 20 / 65 / 153 / 705 / 900 分别覆盖
5×5 / 6×6（单向门）/ 8×8（钥匙门）/ 9×9（传送门）/ 10×10（冰）/ 11×11；
`fill` 控制「走到第几成」，用来核对不同进度下的可读性。

审小尺寸细节时加放大参数（把设计坐标 `(fx, fy)` 那一点放大后居中）：

```
/tools/cover-gallery.html?idx=900&fill=0.55&zoom=4&fx=435&fy=478
```

筹码（13px 的星、7px 的编号徽章）和当前格白环只有在 4~5 倍下才看得出好坏，
全尺寸截图里它们都糊成小色点。
