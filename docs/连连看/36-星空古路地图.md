# 36 · 星空古路：把地图做成「有纵深的一条路」

> 触发：玩家（和自己）反馈「地图还是太平、太丑」，希望能有 3D 纵深感，气质接近「星空古路」。
> 前作：`33-地图重设计.md` 解决的是「表格感」——蛇形网格 → 蜿蜒山路。
> 本篇解决的是**第二个问题**：山路是**平铺的贴纸**，没有远近、没有空气、没有光。
>
> 落地文件：
> - `games/line/src/ui/mapview.ts`（491 行）—— 只放几何、状态、命中
> - `games/line/src/ui/mapdraw.ts`（1296 行）—— 只放绘制
> - `games/line/src/render/mapstyle.ts`（389 行）—— 只放配色（跟棋盘主题联动）

## 一、为什么上一版「平」

33 号那版的山路在**构图**上已经对了：有弯、有斜线、有 Catmull-Rom 的圆角。
但它把所有元素画在同一张「纸」上——节点半径恒定、路面等宽、星星不动、没有阴影。
这四条加起来，就是「一张俯视平面图」，而不是「一条通向远处的路」。

| # | 现象 | 缺的是什么 |
|---|---|---|
| 1 | 远端的关和脚下的关**一样大** | 没有透视，眼睛读不出「哪头远」 |
| 2 | 路从头到尾**一样宽** | 没有收束，路不成「道」，像一条水带 |
| 3 | 星点、行星**完全不动** | 没有视差，天幕是壁纸 |
| 4 | 节点直接**贴在**路上 | 没有阴影，所有东西都没有离地高度 |

一句话：**纵深不是「画得更立体」，是「让屏幕坐标带上 z」。**

## 二、四条纵深手段

### 2.1 透视：一切尺寸乘 `depthScale(y)`

```ts
export function depthScale(screenY: number): number {
  const t = clamp((screenY - ROUTE_TOP) / (VIEW_BOTTOM - ROUTE_TOP), 0, 1);
  return 0.72 + 0.33 * Math.pow(t, 0.8);
}
```

| 参数 | 值 | 理由 |
|---|---|---|
| 起点 0.72 | 屏幕顶部（`ROUTE_TOP = 200`）缩到 72% | 再小（0.6 以下）远端节点小于触控下限，读不清数字 |
| 终点 1.05 | 屏幕底部（`VIEW_BOTTOM`）放到 105% | 略超 1 才有「探到眼前」的压迫感，也让底栏那条「继续」有主角 |
| 指数 0.8 | 近处变化慢、远处变化快 | 线性会让中间的关糊在同一档大小；`t^0.8` 把差异压向远端 |

### 2.2 收束：路面半宽跟着走

```ts
export function roadHalfWidth(screenY: number): number {
  const t = clamp((screenY - ROUTE_TOP) / (VIEW_BOTTOM - ROUTE_TOP), 0, 1);
  return 11 + 16 * Math.pow(t, 0.9);
}
```

11 → 27 半宽（22 → 54 全宽）。**收束比节点更狠**（节点只差 1.45 倍，路差 2.45 倍）——
路宽变化才是「灭点」最强的线索，节点的缩放只是配合。

### 2.3 三层视差：天不动、星慢动、路快动

| 层 | 位移系数 | 内容 | 读作 |
|---|---|---|---|
| 远景 | `scrollY * 0.02` | 行星（带环 + 云带）、地平线雾 | 几乎不动 = 无限远 |
| 中景 | `scrollY * 0.16` | 280 颗星（120 颗聚成银河带）、星座、碎石 | 缓慢横移 = 天穹 |
| 近景 | `scrollY * 1.0` | 古道、节点、门 | 跟着手指走 = 脚下的路 |

三层速度比约 1 : 8 : 50。**只要有两层同速，纵深立刻塌回平面。**

### 2.4 悬浮投影：让球离地

每个节点先画一枚**压扁的深色椭圆**（在球心下方 `r*0.92`，宽 `r*1.5`、高 `r*0.42`，叠两层柔化），
再画球体本身，球体左上打边缘光。**投影是唯一能表达「悬空」的廉价手段**，
没有它，球看起来是「印在路上」的贴纸。

## 三、视觉语言：一条走了很多年的古道

| 元素 | 做法 | 为什么这样做 |
|---|---|---|
| 夜空 | 三段渐变（`skyTop/Mid/Bottom`），画布上下各外扩 160~460px 防接缝 | 一屏 1334 里能同时看到「头顶黑」和「地平线亮」，天就有了厚度 |
| 星云 | 两团径向渐变（`nebulaA` 紫 / `nebulaB` 青），乘在天空上 | 纯渐变的天是「色卡」；两团不对称的云才是「天」 |
| 星点 | 120 颗沿斜带聚集（银河）+ 160 颗散布；越靠下越亮；1/13 画成四芒星；`i % 17` 用暖星 | 均匀撒点 = 噪声；分层 + 少数特殊星 = 星空 |
| 已走路 | **深色石面**（三次混色叠到 `#241A0C`）+ 两条金色边缘线 + 横向石缝 + 虚线金中线 + 外发光带 | 第一版是整条金色缎带，截图一看「像高速公路，路比关还亮」——路是配角，必须暗 |
| 未走路 | `[3, 11]` 虚线 + 一串压扁的踏脚石 | 只有虚线时未解锁段是「孤岛」；踏脚石补出「路还在，只是没走到」 |
| 世界门 | **扁金环 + 两根短柱**：`rx = 140·s`、`ry = 40·s` 的椭圆环（金色渐变，上缘亮下缘暗）+ 左右顶点各一根向下 38·s 的金柱 + 环内一圈世界色细线 + 十颗刻度点（亮几颗 = 这个世界打了多少）+ 环外一侧「Ⅲ · 苔原 / 0 / 32」 | 见 §五，这道门改了四版 |
| 未解锁关 | 暗星球（`locked` 填充 + 冷色边缘光）+ 数字 alpha 0.38 | 33 号版是深色圆片，读作「墙」；球是「还没点亮的星」 |
| 当前关 | 光晕 corona + 实环 + **旋转虚线环** + 球 + 边缘光 + 上方浮动小箭头（bob） | 全屏只有一个会动的东西，视线自动落上去 |
| 已通关 | 三档渐变球 + 裁剪地貌带 + 边缘光 + 数字 + 三颗四芒星 + 金钻；世界末关再加**分两遍画的**金环（后半圈在球前、前半圈在球后） | 环一次画完整椭圆会压在球中间，像在球上划了一刀 |
| 顶栏 | 250px 高遮罩 + 玻璃胶囊（返回 / 关号带金点）+ 世界名 + 菱形 | 地图滚动时内容从顶栏下穿过，必须有遮罩；节点循环里按 `(y - 206) / 64` 淡出，避免半个球探出来 |
| 像素主题 | 叠 CRT 扫描线（每 6px 一条 1.5px 黑，alpha 0.055） | 只有一个主题加这一层——这层是「主题在说话」，不是全局滤镜 |

## 四、主题联动：九套夜晚，同一个世界观

`src/render/mapstyle.ts` 用**主题 id** 取一套 `MapPalette`，每套只覆盖 4~6 个关键色
（天空、星色、路面、金色），其余沿用 `STAR` 基准。九套：默认星穹 / 水墨 / 玻璃 / 像素 / 罗盘 / 霓虹 / 熔岩 / 金线 / 深海。

三个踩过的坑：

| 坑 | 现象 | 解法 |
|---|---|---|
| 世界色是写死的 `WORLDS[].accent` | 霓虹主题下七个世界全是**灰薄荷绿**，跟紫黑天完全脱节 | 全部改用 `p.world[worldOf(idx)]`，配色层统一出 | 
| 世界色往**金色**混 35% 统一色温 | 霓虹里金 = 紫、水墨里金 = 米白 → 所有世界被拉成灰紫（苔原薄荷 → 灰蓝） | 改为往**路面色**混 30%，路面色自带主题色相 |
| 水墨主题地图仍是彩色 | 抽掉颜色后「水墨」和「玻璃」在灰度上撞脸 | 加 `MapPalette.mono`：先按 Rec.601 亮度**去饱和到同亮度的灰**，再往路面色靠 12% 讨一点纸暖（`mixHex(mixHex(c, grayOf(c), 0.94), base.road, 0.12)`）——直接往暖路面混 94% 会留下 33 的通道差，灰不下来 |
| 冷色主题（玻璃/深海）当前关与已通关同色 | 两者糊成一片，「我在哪」找不到 | 冷色主题的 `current` 改**暖金**（`#FFE8B0` / `#FFE0A3`） |

## 五、世界门改了四版：为什么最后是一道「扁金环 + 两根柱子」

这五行代码是全篇返工最多的地方。四版踩的坑不重复，都值得记：

| 版 | 画法 | 截图判词 | 死因 |
|---|---|---|---|
| v1 | 鸟居（两根立柱 + 横梁） | 「像一块挡板」 | 路从门里穿出去后，横梁正压在环内「苔原」两字上；实体结构在俯视角里没有厚度 |
| v2 | 椭圆星环 `rx=112, ry=92`，环内放世界名 + 进度，环顶放罗马数字 | 「像一汪水 / 一个泡」 | 环高 184，而前后两关中心只隔 116 —— 环把两个球**整个套进去**了，于是环读成上一关球的光环；罗马数字被上一关的球压掉 |
| v3 | 扁环 `rx=140, ry=40`，世界色环，文字移到环侧 | 「像一块玻璃盘」 | 门内做了径向提亮（内部比外部亮）+ 世界色近白 → 眼睛读成透镜；没有纵向支撑物，读成趴在地上的盘 |
| v4（现行） | 同上，但环改**金色金属渐变**、门内几乎不提亮、左右顶点加两根 38·s 的短金柱、刻度点用世界色 | 可读 | — |

三条可复用的结论：

1. **门的尺度受关卡间距约束，不是随便定的。** `NODE_STEP = 116`、末关半径 39·s、下一关 46·s，
   球缘之间只有约 44 的空；环高一旦超过这个数就会把球吞掉，读作「球的光环」而不是「门」。
   要保住 116 的节奏，门就只能**扁**。
2. **「门」需要纵向元素。** 纯横向椭圆在俯视里有两种读法：盘 or 水洼，都不是门。
   两根短柱是最低成本的解法——它给了门「立着」的重力方向。
3. **门内比门外亮 = 透镜。** 想表达「门里是另一个世界」不能靠整体提亮，
   只能靠一道极淡的世界色雾气（alpha 0.08）+ 环内一圈世界色细线。

顺带修掉的两处：

- **末关金环**从「一次画完整个椭圆」改成**两遍绘制**（`Math.PI..2π` 在球之前、`0..π` 在球之后），
  环才是「套」在球上；一次画完会横穿球心，看起来像把球切了一刀。
- **末关小旗**删除。33·s 的球上插一面 12·s 的三角旗，截图里读作「一颗金屑」；
  末关的身份已经由金环 + 门承担，旗是多余的第三遍重复。
- **字号抬到 20 设计像素起**：「返回」18→20、「回到当前」18→20（按钮从 150 加宽到 176 才放得下）、
  拖动标签的世界区间 16→18。375 宽的真机上 18 设计像素只有 9 CSS 像素，是「蚂蚁字」。

## 六、命中与手感（透视带来的副作用）

透视会缩小远端节点，如果命中半径还是固定 44，就会出现「看着能点，点了没反应」。

```ts
const r = Math.max(32, nodeRadius(i, cy, st) + 6);   // 触控下限 32
```

- 半径跟随 `nodeRadius`（它已经乘过 `depthScale`），再 `+6` 留一点容错；
- **下限 32**：远端球可能只有 23px 直径，纯几何命中会很难按；
- `test/mapview.test.ts` 有一条专门锁「远端仍点得中」。

其余手感参数（`mapview.ts` 常量）未变：`NODE_STEP = 116`、`FIRST_NODE_Y = 246`、
导轨 `RAIL.hitLeft = 656`。**改纵深不能改这些**——它们是 33 号版定下的节奏。

## 七、代码怎么分的

以前 `mapview.ts` 有 1334 行，几何和绘制搅在一起，改一个颜色要翻半天。现在按「一个文件一件事」切开：

| 文件 | 行数 | 只管 | 谁调 |
|---|---|---|---|
| `ui/mapview.ts` | 491 | 坐标公式、`depthScale`/`roadHalfWidth`/`nodeRadius`、滚动状态机、导轨几何、点击命中 | `main.ts`（输入）、`mapdraw.ts`、测试 |
| `ui/mapdraw.ts` | 1296 | 一切绘制：天空/星/云/行星/路/门/节点/顶栏/导轨/按钮/Toast | `main.ts`、`tools/mock-ui.ts`、`lobby-smoke.test.ts` |
| `render/mapstyle.ts` | 389 | 九套 `MapPalette`、`mixHex`、灰度去饱和 | `mapdraw.ts`、测试 |

入口签名：


`themeId` 由 `main.ts` 传 `progress.current.currentTheme`，未知 id 回落到默认星穹（老版本存的主题下线不会崩）。

## 十、一句话

> 「平」不是画得不够多，是**屏幕坐标没有 z**。
> 给尺寸一个 `depthScale`、给路一个收束、给天三层视差、给球一枚投影，
> 再让九套主题各自决定「这是哪个世界的夜晚」——同一张构图就有了纵深，也有了性格。
