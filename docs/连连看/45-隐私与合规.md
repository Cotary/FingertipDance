## 二、隐私授权怎么走的

```
boot()
  ├─ platform.privacy.installWatcher()   // 注册 onNeedPrivacyAuthorization
  ├─ await ensurePrivacyAuthorized()
  │    ├─ 没有 wx / 老基础库  → true（放行，不拦老设备）
  │    ├─ wx.getPrivacySetting → needAuthorization=false → true
  │    ├─ needAuthorization=true → wx.requirePrivacyAuthorize()
  │    │      success → true
  │    │      fail（玩家拒绝）→ false
  │    └─ 60 秒没回调 → false（授权框被系统挂起时不能把启动卡死）
  └─ if (privacyOK) login()   // 没授权就不发 wx.login
```

### 三个刻意的设计

**① 拒绝授权不等于不能玩。**
不给授权就不登录：不同步进度、不进排行榜、没有好友榜 ——
但本地进度、关卡表、音效全都在，游戏是完整的。
拦在启动页反而更糟：玩家会以为游戏坏了，而且他不会再去点第二次。

**② 拿不到 API 一律放行。**
`wx.getPrivacySetting` 不存在（很老的基础库 / Web）时必须 `resolve(true)`。
合规要求的对象是**能弹出授权框的那些版本**；弹不出来的时候平台自己也不校验。
写成 `resolve(false)` 会让老设备永远进不了游戏 —— 那是最严重的一类回归。

**③ 不用自建隐私弹窗。**
微信的官方弹窗带协议原文入口，自制的容易被判「用户看不到完整条款」。
`onNeedPrivacyAuthorization` 里我们只 `resolve()`（不带参数）= 交给平台默认处理。

## 三、适龄提示

- 档位：**8+**（`AGE_RATING`，单人益智解谜，无社交、无付费、有广告）
- 文案（`AGE_LINES`）：
  1. 本游戏为单人益智解谜，适合 8 周岁及以上用户。
  2. 未满 16 周岁的未成年人请在家长陪同下使用。
  3. 游戏内含广告，点击前会明确提示。
- 时机：**首次启动**自动弹一次（本地键 `age_gate_ack`），之后从「我的 → 适龄提示」回看。
- 遮罩本身也是确认按钮：点卡外任何地方都等于「我知道了」，不会出现点不动的死路。

> 不每次启动都弹：合规只要求「给出提示」，没要求「每次确认」。
> 每次弹就成了一条每次都要点掉的拦路虎，玩家第三次就开始烦。

## 四、隐私保护指引文本（粘到微信后台）

> 位置：微信公众平台 → 设置 → 服务内容声明 → **用户隐私保护指引**
> 勾选：**用户信息（微信昵称、头像）**、**设备信息**
> 填完把「隐私协议版本」提交审核；小程序侧用 `wx.openPrivacyContract` 就能看到这份原文。

```
《指间》用户隐私保护指引

生效日期：2026 年 11 月 22 日
更新日期：2026 年 11 月 22 日

一、我们收集哪些信息
1. 账号标识：使用微信登录时，我们会通过微信开放接口获得你的用户唯一标识（openid），
   用于创建游戏账号、同步关卡进度、参与排行榜。我们不会获得你的微信密码。
2. 昵称与头像：仅在你主动点击「我的 → 昵称头像」并同意授权后收集，用于在排行榜、
   好友榜和分享卡片中显示。你随时可以不再授权，此时我们将显示默认昵称与首字头像。
3. 游戏数据：关卡进度、星级、用时、悔棋次数、看广告次数，用于进度同步与战绩展示。
4. 设备与日志：为排查故障，服务端会记录请求时间、接口与错误码。我们不采集
   通讯录、位置、相册、通话记录，也不读取你设备上的其他应用。

二、我们如何使用这些信息
- 提供游戏服务：保存与恢复进度、计算排行榜名次、展示战绩；
- 保障安全：识别异常请求（例如伪造通关成绩），维护排行榜公平；
- 改进体验：按整体统计（不针对个人）分析关卡难度与流失。

三、我们如何共享
- 微信广告组件（激励视频、插屏、Banner）由微信提供，其数据处理遵循微信的隐私政策；
  我们仅接收「是否看完」的结果，不接触广告平台采集的设备信息。
- 除法律法规要求外，我们不会向任何第三方出售或提供你的个人信息。

四、我们如何存储与保护
- 数据存储于中国境内的服务器，传输使用 HTTPS；
- 微信 openid 在服务端以哈希值与加密值两种形式保存，不落明文；
- 账号数据保留至你申请删除账号为止。

五、你的权利
- 查看与更正：在「我的」页可查看昵称、头像与战绩，并可重新授权修改；
- 撤回授权：在微信「设置 → 隐私 → 授权管理」中关闭本游戏的授权；
- 删除数据：通过下方联系方式申请删除账号及全部游戏数据，我们将在 15 个工作日内处理。

六、未成年人保护
本游戏适合 8 周岁及以上用户。未满 16 周岁的未成年人请在家长指导下使用。
我们不会主动收集未成年人的额外个人信息；如监护人发现相关信息被收集，
可通过下方方式联系我们删除。

七、联系我们
邮箱：<运营填写>
```

## 五、头像昵称：为什么必须玩家点一下

微信从 2022 年起收紧了用户信息接口：

- `wx.getUserProfile` **必须由用户手势触发**，启动时自动调会被判「诱导授权」直接拒审；
- 新版本 `wx.getUserInfo` 返回的是**匿名数据**（灰头像 + 「微信用户」）。

所以流程只能是：

```
我的 → 昵称头像
  → platform.profile.request()   // wx.getUserProfile（老基础库退回 getUserInfo）
  → 用户看到授权框
  → POST /api/profile { nickname, avatar }   // 落库，换设备也能带走
  → progress.sync + 开放数据域 publishMyProfile()（好友榜同步改名）
```

服务端 `UpdateHandler` 的两条规矩：

- **空字段不覆盖**（`CASE WHEN $1 = '' THEN nickname ELSE $1 END`）——
  只想换头像时不会把昵称清空，否则好友榜上会变成一排「玩家」；
- 昵称超过 24 字**截断**而不是报错：玩家不该因为名字太长而保存失败。

### 工程（错了不报错，只是线上坏）

- [ ] **`project.config.json` 的 appid 不是游客值** —— `touristappid` /
      `tt0000000000000000` 只能预览，**上传会被拒**。
      构建脚本会在结尾打警告；设 `WX_APPID=wx...` / `DY_APPID=tt...` 重新构建，
      或手改 `line-wx/` / `line-dy/project.config.json`（脚本会保留非占位值）
- [ ] **构建时给了 `API_BASE`** —— 小游戏构建漏配**会直接失败**，
      显式给环回地址也会失败（见 `scripts/api-base.ts`）。
      产物自检：`grep -c "127.0.0.1" line-wx/dist/game.js` 必须为 **0**
- [ ] 微信后台「服务器域名 → request 合法域名」已加 API 域名（https、已备案）
- [ ] `config.prod.yaml` 的 `wechat` / `douyin` 两段都填了真实 appid+secret 且 `mock: false`
- [ ] `config.prod.yaml` 的 `cors.allowed_origins` 保持 `[]`
      （小游戏不带 `Origin` 头，不受影响；后台网页跨域时才往里加具体域名，
      **不要写 `*`**）
- [ ] `jwt.ttl_hours` 在 24~72 之间（模板是 72；720 意味着令牌泄露后能用 30 天）
- [ ] 广告位 ID 已填（`44` 的 A1）—— 没填时广告走兜底发放，收入为 0
