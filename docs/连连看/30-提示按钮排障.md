# 提示按钮「点了没反应」排障

> 2026-11-12 · 起因：玩家（也是我们自己测试时）点「提示」，画面毫无变化。

## 结论先说

不是按钮坏了 —— **点击一直有命中**。问题在点击之后：`useHint()` 在四种情况下
**静默 return**，一句反馈都没有。其中一种正好是第 1 关的默认状态。

| # | 触发条件 | 旧行为 | 影响面 |
|---|---|---|---|
| 1 | 自由起点关卡（D=0）且还没下笔 | 求解器无线头 → `found:false` → 直接 return | 32 关，**含第 1 关** |
| 2 | 松手后的 1.5 秒宽限期（`paused`） | 相位不匹配 → return | 所有关卡的高频时刻 |
| 3 | 首次使用要过激励视频（3 秒） | 屏幕无任何变化 | 每关第一次 |
| 4 | 求解失败（走岔 / 预算耗尽） | `console.log` 之后就 return | 约 5% 的高难关 |

前三条是「玩家点了、觉得坏了」；第四条是「确实给不出，但不说」。

## 1. 自由起点关卡的第一手

提示器的模型是「**从当前线头往后**再求一条铺满剩余格的路」。
可自由起点（D=0）关卡在空盘上**根本没有线头** —— 玩家还没下笔，也就没有「接下来」。

旧代码在这里返回 `{cells: [], found: false}`，注释写的是「只能提示随便挑一格起手」，
但**并没有真的去挑**。而第 1 关的 HUD 正好写着「起点自由 · 任意格都能起手」——
新玩家第一次点提示，就撞在这个洞上。

### 为什么不能用参考解

第一反应是把参考解带进客户端（表里本来就有 `solution` 字段）。
**不行**：`data/levels-v3-client.json` 是刻意剥掉参考解的，`coverLevelStore.ts`
的注释写得很清楚 ——「参考解是答案，绝不能下发到客户端」。走这条路等于把答案发到前端。

### 实际做法：替他挑一格

空盘时 `state.visited` 全零，`solveRemaining(state, 候选格, …)` 问的正是
「从这格起手能不能铺满剩下的」。于是：

1. 候选 = 所有可走格，**按四邻接度升序**排 —— 哈密顿路径的两端绝大多数是死角（度 1），
   从死角起手命中率最高；而按编号从 0 试起，前几格大多是内部格，每次都要搜到底才失败；
2. 逐个试，第一个能走通的就取前 3 格当提示；
3. **总时限共享**（仍是 120ms），最多试 16 个候选，超时收手。

全量实测（`tools/probe-hint.ts`）：

```
自由起点 32 关：给出提示 32（100.0%）
  平均 1.0ms，最慢 13ms（第 29 关）
```

## 2. 宽限期点提示

松手后有 1.5 秒宽限（见 `28-移动端适配体检.md`），此时相位是 `paused`。
旧守卫只放行 `idle` / `dragging`，所以「刚抬手想问提示」这个**最自然的时机**被挡掉了。

现在 `paused` 也放行 —— 路径没清、线头还在，问「下一步」完全说得通。
即使随后宽限到期、整段作废，`findCoverHint` 读的是**调用那一刻**的状态，
会自己退化成「空盘挑起手格」，不会给出指向已消失路径的过期建议。

## 3. 等广告的三秒

Web / 调试环境的模拟广告只是干等 3 秒，屏幕上什么都不发生 ——
这三秒足够让玩家认定「按钮坏了」并连点三次。

现在广告开始就挂一条 `提示准备中…`（3200ms）。微信端激励视频有自己的界面，
这条提示被盖住，无害。

广告返回后还会校验 `session.state === st`：这几秒里玩家可能已经通关或换关，
不能把提示贴到旧关卡上。

## 4. 给不出时要说一声

- 走岔了（有 `backtrackTo`）→ 高亮那一格 + 「这条线已经走不通了，退回到高亮格试试」
- 真给不出 → 「这一关暂时给不出提示」

### 剩下的 5%

钉死起点的关卡里，空盘点提示有 **50/1000** 给不出（`findCoverHint` 的搜索预算内没辙）。
试过放宽时限：

```
时限 300ms  -> 救回 3/50（总耗时 14.4s）
时限 600ms  -> 救回 4/50（总耗时 17.2s）
时限 1200ms -> 救回 4/50（总耗时 17.2s）
```

几乎救不回来，而单次代价从 120ms 涨到 1.2 秒（主线程同步跑，玩家会感觉卡死）。
**维持 120ms，靠文案说明**。这批关卡是 9×9 / 10×10 的高难关（第 159/256/707/726 等），
要真正解决得动求解器（换启发式或上 Web Worker），不在这次范围。

## 5. 顺带修掉的：高亮从不消失

`state.hint` 一旦设置就**再也没被清过**。玩家照着提示走完那两格，黄色环还挂在原地 ——
「接下来该往哪走」变成一句过期的建议，比不给还糟。

现在三个时机清掉：

| 时机 | 位置 |
|---|---|
| 走了一步 / 回退 | `tryCoverMove` |
| 整段作废 | `resetPath`（`failCover` / `abandon` 都走它） |

## 排查方法备忘

「点了没反应」这类问题，只看 `console.error` 是查不到的 —— 静默 return 不报错。
`tools/shot-cdp.mjs` 补了三个开关：

```bash
LOG=1 ...        # 全量转发页面 console，连 console.log 一起看
PRINT=1 ...      # 真实 CSS 视口尺寸（headless 的 --window-size 会被系统缩放改写）
EVAL="..." ...   # 页面内求值，可在一次求值里完成「点击 → 等 → 读日志」
```

最后那个尤其有用：把「点击 + 等待 + 取日志」放进**同一次** `Runtime.evaluate`，
时序才可控 —— 分成多次发命令时，中间的 `setTimeout` 偶尔会被拖到超时之后。
