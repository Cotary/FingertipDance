## 1. 为什么有这份文档

T01–T22 的规格（GDD / 美术规范 / 屏幕分区）里**从头到尾没有大厅**：

- `10-GDD-连连看.md` §2 核心循环第一句是「进入游戏 → 看到当前关卡与已装备皮肤」
- `04-美术规范.md` §2.1 屏幕分区图只有 HUD / 棋盘 / 进度条 / 主按钮四层

所以 T01–T22 实现出来的版本是一个**裸游戏循环**——启动直接进关卡，没有主页、没有关卡选择、没有底部导航。用户提供的参考截图（`I:\work\f-game\连连看` 下 6 张）明确是一个完整 App 外壳。

本文 + T23 任务书补齐这部分。**不改动 T01–T22 的任何既有结论**，只在客户端前端补页面，不动关卡生成/求解/后端表结构。

## 2. 页面清单与导航结构

```
        ┌──────────────────────────────────────┐
        │           游戏内（深色主题）           │
        │  playing ←──── 返回大厅 ───→ home     │
        │  result  ←──── 返回大厅 ───→ home     │
        └──────────────────────────────────────┘

        ┌──────────────────────────────────────┐
        │         大厅体系（亮色卡通主题）        │
        │  ┌─────┬─────┬─────┬─────┬─────┐     │
        │  │主页 │地图 │皮肤 │排行 │我的 │ ← 底部导航（常驻）
        │  └─────┴─────┴─────┴─────┴─────┘     │
        │   home  map  skins  rank  profile    │
        └──────────────────────────────────────┘

分享挑战进入（带 ?challenge= 参数）→ 直接进 playing，不经过大厅
```

**规则**：
- 底部导航常驻于 home / map / skins / rank / profile 五个页面
- playing / result 页面**不显示**底部导航
- 从任意大厅页进入关卡，返回时回到**上一个大厅页**（本版本简化为回 home）

## 3. 主题系统

两套主题，边界清晰：

| 主题 | 常量 | 使用范围 | 底色 |
|---|---|---|---|
| 游戏内 | `GAME_THEME` | playing / result | `#141824` 深色扁平 |
| 大厅 | `LOBBY_THEME` | home / map / skins / rank / profile | `#EEF3FF` 亮色卡通 |

## 5. 关卡地图（对应参考图 52_2）

### 5.1 路线算法

S 形竖向曲线：

```
x(idx) = 375 + sin((idx-1) * 0.55) * 200
y(idx) = 210 + (idx-1) * 132
```

- 节点间距 `NODE_GAP = 132`
- 路线用 `lineWidth = 12` 的圆头折线连接，色 `rgba(61,123,255,0.35)`

### 5.2 节点三态与装饰

| 状态 | 判定 | 底色 | 描边 | 附加 |
|---|---|---|---|---|
| done | idx ≤ maxLevel | 暖黄 | `#E0A93B` 3px | 下方 3 颗星（实心数 = 星级） |
| current | idx == maxLevel | 白 | 主蓝 5px | 呼吸光圈 + 更大半径 40 |
| locked | idx > maxLevel | `#CBD6E8` | 白 3px | 锁图形（矩形锁体 + 半圆锁梁） |

**章节里程碑**：每 10 关（`idx % 10 === 0`）在节点侧边插一面小三角旗（红旗），旗杆 3px。

### 5.3 虚拟滚动

- 可视区：`ROUTE_TOP = 210` 到 `VIEW_BOTTOM = DESIGN_H - 120`（底部导航之上）
- `visibleRange(scrollY)` = `[floor(scrollY/NODE_GAP) - 1, ceil((scrollY + 可视高)/NODE_GAP) + 1]`，并夹到 `[1, levelCount]`
- 只渲染可视区内的节点 → 1000 关也不掉帧
- 拖动 vs 点击用 `moved` 标志区分：位移 > 6px 判定为拖动，松手不进关

### 5.4 星级

星级来自服务端 `GET /api/progress/stars`，返回 `{ stars: { "1": 3, "2": 2, ... } }`。

阈值（**前后端必须一致**）：

| 星级 | 条件（steps / shortest） |
|---|---|
| ★★★ | ≤ 1.15 |
| ★★ | ≤ 1.5 |
| ★ | 其他 |

客户端 `ui/hud.ts` 的 `starOf()` 与服务端 `stars.go` 的 `StarOf()` 是两份实现，靠双端测试锁定边界。

## 6. 排行榜页

两个 Tab：**总榜** / **好友榜**。

### 6.1 总榜

- 数据源：`GET /api/leaderboard`（Redis ZSet，已存在但首版无 UI 调用）
- 行高 84，底板白/白半透明交替
- 名次徽章圆 r=22，前三名金 `#FFC93C` / 银 `#C9D2E0` / 铜 `#E0A97A`，其余描边色
- 左侧：名次徽章 + 昵称（26px）+ `第 N 关 · X 秒`
- 右侧：主蓝圆角徽章 `N 关`
- 吸底条：我的名次 `第 N 名 / M 人` 或 `未上榜`

### 6.2 好友榜

复用 `ui/friends.ts` 的开放数据域 `sharedCanvas` 绘制 + 统计面板（好友数 / 平均进度 / 最高进度 / 我的名次）。

Web 端无开放数据域，回退到服务端 `GET /api/friends` 的列表。
