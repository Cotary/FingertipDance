# 03 — 后端规格（Go）

> 后端是**权威端**：关卡表下发、成绩校验、排行榜、好友统计的唯一来源。
> 分层沿用大 plan 的 L1/L2/L3。

---

```

│  │  ├─ jwt.go                      # JWT 签发/校验
│  │  ├─ middleware.go               # CORS / 日志 / 鉴权 / 限流
│  │  └─ errors.go                   # 业务错误类型
│  ├─ platform/
│  │  └─ wechat/
│  │     ├─ code2session.go          # L1：wx code → openid/session_key
│  │     └─ openid.go                # openid 加密存储（AES + AppID 派生）
│  ├─ modules/                       # L2 通用模块（跨游戏）
│  │  ├─ profile/profile.go          # 昵称/头像/设置
│  │  ├─ leaderboard/leaderboard.go  # Redis ZSet 榜单
│  │  └─ friend/friend.go            # 自维护好友
│  └─ games/line/                    # L3 本游戏专属
│     ├─ levels.go                   # 关卡表加载（embed）+ 下发

├─ data/

│  ├─ 001_init.sql
└─ deploy/
   ├─ docker-compose.yml
   ├─ config.local.yaml
   └─ nginx.conf
```

**铁律**
- `internal/games/line/` 里出现一个 `wx.` 字面量 = 架构违规
- `internal/modules/` 里出现任何游戏专属概念 = 架构违规
- `internal/platform/` 只做翻译，不含业务逻辑

## 3. 数据模型（`migrations/001_init.sql`）

```sql
CREATE TABLE users (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  openid        VARCHAR(64)  NOT NULL,           -- 加密存储
  openid_hash   CHAR(64)     NOT NULL,           -- sha256(openid)，用于唯一索引与查询
  nickname      VARCHAR(64)  NOT NULL DEFAULT '',
  avatar        VARCHAR(512) NOT NULL DEFAULT '',
  max_level     INT          NOT NULL DEFAULT 0,
  total_time_ms BIGINT       NOT NULL DEFAULT 0,
  total_steps   INT          NOT NULL DEFAULT 0,
  unlocked_skins JSON        NOT NULL,
  ad_watch_cnt  INT          NOT NULL DEFAULT 0,
  created_at    DATETIME     NOT NULL,
  last_login_at DATETIME     NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_openid_hash (openid_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE level_records (
  uid        BIGINT UNSIGNED NOT NULL,
  level_idx  INT          NOT NULL,
  steps      INT          NOT NULL,
  time_ms    INT          NOT NULL,
  path       JSON         NOT NULL,     -- 格子索引序列
  skipped    TINYINT(1)   NOT NULL DEFAULT 0,
  created_at DATETIME     NOT NULL,
  PRIMARY KEY (uid, level_idx),
  KEY idx_level (level_idx)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE friends (
  uid        BIGINT UNSIGNED NOT NULL,
  friend_uid BIGINT UNSIGNED NOT NULL,
  status     TINYINT NOT NULL,           -- 0=pending 1=accepted 2=blocked
  created_at DATETIME NOT NULL,
  PRIMARY KEY (uid, friend_uid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE scores (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  uid        BIGINT UNSIGNED NOT NULL,
  level_idx  INT    NOT NULL,
  steps      INT    NOT NULL,
  time_ms    INT    NOT NULL,
  created_at DATETIME NOT NULL,
  PRIMARY KEY (id),
  KEY idx_uid (uid), KEY idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE skips (
  uid        BIGINT UNSIGNED NOT NULL,
  level_idx  INT    NOT NULL,
  day        VARCHAR(10) NOT NULL,     -- YYYY-MM-DD
  PRIMARY KEY (uid, level_idx, day)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**索引说明**
- `level_records` 用 `PRIMARY KEY (uid, level_idx)` → 一人一关一条，天然幂等（重复提交即 upsert 保留最优）
- `openid` 加密存储 + `openid_hash` 唯一索引 → 既满足"数据库里不存明文 openid"，又能高效查找
- `scores` 只增不改 → 支撑总榜与流失热力图统计

## 4. 接口清单

统一响应包装（`core/resp.go`）：

```json
{ "code": 0, "msg": "ok", "data": { } }
```
`code != 0` 为失败。错误码见下表。

### 4.1 `POST /api/login`
**请求**：`{ "code": "wx.login 的 code", "nickname": "", "avatar": "" }`
**处理**：
1. `platform/wechat.Code2Session(code)` → `openid`（mock 模式返回 `mock_openid_<code>`）
2. `sha256(openid)` → 查 `users`；不存在则创建（`unlocked_skins = ["wood"]`）
3. 更新 `last_login_at`、昵称头像（若非空）
4. 签发 JWT（`uid` 作为 subject）
**响应**：`{ "token": "...", "uid": 123, "nickname": "", "avatar": "", "maxLevel": 5, "unlockedSkins": ["wood","mint"], "adWatchCnt": 0 }`

### 4.2 `GET /api/config`
**响应**：
```json
{
  "levelVersion": "sha256:9f2c...",
  "levelCount": 1000,
  "skins": [ { "id":"wood", "name":"原木", "tier":"free", "unlockType":"default", "unlockValue":0 } ],
  "ad": { "rewardedVideoId": "adunit-xxx", "interstitialId": "adunit-yyy" },
  "features": { "hint": true, "skip": true, "shareChallenge": true },
  "serverTime": 1730000000000
}
```

### 4.3 `GET /api/levels?from=1&count=50`
**校验**：`from ≥ 1`，`count` ∈ [1, 100]
**响应**：`{ "version": "sha256:...", "from": 1, "levels": [ ...关卡对象... ] }`
- 只返回 `levels.json` 的公开字段，**不含 `solution`**
- 服务端启动时把 `levels.json` 与 `solutions.json` 都读进内存（121KB × 2，零压力）

### 4.4 `POST /api/progress`
**请求**：
```json
{ "levelIdx": 12, "steps": 14, "timeMs": 42310, "path": [0,6,12,...], "skipped": false }
```
**处理（成绩校验，核心）**：
1. 查关卡 → 不存在 → `4004 关卡不存在`
2. `skipped == true` → 走跳过分支：校验 `steps == level.shortest`，写 `level_records(skipped=1)`，**不发皮肤**
3. 否则逐项校验（与 `core/solver.ts` 的 `isPathLegal` 同规则）：
   - `path[0]` 是 START、`path[last]` 是 END
   - `len(path) == steps + 1`
   - 每步 4 邻接
   - 中间格非 BLOCK
   - 中间格若 ONEWAY，进入方向 == 箭头方向
   - START/END 不出现在中间
4. `steps >= level.shortest` → 否则 `4005 步数低于理论最短`
5. `timeMs` 下限检查：`timeMs < steps * 50` → `4006 用时异常`（50ms/步 是极宽松的下限）
6. 通过 → 事务内：
   - upsert `level_records`（保留更优：`steps` 更少 或 `steps` 相同但 `time_ms` 更小）
   - 更新 `users.max_level`（仅当 `level_idx > max_level`）
   - 累加 `users.total_time_ms` / `total_steps`（**仅当该关首次通关**，避免重复提交刷数值）
   - 写入 `scores` 一条流水
   - 更新 Redis 榜单
   - **解锁皮肤**：`level.unlockSkin` 不在 `unlocked_skins` → 加入
7. 更新 Redis 榜单分数：`score = max_level * 1000000 - min(total_time_ms/1000, 999999)`
8. 每日首次通关 → `ad_watch_cnt` 不变（广告次数是另一回事）

**响应**：
```json
{ "passed": true, "unlockedSkin": { "id":"marble","name":"大理石" } | null,
  "isNewBest": false, "maxLevel": 13, "unlockedSkins": [...], "myRank": 42 }
```

### 4.5 `GET /api/leaderboard?scope=global&around=5`
- `scope=global`：Redis ZSet `rank:global` 的 Top 100（含 `uid` → 查 `users` 补昵称头像）
- `around=5`：额外返回当前用户前后各 5 名
- **响应**：`{ "list": [ {"rank":1,"uid":9,"nickname":"","avatar":"","maxLevel":100,"totalTimeMs":123456} ], "myRank": 42, "total": 1234 }`
- `total` = `ZCARD`

### 4.6 `POST /api/friend`
**请求**：`{ "action": "apply|accept|remove|block|unblock", "friendUid": 123 }`
**响应**：`{ "ok": true }`
- `apply` → 写 `friends(uid=me, friend_uid=target, status=pending)`，并写反向行 `status=pending`
- `accept` → 双方状态改 `accepted`
- `remove` → 删两行
- `block` → 状态 `blocked`

### 4.7 `GET /api/friends`
**响应**：`{ "list": [ {"uid":1,"nickname":"","avatar":"","maxLevel":30,"totalTimeMs":123456,"skinCount":3,"isMutual":true} ] }`
- 用于"好友进度统计面板"的服务端版本

### 4.8 `POST /api/challenge`
**请求**：`{ "levelIdx": 27, "steps": 16, "timeMs": 40122, "path": [...] }`
**处理**：与 `/api/progress` 同样的校验，但**不推进主线进度**（`max_level` 不变），只写 `scores` 并记录挑战结果。
**响应**：`{ "passed": true, "best": { "steps": 15, "timeMs": 38000 } }`

### 4.9 `POST /api/skip`
**请求**：`{ "levelIdx": 27 }`
**处理**：
1. 查 `skips` 表 `WHERE uid=? AND level_idx=? AND day=?` → 已存在 → `4007 本关今日已跳过`
2. 写 `skips` 一行
3. 写 `level_records(skipped=1, steps=shortest)`
4. **不推进 `max_level`**（跳过的关卡不算通关），但**发放该关皮肤**（GDD 第 9 节说"跳过不发放皮肤奖励"→ 改为：不发放通关皮肤，但推进到该关以便继续）

> **口径统一**：跳过 → `max_level` 推进到该关（否则玩家卡死），但**该关皮肤不发**，需要在 `unlocked_skins` 里记录"已跳过"以防后续重复发放。
> 简化实现：`level_records.skipped=1` 的关卡，其 `unlockSkin` 永不发放。

**响应**：`{ "ok": true, "maxLevel": 28 }`

## 5. 错误码表

| code | 含义 |
|---|---|
| 0 | 成功 |
| 4000 | 参数错误 |
| 4001 | 未登录 / token 无效 |
| 4002 | 频率限制 |
| 4004 | 关卡不存在 |
| 4005 | 步数低于理论最短（作弊） |
| 4006 | 用时异常（作弊） |
| 4007 | 本关今日已跳过 |
| 4008 | 路径非法（作弊） |
| 5000 | 服务器内部错误 |

## 6. 中间件

| 中间件 | 行为 |
|---|---|
| `CORS` | 允许 `*`（开发期）；生产按域名白名单 |
| `Logger` | 记录 `method/path/status/latency/uid` |
| `Auth` | 解析 `Authorization: Bearer <token>`，注入 `uid` 到 context；`/api/login`、`/api/config` 白名单 |
| `RateLimit` | 基于 Redis 令牌桶；写接口 10 次/秒/IP，登录 5 次/分钟/IP |

---

## 7. 安全

- **openid 不落明文**：`AES-GCM` 加密（密钥 = SHA256(appid+secret)），`openid_hash` = SHA256(openid) 做唯一索引
- **成绩校验必须做**（本项目唯一的作弊入口就是进度上报）
- JWT 有效期 30 天，`HS256`
- 路径长度上限 200（防超大 payload）

## 9. 启动自检（`cmd/http/main.go`）

启动时依次检查，任一失败则**打印错误并退出**（不要带着半张表上线）：
1. DB 可连接，迁移已执行（查 `users` 表是否存在）
2. Redis 可连接
3. `data/levels.json` 与 `data/solutions.json` 存在且 `version` 一致
4. `levels.json` 的 `count` == 实际关卡数
5. **抽检 50 关**（均匀分布：第 1 关、中间 48 关、最后 1 关）：解码 grid → 验证 `solutions.json` 的路径合法 → 验证 `steps == len(solution)-1`
6. 打印启动摘要：版本号、关卡数、皮肤数、DB/Redis 状态
