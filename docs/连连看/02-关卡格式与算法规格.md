# 02 — 关卡格式与算法规格

> **关卡生成与求解的唯一来源。** 客户端（提示）与关卡表流水线（生成）都以此为准。
> 关键约束：**生成器只在 TypeScript 侧实现一份**，Go 侧不重复实现。

---

## 1. 关卡表文件格式

### 1.1 `data/levels.json`（公开，会下发给客户端）

```json
{
  "version": "sha256:9f2c1a...（前 12 位十六进制）",
  "count": 1000,
  "generatedAt": "2026-11-01T13:00:00Z",
  "levels": [
    {
      "idx": 1,
      "seed": 2748129301,
      "w": 6,
      "h": 6,
      "grid": "BAQAAA...（base64，见 1.2）",
      "shortest": 9,
      "turns": 2,
      "blocks": 3,
      "oneways": 0,
      "diff": 8,
      "unlockSkin": "mint"
    }
  ]
}
```

### 1.2 `grid` 的 base64 编码（紧凑，自研）

每个格子 1 字节，高位到低位：

| bit | 含义 |
|---|---|
| `bit 7` | `1` = 该格是 ONEWAY，否则 `0` |
| `bit 6..4` | 方向 `dir`（0..3），仅当 bit7 = 1 时有效 |
| `bit 3..2` | `type & 3`，见下表 |
| `bit 1..0` | 保留，恒为 0 |

**type 编码**（`bit 3..2` 只有 2 位，需要 5 种类型 → 改用 3 位）：

> 修正：使用 `bit 3..1`（3 位，0..7）存 type，`bit 0` 恒为 0。

| type | 含义 |
|---|---|
| 0 | BLOCK |
| 1 | BRICK |
| 2 | ONEWAY |
| 3 | START |
| 4 | END |

**方向编码**：`bit 6..4`（3 位，0..3），`0=UP, 1=DOWN, 2=LEFT, 3=RIGHT`

最终布局：每格 1 字节，按行优先（`y` 从 0 到 `h-1`，每行 `x` 从 0 到 `w-1`）拼接，字节序 = 该格的 `type | (dir<<4) | (isOneWay<<7)`。

> 编码**必须往返一致**：`decode(encode(grid))` 深度相等。T02 要写这个测试。
> 体积：6×6=36B，9×9=81B，11×11=121B → 1000 关平均 ≈ 95B → **总计 ≈ 95KB**，gzip 后 ≈ 28KB。

### 1.3 `data/solutions.json`（私密，仅服务端）

```json
{
  "version": "sha256:9f2c1a...",
  "levels": [
    { "idx": 1, "solution": [0, 6, 12, 18, ...], "solutionSteps": 9, "turns": 2, "diff": 8 }
  ]
}
```
- `solution` 是**格子索引序列**（`idx = y*w + x`），从 START 到 END
- **绝不下发给客户端**（下发答案 = 可直接作弊通关）

### 1.4 `version` 的一致性机制

- `version` = `sha256(levels.json 内容)` 取前 12 位十六进制
- 服务端 `/api/config` 返回 `levelVersion`
- 客户端本地缓存关卡时带上 version；不一致 → 清空缓存重新拉取
- 服务端启动时校验：`count == len(levels)`、`version` 匹配、抽检 50 关用 `solutions.json` 验证路径合法 → 不通过则**拒绝启动**

## 3. RNG 规格

```ts
export interface Rng {
  next(): number;                 // [0, 1)
  int(minInclusive: number, maxExclusive: number): number;
  pick<T>(arr: readonly T[]): T;
  shuffle<T>(arr: readonly T[]): T[];
  chance(p: number): boolean;
}
export function mulberry32(seed: number): Rng;
export function hashSeed(str: string): number;   // FNV-1a 32 位
export function levelSeed(globalSeed: number, idx: number): number;
```

- `levelSeed` = `hashSeed(`${globalSeed}:${idx}`)`，保证关卡之间互不相关
- **禁止 `Math.random()`**，所有随机都走 `Rng`

## 4. 难度曲线（`core/curve.ts`）

```ts
export interface CurveParams {
  w: number; h: number;
  blocks: number;        // 阻挡块数量
  oneways: number;       // 单向块数量
  minTurns: number;      // 正解路径最少转弯数
  branchPenalty: number; // 分叉抑制强度 0..1
  openRatio: number;     // 目标开放面积比下限
}
export function curveFor(idx: number): CurveParams;
```

### 4.1 分段表

| idx | w×h | blocks | oneways | minTurns | openRatio |
|---|---|---|---|---|---|
| 1–10 | 6×6 | 0–3 | 0 | 1 | 0.78 |
| 11–30 | 7×7 | 6–12 | 0–2 | 2 | 0.72 |
| 31–60 | 8×8 | 12–20 | 3–6 | 3 | 0.66 |
| 61–150 | 9×9 | 20–30 | 6–10 | 4 | 0.60 |
| 151–400 | 9×9 | 28–38 | 8–14 | 5 | 0.56 |
| 401–700 | 10×10 | 35–48 | 10–16 | 6 | 0.52 |
| 701–1000 | 10~11×11 | 45–60 | 12–20 | 7 | 0.48 |

**段内插值**：段内 idx 归一化 `t = (idx - segStart) / (segLen - 1)`，数值用 `lerp(start, end, easeInOut(t))`。

### 4.2 难度分 `diff`（0–100）

```
diff = 100 * (
    0.30 * clamp01(blocks / (w*h*0.45)) +
    0.15 * clamp01(oneways / (w*h*0.25)) +
    0.25 * clamp01(turns / 8) +
    0.20 * clamp01((1 - openRatio) / 0.55) +
    0.10 * clamp01(1 - uniqueness)
)
```
- `uniqueness` = 最短路条数归一化（`1` 表示唯一解）
- 计算后 `round`，钳制到 `[0, 100]`

### 4.3 目标难度曲线

`targetDiff(idx)` = 分段线性上升，1–10 关从 5 升到 15，11–1000 关从 15 升到 92。
**每 10 关加一个"小高峰"**：`(idx % 10 === 0) ? +8 : 0`，并钳制 ≤ 100。
**每 100 关是"大关"**：(idx % 100 === 0) 时额外放宽 `openRatio` 下限 0.04、`blocks` -6（即相对同段稍微简单一点，但转折更多）→ 让大关"绕但不死"。

### 4.4 校准指标（`batch-audit` 输出）

每 10 关一档，输出：`平均 diff`、`平均步数`、`平均转弯`、`平均阻挡率`、`最短路唯一解占比`、`无解数`。
**判定标准**
- 无解数必须 = 0
- `平均 diff` 与 `targetDiff` 的偏差 ≤ ±8
- 最短路唯一解占比 ≥ 60%（低于则"随便走也能过"）
- 相邻档 `平均 diff` 增量 ∈ [3, 12]（不能忽平忽陡）

## 5. 求解器规格（`core/solver.ts`）

### 5.1 状态空间

由于单向块让**进入方向**成为状态的一部分：

```ts
interface Node { x: number; y: number; enterDir: Dir; }
```
- START 节点：`enterDir` 任取（起点无进入方向约束）
- 转移：当前节点 `(x,y)` 的**离开方向** `d` → 目标 `(nx,ny)`
  - `nx,ny` 必须在界内
  - 目标不是 BLOCK
  - 若目标是 ONEWAY，则**进入方向 == 箭头方向**才合法（进入方向 = 从 `(x,y)` 指向 `(nx,ny)` 的方向，即 `d`）
  - 目标不是已访问状态 `(nx,ny, d)`
- 注意：单向块的**离开方向不受限**

### 5.2 API

```ts
export interface SolveResult {
  solvable: boolean;
  steps: number;                    // 最短步数；无解时 -1
  paths: number[][];                // 所有最短路径（格子索引序列），最多保留 8 条用于唯一性判定
  pathCount: number;                // 最短路总条数（截断到 8 表示 ≥8）
  visited: number;
}

export function solve(grid: Cell[][], from?: {x,y}, maxPaths?: number): SolveResult;
export function isPathLegal(grid: Cell[][], path: number[]): boolean;  // 服务端校验同款逻辑
export function countTurns(path: number[], w: number): number;
export function findHint(grid: Cell[][], head: {x,y}, steps?: number): number[];  // 提示
```

### 5.3 BFS 实现要点

- 队列元素 `{x, y, enterDir}`，访问集合 key = `idx * 4 + enterDir`
- 父指针数组记录路径 → 从终点回溯出路径
- **要统计所有最短路径**才能算唯一性 → BFS 在最短层内继续扩展，记录到达每个状态的最短距离 `dist[]`，只有 `dist == 当前层` 的转移才计入 `paths`
- `maxPaths` 默认 8；达到上限后停止收集但**继续 BFS**（保证 `steps` 正确）
- 网格最大 11×11=121 格 × 4 方向 = 484 状态 → BFS 极快，单关 < 0.1ms

### 5.4 `isPathLegal` 规则（服务端成绩校验同款）

```
1. path 非空，path[0] 是 START，path[last] 是 END
2. 长度 = steps + 1
3. 相邻两格必须 4 邻接
4. 中间格不能是 BLOCK
5. 中间格若是 ONEWAY，进入方向必须 == 箭头方向
6. START/END 不能出现在中间
```

## 6. 生成器规格（`core/generator.ts`）

### 6.1 整体流程

```
gen(idx, seed):
  params = curveFor(idx)
  rng  = mulberry32(levelSeed(seed, idx))
  for attempt in 1..MAX_ATTEMPT(=40):
     level = attemptGenerate(idx, params, rng)
     if level == null: continue
     res = solve(level.grid)
     if !res.solvable: continue                      // 情况 A：重生成
     if res.steps < params.minPathLen: continue      // 情况 A'：太短
     if res.pathCount > 1:                           // 情况 C：分叉太多
        if !narrowBranches(level, res, rng): continue
        res = solve(level.grid)                     // 收窄后必须重验
        if !res.solvable || res.pathCount > 1: continue
     level.shortest = res.steps
     level.turns    = countTurns(res.paths[0], level.w)
     level.diff     = computeDiff(level, res)
     if abs(level.diff - targetDiff(idx)) <= 6: return level
     // 情况 B：难度偏离 → 记入 nextLevel 供下次微调
     nextLevel = adjust(level, params, rng)
     if nextLevel: return nextLevel
  return lastBest   // 兜底：用尝试中 diff 最接近目标的那一关
```

### 6.2 `attemptGenerate` 细节

**步骤 1：摆 START / END**
- START 在左侧列（`x=0`）或上侧行（`y=0`），随机选一个；同理 END 在右侧列或下侧行
- 二者不贴同一条边；`w=6,h=6` 时用随机偏移量避免正对

**步骤 2：造正解路径**
- 用「带朝向的随机游走」：每步在**不立即回退**的候选方向里选一个，朝 END 方向有加权加成
- 当 `len(path) < params.minPathLen` 时继续延伸
- 强制转弯：记录当前路径的转弯数，若 `< minTurns` 则**优先选会转弯的方向**
- `minPathLen` 建议 = `max(w, h) * 1.4`（6×6 → 9 步左右）
- 路径上的格子先标记为 BRICK

**步骤 3：放单向块**
- 在**路径上**选择若干格替换为 ONEWAY
  - **关键约束**：该格的箭头方向必须与路径在此处的**离开方向一致**
  - 否则玩家沿正解走会被单向块挡住 → 无解
- 放在路径上而非路径外，是因为单向块的语义是"引导"，放在路径外容易变成死路陷阱

**步骤 4：放阻挡块**
- 在**非路径格**中随机选 `params.blocks` 个
- **禁止贴边围死 START**：START 上下左右至少留 1 个可通行格
- 放置后立即验证"从 START 出发可达 END"（用 solver）

**步骤 5：计算开放面积比**
- `open = (总格 - blocks) / 总格`
- 若 `< params.openRatio` → 减少 blocks 后重试

### 6.3 `narrowBranches`（情况 C 处理）

- 取 solver 返回的第 2 条最短路径
- 找出它与第 1 条路径**分叉的那个格子** `p`
- 在 `p` 的一个"分叉方向"上放一个 BLOCK（该方向不能是通向 END 的方向）
- 这样就把第 2 条路径堵掉了
- 若有 >2 条等价路径，重复执行（最多 3 轮），每轮后重跑 solver

### 6.4 `adjust`（情况 B 处理：难度微调）

| 情况 | 动作 |
|---|---|
| diff 偏低（关卡太水） | ① 增加 1–3 个阻挡块（避开路径）② 把路径上 1–2 个 BRICK 改成 ONEWAY ③ 增 1 个分叉再 narrow |
| diff 偏高（太难） | ① 移除 1–3 个阻挡块 ② 放宽 openRatio ③ 减少单向块 |
| 调整后 | 重跑 solver，必须仍可解且 `steps >= shortest_before`（不能变得更简单） |

### 6.5 去重

- 布局指纹 = `grid` 的 base64 编码字符串（不含尺寸则加尺寸前缀）
- 关卡表流水线里检测重复指纹 → 换 seed 重生成

## 7. 关卡表流水线（`tools/level-gen.ts`）

### 7.1 CLI

```bash
npm run level:gen -- --count 1000 --seed 20261101 --out data/levels.json
```
参数：
- `--count` 生成数量（默认 1000）
- `--seed` 全局种子（默认 20261101）
- `--out` 输出路径
- `--solutions` 私密解法输出路径（默认 `data/solutions.json`）
- `--start` 起始关号（默认 1），用于**增量生成**：只生成 idx ≥ start 的关，保留已有文件里 idx < start 的部分

### 7.2 流程

1. 逐关生成（带进度输出：`[ 123/1000 ] idx=123 diff=41 steps=17 ✓`）
2. 每关立即用 solver 复验（生成器内部已做，这里是独立二次校验，防生成器 bug）
3. 检测重复指纹 → 重生成（最多 5 次）
4. 写 `levels.json` + `solutions.json`
5. 计算 `version` = sha256(levels.json)
6. **写完后重新读回并校验**：解码每关 grid → 求解器验证 → 与 `solutions.json` 对照 → 有任何不一致则**退出码非 0**

### 7.3 批量体检（`tools/batch-audit.ts`）

```bash
npm run level:audit -- --file data/levels.json --report out/audit.md
```
输出内容：
- 总数、无解数、重复数、编码往返失败数
- 每 10 关一档的难度统计表（见 4.4）
- **diff 分布直方图**（ASCII）
- **异常关卡列表**：`diff` 与目标偏差 > 12 的关号、`shortest < 8` 的关号（过于简单的关）
- 退出码：有异常则非 0

## 8. 关卡调试器（`tools/level-inspector.html`）

一个独立 HTML（不依赖 Vite 构建，双击即开）：

> 调试器是**调参主力**，比肉眼可靠。P1 阶段必须做完。

## 9. 提示功能（`findHint`）

```ts
findHint(grid, head, steps = 2): number[]
```
- 从 `head` 出发跑 BFS，找到到达 END 的最短路径
- 返回路径的前 `steps` 个格子（不含 head 本身）
- 若 head 已经在某条最短路径上 → 返回该路径的后续
- 若 head 走不到 END（玩家走岔了）→ 返回**从 head 到最近可达点的方向**，或者返回空数组让 UI 提示"回到起点重来"
- 客户端据此高亮格子 + 画引导箭头
