# 01 — GDD（玩法规格）

> **判定逻辑的唯一来源。** 客户端渲染、客户端提示、服务端成绩校验三者都以此为准。
> 任何规则疑问先查这里。

---

## 1. 核心循环

```
打开游戏 → 看到「第 N 关」+ 当前皮肤
   → 按住 🟢起点拖动 → 经过若干砖块 → 抵达 🔴终点
      → 若中途走错 → 断线回退到上一个合法点（不惩罚，只是重来那一段）
   → 抵达终点 → 全盘砖块波次点亮 → 结算页
      → 解锁皮肤 N+1 + 进度条前进 + 分享按钮亮起
   → 下一关
```

**单关时长目标：30–90 秒。** 超过 90 秒的关卡在难度曲线里算"大关"。

---

## 2. 棋盘与格子

- 棋盘为 `w × h` 的矩形网格
- 格子类型见 `00-项目约定.md` 第 5 节
- **每关有且仅有一个 🟢START 和一个 🔴END**，二者位置不同格
- START 与 END **不在同一直线上（横/纵）**，且不贴同一条边（否则关卡退化）
- 起点与终点位于棋盘的**相对两侧边缘**（START 在左/上，END 在右/下，或反之），二者所在边允许有少量错位

### 2.1 阻挡块（🔲）
- 不可进入
- 贴边布置时形成"墙"，用于限制起始走位

### 2.2 单向块（➡️）
- 有方向 `dir`
- **只能沿 `dir` 方向进入**
  - 即：玩家从 `(x,y) - delta(dir)` 移动到 `(x,y)` 才合法
- 玩家**可以**从单向块沿 `dir` 方向离开（离开方向不受限）
- 视觉：块面上画一个箭头，箭头指向 = `dir`

### 2.3 普通砖块（🟧）
- 进入即"点亮"（视觉上从灰变亮）
- 不影响通行
- **已点亮的砖块仍然可以再次经过**（不做消除，避免出现"路径断了"的技术性失败）

> **重要设计决策**：不做"消除"。如果砖块被消除，后续路径可能无处可走，玩家会陷入"自己把自己走死"的挫败感。点亮的砖块只是视觉反馈。

---

## 3. 输入与连线规则

### 3.1 开始
- 玩家在 START 块上按下 → 进入 `dragging` 状态
- 若按下不在 START 上 → 忽略（不做"从任意点开始"）

### 3.2 移动
- 手指移动时，找到**距离手指最近的格子**（欧氏距离最小）
- 若该格子与当前线头**4 邻接** → 尝试移动
- 若**不是 4 邻接** → **断线**：
  - 线头回退到**上一个合法点**（即断线前的位置）
  - 已点亮的砖块**保持点亮**
  - 播放红色抖动 + 短促音效
  - **不扣分、不失败**

### 3.3 不可进入的情况（断线处理同 3.2）
- 目标是 BLOCK
- 目标是 ONEWAY 且进入方向 ≠ 箭头方向
- 目标是**已经点亮的砖块** → **允许**（可重复经过），但不重复播放点亮动画

### 3.4 回退（撤销）
- **不允许**主动回退（松开手指前不能往回走）
- 已走过的格子再次经过时：**跳过重复的转弯**，视觉上不画折角

### 3.5 松手
- 松手时若线头 ≠ END → **本段作废**：
  - 全部砖块熄灭，线头回到 START
  - 玩家可以重新开始拖
  - **不算失败**，只是"这次没走完"
- 松手时线头 = END → **通关**

> **不做硬失败**。关卡只有"没走完"，没有"失败"。卡住时用「提示」/「跳过」（看广告）。这是 IAA 休闲品类标准做法。

## 4. 胜利与结算

1. 线头抵达 END → 冻结输入
2. **通关演出**（约 1.2 秒）：
   - 从 START 出发，以波次形式向外扩散点亮所有已走过路径上的砖块（每层间隔 60ms）
   - 终点块放大 + 辉光 + 粒子迸发
3. 结算页显示：
   - `第 N 关 通关！`
   - 本关步数 / 用时 / 评价（★☆☆ 按步数与 `shortest` 的比值）
   - **皮肤解锁卡片**（"解锁了新皮肤：大理石" + 预览 + 立即装备按钮）
   - 进度条：`第 N 关 / 皮肤 3/12`
   - 按钮：`下一关`（主）、`分享`（次）、`皮肤`（次）
4. **下一关**按钮默认聚焦，分享按钮在**首次刷新好友榜第一**时高亮跳动

### 4.1 星级评价
```
ratio = steps / shortest
3★: ratio <= 1.15
2★: ratio <= 1.5
1★: 其他
```
（`shortest` 由生成器写入关卡表，服务端也用它做校验）

## 5. 难度构成

| 维度 | 说明 |
|---|---|
| 棋盘尺寸 | 6×6 → 11×11 |
| 阻挡块密度 | 越高越难 |
| 单向块密度 | 越高越难 |
| 强制转弯数 | 正解路径必须转弯的次数 |
| 唯一性 | 最短解路径越唯一越好（避免"随便走也能过"） |
| 开放面积比 | 可通行格 / 总格数，过低则过于憋屈 |

**难度分 `diff`（0–100）** 由上述加权得出，具体公式见 `02-关卡格式与算法规格.md` 第 4 节。

## 6. 后续可扩展玩法（本期不实现，规格预留）

1. **收集式**：路径必须途经所有 💎 宝石才能到终点
   - 实现：仅改 `solver.ts` 的目标判定 + `generator.ts` 的装饰规则
2. **颜色匹配**：只能走到与当前颜色相同的砖块，按顺序切色
3. **步数限制**：限定最大步数，超出需用「重置」

> 这三条**不动物理层与渲染层**，只改求解器目标判定和生成器规则 → 所以求解器必须做成独立可参数化模块。

## 7. 成功指标（用于 P15 手感验收与上线后复盘）

| 指标 | 目标 |
|---|---|
| 单关时长 | 30–90 秒（P50） |
| 首次进入到第一次通关 | ≤ 60 秒 |
| 首关通过率 | ≥ 95%（第 1 关必须是教学关） |
| 第 10 关通过率 | ≥ 75% |
| 关卡流失热力图 | 每关流失率无异常尖峰（相邻关流失差 < 15%） |
| 次日留存 | > 40% |
| 7 日留存 | > 15% |

## 8. 提示（Hint）机制

- 按钮位置：关卡内右上角
- 行为：调用 `solver.ts` 的 `findHint(grid, currentHead, currentDir)`，返回**接下来 1–3 步**的正确格子
- 表现：这几个格子高亮 + 呼吸动画 + 引导箭头
- 首次使用（每关一次）**必须看广告**；同一关第二次使用免费（避免逼迫感，也给二次播放机会）
- **服务端不参与提示计算**：关卡表已下发完整 grid，客户端本地算即可

---

## 9. 跳过（Skip）机制

- 按钮位置：关卡内右上角，提示按钮旁边
- 行为：看广告 → 直接判定本关通关，步数记为 `shortest`（记为"跳过通关"）
- 效果：**跳过不发放该关的皮肤奖励**（皮肤仍可通过之后的关卡解锁），但发放"跳过"标记，结算页展示
- 防滥用：同一关每 24 小时最多跳过 1 次（客户端记录 + 服务端记录）
