# 提示改成「可跟随的整条路线」

> 2026-11-12 · 起因：提示只亮 3 格，玩家看不出「往哪走」，等于没提示。

## 结论先说

旧实现把求解结果**截断到 3 格**（线头 + 2 步）。而求解器本来就把整条剩余路径算完了 ——
截断**不省任何计算**，只省了玩家的信息量。

现在的模型：

| | 旧 | 新 |
|---|---|---|
| 数据 | 3 个格子的集合 | 整条剩余路线（`cells`，长度 = 剩余步数） |
| 存法 | `hint: Set<number>` | `hint: CoverHintPlan \| null`（路线 + 游标 + 点亮时刻） |
| 走一步 | 整组清空，要再点一次 | 游标 +1，窗口向前滑一格 |
| 走岔了 | 整组清空 | 整条清空（不重新求解，见下） |
| 同时亮几格 | 3 | **5**（`HINT_WINDOW`），尾部随窗口滑入 |

## 为什么是 5 格

盘面 11×11 最多 121 格。一次性全点亮 = 一张色块图，反而看不出「下一步是哪」。

5 格刚好吃得下一次转折（直行 + 拐弯 + 再直行）：够读出方向，又不至于把答案糊在脸上。

## 视觉：由近到远的三层递减

同一个窗口里，五格不是「一样亮的 5 个环」——那样只会被读成「这 5 格随便点一个」。

1. **亮金 → 深琥珀**：`#FFCE40` → `rgb(196,128,36)`
2. **描边由粗到细**：`0.115·size` → `0.049·size`
3. **底色由深到浅**：暖白 0.30 → 0.12

第一版描边不透明度是 `1 / .72 / .52 / .36 / .24`，实拍直接否掉了：
盘面空格是**蓝灰**的，琥珀压在蓝灰上本来就缺明度对比，再乘 0.36 等于没画。
现在下限抬到 0.44，让「远」靠**变细**表达，而不是靠「淡到消失」。

### 依次点亮

- 装路线时前 5 格**错峰点亮**，70ms 一格（`litAt[k] = now + k·70`），
  读起来像一只手电沿着路线扫过去，而不是「啪」地出现五个环；
- 之后叠加一层沿窗口流动的呼吸（`sin(now/300 - k·0.9)`），静态截图看不出，
  动起来才有「往那边走」的感觉；
- 窗口滑动时尾部新补进来的那格，从 `litAt` 起 170ms 内淡入，不会硬闪。

### 试过但否掉：连接虚线

试过在窗口各格之间画虚线（「实线是走过的、虚线是没走的」）。
2× 实拍后否掉：一格一段的距离配上虚线间隙，出来是一堆零碎短横，
既没连成路的形态，又把环和底色衬得更乱。顺序感交给「渐弱 + 变细」就够了。

## 状态机怎么跟随

`coverState.ts` 里三个函数，全部围绕游标：

- `setHintPlan(state, cells, now)` —— 装路线，`at = 0`，预填前 5 格的 `litAt`；
- `consumeHintCells(state, consumed, now)` —— 玩家走了 `consumed` 之后推进游标：
  **每一格都对得上**才前进，**有一格对不上**就整条作废；
- `clearHint(state)` —— 回退 / 重来 / 换关时用。

`tryCoverMove` 的两个 `moved` 分支（单步、快拖补齐）都会调 `consumeHintCells`，
所以冰块滑行一次吃两格、快拖一次吃五格，游标都是一次跳过去的。

### 两个容易踩的起步分支

起步走的是 `beginCoverDrag`，不是 `tryCoverMove`，得单独处理：

| 关卡类型 | 提示第一格是 | 按下起点时 |
|---|---|---|
| 自由起点（D=0） | **起手格本身** | 兑现第一格，游标 → 1 |
| 钉死起点（D≥1） | 起点**之后**那一格 | 什么都不做，路线继续有效 |

漏了第一种，玩家按下起手格后第一颗落子就会被判成「偏离」，提示当场消失；
漏了第二种，钉死起点按下起点时会误清提示。

## 为什么偏离后不重新求解

求解只要 1~13ms，但那是**在拖动过程中**算 —— 手指会感到一顿一顿的。
而且提示突然改道比消失更让人迷惑。想再要一次，松手再点「提示」就是了
（每关第一次要过广告，之后免费）。

## 验收

- `test/cover-hint-plan.test.ts` 新增 9 条：窗口只亮 5 格且错峰、游标跟随、
  尾部补亮、偏离清空、作废清空、两种起步分支、沿路线走完能真的通关；
- `test/cover-hint.test.ts` 的冰面用例改成**真重放**——
  路线长了以后「拿初始盘面逐对判邻接」不再成立（第 40 步的合法性取决于前 39 步）；
- 全量 266 用例通过；`npx vite build` 395.56KB / gzip 81.64KB；
- 实测第 1 关：点提示 →「跟着亮的路走，还剩 21 格」→ 右列 5 格由下到上依次点亮。

## 已知限制

- 钉死起点 + 空盘 + 高难关（9×9 / 10×10）仍有约 5% 给不出提示：
  120ms 主线程预算内搜不到。要彻底解决得上 Web Worker 或换启发式，属另一件事；
- 提示目前不区分「这一步要踩冰」，玩家看到的是「该落在哪格」，
  滑行多出来的格子会在下一步随窗口滑出。
