# 关卡设计规格（Cover 模式 v2）

> **地位**：本文件是关卡设计的**现行唯一真相源**。
> `14-数值与难度曲线.md` 降级为**历史参考**（记录 v1 的实测校准过程），其 §7 的改版草案已被本文取代。
> 冲突时以本文为准。

## 0. 为什么重写

v1 的关卡被判定「差点意思」，不是数值没调好，是**三条结构性病根**：

| # | 病根 | 证据 |
|---|---|---|
| 1 | 1000 关是同一个谜题的放大版 | `generator.ts` 的 `attemptGenerate` 是**先造一条 START→END 正解路径，再把阻挡块撒在路径之外**。阻挡块永远不影响解法，只把路径外的空间堵掉一部分。玩家永远在做同一件事：「从一堆看起来一样的空格里找出唯一那条路」 |
| 2 | 难度只有量的堆砌，没有质的变化 | 旋钮只有三个：盘面变大（6×6→11×11）、转弯变多（`minTurns` 1→7）、单向块变多 |
| 3 | 设计好的分段一点没进 UI | `SEGMENTS` 的 7 段、`skinForLevel` 的奖励关、每 100 关大关，在地图上全被抹平成一条无差别直线 |

附带发现：`computeDiff` 把 `blocks` 当**正**贡献（权重 0.30），但阻挡块只放在路径外——块越多，路径外的干扰格越少，玩家反而越好找路。**这个权重方向是反的**。

v2 的解法不是调这三个旋钮，而是**换玩法约束**：从「START→END 找路」改成「走完所有格子」。

## 1. 玩法定义

### 1.1 通关条件

> **走完所有「必需格」，且路径不自交。起点与终点由玩家自选。**

即经典的**哈密顿路径**（一笔画）。与 v1 的对比：

| | v1 (Path) | v2 (Cover) |
|---|---|---|
| 通关 | 从 START 拖到 END | 覆盖全部必需格 |
| 起点 | 固定 START 格 | **任意必需格** |
| 终点 | 固定 END 格 | **任意**（路径自然终止处） |
| 未走完 | 不算通关 | 不算通关 |
| 步数 | 8~19（可变） | = 必需格数 − 1（恒定） |

`CellType.START` / `CellType.END` **不再存在**。棋盘上没有起终点标记，玩家的第一次触摸就是起点。

### 1.2 起终点自由度 = 死端数量

「刚开局不限制起终点，后面逐步收紧」不能用配置项实现，它是**棋盘拓扑的必然结果**：

- **度 = 1 的格子（死端）必然是路径的端点**——它只有一个邻居，走进去就出不来，只能是最后一格；从它出发则只能是第一格。
- 因此死端数量 `D` 直接决定起点自由度：

| D | 含义 | 玩家感知 |
|---|---|---|
| 0 | 无死端 | **完全自由**：随便从哪开始都行 |
| 1 | 一个端点被钉死 | 必须从那个尖角开始（或结束） |
| 2 | 两个端点都被钉死 | 起终点固定 = v1 的体验 |
| ≥3 | **无解** | 生成时必须拒绝 |

这就是难度主轴的第一条：**`D` 从 0 爬到 2，约束从无到有**。它是可构造、可验证的，不需要额外字段。

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| 必需格 | 必须被路径覆盖的格子（`BRICK` / `ICE` / `KEY` / `GATE` / `ONEWAY` / `PORTAL`） |
| 空洞 `VOID` | 这块地方**没有格子**。塑造棋盘轮廓 |
| 石障 `BLOCK` | 格子存在但不可进入。保持轮廓完整，在盘内制造绕行 |
| 星屑格 `SHARD` | **可选格**。不走也能通关，走了才有 3 星 |
| 度 `deg(v)` | 格子 `v` 的可进入邻居数 |
| 死端 | `deg = 1` 的必需格 |
| 走廊 | `deg = 2` 的必需格。路径经过它时两个邻居都被强制使用 |
| 分叉 | `deg ≥ 3` 的必需格。玩家在此处有选择 |
| 隘口 | 路径**被迫**通过的唯一通道 |
| 诱饵 | 走进去之后剩余图不再连通的分支 |

`VOID` 与 `BLOCK` 在**求解层完全等价**（都不可进入、不计入必需格），区别只在渲染：空洞让轮廓不规则，石障是盘内一块可见的深色黏土。

## 2. 棋盘

### 2.1 第一定律：棋盘染色奇偶性

把格子按 `(x + y) % 2` 染成黑白。路径黑白交替，因此覆盖全部必需格的路径存在必须满足：

```
|黑格数 − 白格数| ≤ 1
```

且：

| 条件 | 结论 |
|---|---|
| `\|B − W\| ≥ 2` | **无解**，生成时必须拒绝 |
| `\|B − W\| = 0` | 两个端点必为一黑一白 |
| `|B| = |W| + 1` | 两个端点都是黑格 |
| `|W| = |B| + 1` | 两个端点都是白格 |

**这是设计不规则棋盘时的物理定律**。挖洞不能随手挖——每挖一个格子就翻转一次奇偶差。它是 O(area) 的**前置过滤**，比跑一次哈密顿路径搜索便宜几个数量级，所有轮廓构造都必须先过这一关。

> 推论：挖洞要**成对挖**（一黑一白），否则奇偶差失控。这是形状库设计的硬约束。

### 2.2 第二定律：连通性

必需格集合必须**四邻接连通**，否则不可能一条路径走完。同样是 O(area) 前置过滤。

注意：这条只对**必需格**成立。星屑格可以在连通域之外（它本来就是可选的），但它必须至少与路径上某两个相邻格都相邻（见 §3.3）。

### 2.3 尺寸上限：9×9

v1 的棋盘长到 11×11，但那是 START→END 只需 8~19 步的玩法。cover 模式下**步数 = 必需格数 − 1**，11×11 意味着一次拖动 120 步——对休闲玩家过长。

**尺寸上限收到 9×9（最多 81 格，减空洞后 60~78 格）**。难度改由结构与机制承担，不再靠盘面堆大。附带好处：81 格的哈密顿路径搜索比 121 格快得多，生成性能压力大幅下降。

| 世界 | 尺寸 | 必需格数 | 步数 |
|---|---|---|---|
| 一 | 5×5 | 21~25 | 20~24 |
| 二 | 6×6 | 28~34 | 27~33 |
| 三 | 6×6 → 7×7 | 31~44 | 30~43 |
| 四 | 7×7 | 38~47 | 37~46 |
| 五 | 7×7 → 8×8 | 43~55 | 42~54 |
| 六 | 8×8 | 50~60 | 49~59 |
| 七 | 8×8 → 9×9 | 56~76 | 55~75 |

### 2.4 轮廓形状库

从满矩形出发，按 `voidPattern` 挖。每次挖完立即检查**第一定律 + 第二定律**，不过就回滚重试。

| 模式 | 做法 | 出现世界 |
|---|---|---|
| `solid` | 不挖 | 一 |
| `corner` | 挖 1~4 个角（2×2 或 L 形） | 二 |
| `hole` | 挖 1~2 个内部洞（2×2 / 1×3） | 三 |
| `island` | 挖一条「河」把盘面分开，留 1~2 座桥 | 四 |
| `cross` / `ring` / `lshape` | 预设布尔掩码 | 五 |
| `scatter` | 随机撒 3~6 个单格洞（必须成对保持奇偶） | 六 |
| `composite` | 上面任意两种叠加 | 七 |

`BLOCK`（石障）用于**保持轮廓是矩形**但在盘内制造绕行——它和挖洞的效果相同，但视觉上是「盘内有一块石头」而不是「盘缺了一块」。世界二、三以石障为主，世界四之后以空洞为主（轮廓辨识度更强）。

## 3. 机制系统

### 3.1 总表

机制**随世界依次登场**，且新机制首次登场时：盘面取该世界的**下限**尺寸、其他机制全部关闭。v1 的毛病是机制随机叠加，玩家学不明白。

| 机制 | 类型 | 效果 | 登场 | 求解状态 |
|---|---|---|---|---|
| 单向门 | `ONEWAY` | 离开方向被箭头定死 | 世界二（13） | 不变，出边减少 |
| 星屑 | `SHARD` | 可选绕道格，集齐才 3 星 | 世界三（33） | 见 §3.3 |
| 钥匙与门 | `KEY` / `GATE` | 取了钥匙才能进门 | 世界四（65） | `(idx, keyMask)`，×2^k |
| 传送门 | `PORTAL` | 成对格子，进 A 出 B | 世界五（153） | 不变，多一条边 |
| 隘口与诱饵 | 不加格子，改生成算法 | 必经隘口 / 看着通其实不通 | 世界六（405） | 不变 |
| 冰面 | `ICE` | 踩上去滑到撞墙才停 | 世界七（705） | 见 §3.7 |

### 3.2 单向门 `ONEWAY`

**语义改为「允许的离开方向」**（v1 是「进入方向必须等于箭头」，两者在自避路径下几乎等价，但箭头的视觉直觉是「往这边走」）。

实现上等价于「该格只有一条出边」——**BFS 状态空间完全不变**，只是边变少。零求解成本。

放置：只能放在**构造好的哈密顿路径上**，箭头 = 该处路径的离开方向。这样保证解一定存在。

### 3.3 星屑 `SHARD`（绕道插入法）

cover 模式下路径长度恒定，所以星屑**不能靠「绕远路」**实现——没有远路可绕。解法是给它**额外造一段路**。

**构造算法（插边法）**：

1. 先在必需格集合 `S` 上构造哈密顿路径 `P_base`（这是「不拿星屑的解」）。
2. 在 `S` 之外预留 2~6 个星屑格。
3. 对每颗星屑，在 `P_base` 上找一条边 `a→b`，把它替换成绕道 `a → s1 → s2 → b`：

```
a=(x,y), b=(x+1,y)  ⇒  绕道 = (x,y±1) → (x+1,y±1)
a=(x,y), b=(x,y+1)  ⇒  绕道 = (x±1,y) → (x±1,y+1)
```

> **注意**：网格图没有三角形，所以**不能插入单个格子**（不存在同时与 `a`、`b` 相邻的第三格）。绕道至少 2 格，这是二分图的必然。

4. 插完全部绕道得到 `P_full`——这是「集齐星屑的解」。**两个解都由构造保证存在**，不需要搜索验证。

星屑格在棋盘上渲染成带小星星的半透明黏土砖，与必需格明显不同色——玩家一眼看到「那边有星星，要不要绕过去」。

**为什么它是好机制**：它同时解决了两个问题。一是给了「再打一次」的动机（v1 完全没有），二是撑起了 §7 的星级。

**备选（未采纳）**：把星屑改成「按编号顺序经过的必经格」（时序约束，状态 `(idx, 已收集进度)`）。它确实更难，但与覆盖约束叠加后对休闲玩家过狠，且会挤掉星级的空间。留作世界七之后的加料。

### 3.4 钥匙与门 `KEY` / `GATE`

`KEY(v, k)` 是必需格，走过即拾取钥匙 `k`；`GATE(v, k)` 是必需格，未持有钥匙 `k` 时不可进入。

cover 模式下钥匙格和门格**都必走**，所以真正的约束是**时序**：必须先经过钥匙再经过门。这是真实的规划难度，不是信息隐藏。

- 求解状态 `(idx, keyMask)`，`k ≤ 3` → 状态数 ×8。BFS 可行。
- 构造：在 `P_base` 上选位置 `i` 放门，在 `i` **之前**的位置放钥匙。`P_base` 自动合法。
- 门用 `group` 字段（2 bit）记钥匙编号，最多 4 组。

### 3.5 传送门 `PORTAL`

成对格子 `A`、`B`（`group` 相同），**在图上额外加一条边** `A↔B`（几何上不相邻也能连）。

- 求解状态空间**完全不变**（只是多一条边），零额外成本。
- 视觉冲击力最强：路径在某处断开，从另一处冒出来。
- 它会彻底改变图的连通性，创造出几何上不可能的拓扑——这是后期关卡「眼前一亮」的来源。
- 构造：`growPath` 时把传送边当成普通边使用。

### 3.6 隘口与诱饵（不加格子，改生成算法）

这是**最重要也最便宜**的一条。v1 的阻挡块只撒在路径外，所以「难」纯粹是信息隐藏；v2 让难来自设计：

- **隘口**：把某个格子塑造成 `deg = 2`，且它的两个邻居路径上必须连续经过——形成必经通道。长走廊串起来就是一条「独木桥」。
- **诱饵**：在分叉处造一条分支，走进去之后剩余未访问格**不再连通**（或奇偶被破坏）。

诱饵可以量化：**诱饵深度** = 走进去多少步才发现走不通。生成后遍历所有 `deg ≥ 3` 的格子，模拟「先走该分支」，检查剩余连通性，即可自动标注。

难度旋钮因此变成**分叉数 `B`**（`deg ≥ 3` 的格子数）和**诱饵深度**，而不是 v1 的阻挡块数。

### 3.7 冰面 `ICE`

踩上去沿当前方向滑行，直到撞到边界 / 空洞 / 石障才停下。滑行经过的格子**算已走过**，且**不允许滑过已走过的格子**（否则非法）。

- 状态空间**不变**——滑动结果由 `(格子, 进入方向)` 唯一确定，可以**预计算成一张表**，BFS 时查表即可。
- 成本「中等」不是因为状态爆炸，而是因为转移函数变复杂 + 生成时的可解性验证变重。
- 生成：把滑行当作一次「多格移动」，在构造路径时整段纳入。

## 4. 生成算法

### 4.1 总流程

```
generateCoverLevel(idx, seed):
  params = curveFor(idx)                       # 尺寸 / 轮廓 / 死端 / 机制配置
  for attempt in 1..MAX_ATTEMPT:
    # 1. 轮廓：满矩形 → 挖洞 → 预留星屑格
    board = buildShape(params, rng)
    if !parityOK(board) or !connected(board):  continue      # 第一/第二定律，O(area)
    # 2. 在必需格上构造哈密顿路径
    P = hamiltonian(board, rng)                # Warnsdorff + 剪枝，带随机重启
    if !P: continue
    # 3. 机制注入（保证 P 仍是解）
    if !injectMechanics(board, P, params, rng): continue
    # 4. 验证与评分
    res = analyze(board)                       # 死端 / 分叉 / 诱饵 / 解数上界
    if !res.acceptable: continue
    # 5. 难度对齐
    if |diff − targetDiff(idx)| <= 6: return level
    keep best
  return best ?? fallback
```

关键：**v1 是「随机撒块 → 求解验证」，v2 是「构造路径 → 反推合法性」**。哈密顿路径是 NP 难，不能靠随机撒完再验证；但**构造式生成让「有解」成为构造的副产品**。

### 4.2 哈密顿路径构造

在必需格集合上找一条哈密顿路径。规模 ≤ 81 格、图稀疏（度 ≤ 4），带剪枝的回溯实际很快：

1. **Warnsdorff 规则**：优先访问「剩余未访问邻居数最少」的格子（即最孤立的那个）。网格图上极其有效。
2. **连通性剪枝**（最强）：每走一步，检查「未访问格 + 当前头部」是否仍连通（并查集增量维护）。不连通立即回溯。
3. **死端剪枝**：若存在未访问格其未访问邻居数 = 0 且不是当前头部的邻居 → 回溯。
4. **随机化**：邻居顺序按 seed 打乱 → 不同 attempt 得到不同解，也用于「多解计数」的采样。
5. **预算**：单关搜索步数上限（如 200k），超出即判失败换 attempt。

回退到**蛇形基线**：若某关在预算内搜不到（大尺寸 + 复杂轮廓），先铺一条蛇形路径作为保底解，再在此基础上做局部变换（反转一段 / 2-opt）增加变化。

### 4.3 机制注入

全部遵循一条铁律：**机制只能加在已构造好的路径 `P` 上，且加完 `P` 仍然合法**。这样「有解」永远不用验证。

- `ONEWAY`：箭头 = `P` 在该处的离开方向。
- `SHARD`：按 §3.3 插边，插完更新 `P` 为 `P_full`。
- `KEY/GATE`：门在位置 `i`，钥匙在 `i` 之前。
- `PORTAL`：把 `(A,B)` 当作 `P` 上允许的一条边。
- `ICE`：整段滑行纳入 `P`。

### 4.4 退化策略

若某关连续 `MAX_ATTEMPT` 次失败，按序降级：减少机制数量 → 简化轮廓 → 缩小尺寸 → 蛇形保底。保证流水线不崩（v1 已有 `fallbackLevel`，v2 保留同机制）。

## 5. 求解、提示与校验

### 5.1 参考解必须入库

cover 模式下「给提示」意味着从当前线头出发找一条覆盖剩余所有格的路径——这是一个 NP 难子问题，运行时求解不可接受。

**生成时把参考解存进关卡表**。编码：

```
起点索引（1~2 字节） + 每步方向 2 bit
```

81 格 → 80 步 × 2 bit = **20 字节**；1000 关 ≈ 20 KB。压缩后可忽略。

v1 已经有 `SolutionTableFile`（私密解法表），v2 把它从「调试用」提升为**运行时依赖**。

这一条带来三个收益：

1. **提示是 O(1) 查表**，且保证一定正确（不会给出走不通的提示）。
2. **服务端校验不需要跑求解器**（见 §5.3）。
3. **关卡质量可离线全量复核**。

### 5.2 提示

`findHint` 改为：从参考解中定位玩家当前路径的最后一次匹配，返回后续 1~2 步。若玩家已偏离参考解（走岔了），提示「这一步之后无解」，并高亮第一个分歧点。

> 玩家走岔后，参考解不一定能接回去——此时更实用的做法是提示「撤销到某个分叉点」，而不是硬给一条新路径。

### 5.3 服务端成绩校验

v1 的 `isPathLegal` 要求 `path[0] === START`、`path[last] === END`。v2 改为：

1. 路径不自交、每步四邻接、不进入 `VOID`/`BLOCK`、尊重 `ONEWAY`/`GATE`/`PORTAL`/`ICE` 规则；
2. 覆盖**全部必需格**（用 bitmask，O(len)）；
3. `steps === requiredCount − 1 + 走过的星屑数`（防篡改）。

不需要搜索，纯线性扫描。

### 5.4 ⚠️ 星级规则必须反转

v1 的 `StarOf(steps, shortest)`：

```go
ratio := float64(steps) / float64(shortest)
case ratio <= 1.15: return 3
```

在 cover 模式下这**正好是反的**：只走必需格时 `ratio = 1.0` → 3 星；**绕路收集星屑反而 `ratio > 1.15` → 降星**。我们想要奖励的行为被公式惩罚了。

同时 `shortest` 在 cover 模式下恒等于 `必需格数 − 1`，是个常量字段，不再携带信息。

新规则见 §7。它同时影响 `server/internal/games/line/stars.go` 与 `src/ui/hud.ts`（两处阈值必须一致，v1 已有这个约定）。

## 6. 难度体系

### 6.1 六个维度

难度不再由单一 `diff` 驱动，而是六维**逐维解锁**：

| 维度 | 由松到紧 |
|---|---|
| 棋盘尺寸 | 5×5 → 9×9 |
| 轮廓复杂度 | 满矩形 → 挖角 → 挖洞 → 岛屿 → 不规则 → 复合 |
| **死端数 `D`** | 0（起终点自由）→ 1 → 2（起终点固定） |
| **分叉数 `B`** | 少（走廊化、近乎唯一解）→ 多（选择爆炸） |
| 机制 | 无 → 单向门 → 星屑 → 钥匙门 → 传送门 → 隘口诱饵 → 冰面 |
| 诱饵深度 | 无 → 一眼看穿 → 走 3~5 步才发现是死路 |

v1 的 `blocks` 维度**删除**（cover 模式下 `VOID`/`BLOCK` 已并入轮廓复杂度，不再单独计分）——顺带消除了 §0 里那个方向搞反的权重。

### 6.2 难度公式

```
diff = 100 * (
    0.24 * sizeTerm       # |必需格| 在 20..78 上的归一
  + 0.20 * branchTerm     # deg>=3 的格子占比
  + 0.16 * deadEndTerm    # D=0 → 0.0 / D=1 → 0.5 / D=2 → 1.0
  + 0.18 * mechTerm       # 机制种类加权 + 数量
  + 0.12 * shapeTerm      # 空洞数 + 轮廓周长/面积比
  + 0.10 * baitTerm       # 最深诱饵深度
)
```

> 权重是**先验值**，没有实测支撑（v1 的权重是拍脑袋后校准出来的，v2 的第一次全量生成后必须用 §10 的门禁复核并回填）。这一点与 v1 不同：v1 是先有公式后有实测，v2 明确承认公式待校准。

`targetDiff` 的目标曲线保持「段内缓升 + 峰值」的形状：世界内从该世界下限升到上限，世界末关 +4。

### 6.3 世界阶梯

复用地图页已落地的七个世界（边界已对齐行首，见 `23-UI风格方案.md` §7.7）：

| 世界 | 关号 | 尺寸 | 轮廓 | D | 新机制 |
|---|---|---|---|---|---|
| 一 苗圃 | 1–12 | 5×5 | solid | 0 | — |
| 二 石溪 | 13–32 | 6×6 | corner + 石障 | 0 | 单向门 |
| 三 苔原 | 33–64 | 6×6→7×7 | hole | 0→1 | 星屑 |
| 四 熔炉 | 65–152 | 7×7 | island / cross | 1 | 钥匙门 |
| 五 深井 | 153–404 | 7×7→8×8 | ring / lshape | 1→2 | 传送门 |
| 六 云阶 | 405–704 | 8×8 | scatter | 2 | 隘口诱饵 |
| 七 星穹 | 705–1000 | 8×8→9×9 | composite | 2 | 冰面 |

机制登场点**对齐世界边界**而不是任意关号：玩家进入新世界的那一刻就意识到「有新东西了」，而地图页的世界门正好在那个位置。

## 7. 星级

### 7.1 为什么必须重定义

cover 模式下 `steps ≡ 必需格数 − 1`，`ratio ≡ 1.0`，`StarOf` 恒等于 3 星——星级失效。而如果玩家绕路拿星屑，`ratio` 变大反而**降星**（§5.4）。两个方向都错。

### 7.2 新规则

两个独立条件，**统一适用于有无星屑的关卡**：

| 星 | 条件 |
|---|---|
| 3 | 通关 **且** 集齐所有星屑 **且** 零重来 |
| 2 | 通关 **且**（集齐星屑 **或** 零重来） |
| 1 | 通关 |

- 早期关卡没有星屑（`required = 0`）→ 「集齐」自动成立 → 3 星 = 零重来。自然落位，**不需要两套规则**。
- 「重来」定义：松手时未通关，`path` 被清空 → `undos += 1`。拖动中的回退（pop）不计。

### 7.3 数据结构与后端改动

| 位置 | 改动 |
|---|---|
| 关卡表 | 新增 `shards: number`（该关星屑总数，0 或 3） |
| 上报 | 新增 `shards`（本次收集数）、`undos`（重来次数） |
| DB | `ALTER TABLE level_records ADD COLUMN shards INT NOT NULL DEFAULT 0, ADD COLUMN undos INT NOT NULL DEFAULT 0;` |
| `stars.go` | `StarOf(shards, required, undos int) int`，替换现版本 |
| `hud.ts` | `starOf` 同步，两处阈值必须一致 |
| `shortest` | 保留字段但语义退化为「必需格数 − 1」，仅用于展示与兼容 |

## 8. 数据结构与迁移

### 8.1 `CellType` 重新编号

`codec.ts` 现在每格 1 字节：`bit7` oneway 标志 / `bit6..4` dir / `bit3..1` type（3 bit，只够 8 种）。新类型需要 9 种，且 `dir` 只要 2 bit：

```
byte = (type << 4) | (dir << 2) | group
  type  4 bit  (0..15)
  dir   2 bit  (0..3)
  group 2 bit  (0..3)   传送门配对号 / 钥匙-门编号
```

| 值 | 类型 | 说明 |
|---|---|---|
| 0 | `VOID` | 空洞 |
| 1 | `BRICK` | 必需格 |
| 2 | `BLOCK` | 石障 |
| 3 | `ONEWAY` | 单向门（`dir` = 允许的离开方向） |
| 4 | `SHARD` | 星屑（可选格） |
| 5 | `KEY` | 钥匙（`group` = 钥匙号） |
| 6 | `GATE` | 门（`group` = 钥匙号） |
| 7 | `PORTAL` | 传送门（`group` = 配对号） |
| 8 | `ICE` | 冰面（必需格的变体） |

`START` / `END` **删除**。

### 8.2 `Level` 字段

| 字段 | 变化 |
|---|---|
| `w` / `h` | 保留 |
| `grid` | 新编码 |
| `shortest` | 语义退化为 `必需格数 − 1` |
| `turns` | 保留（参考解的转弯数） |
| `blocks` / `oneways` | 保留（统计用） |
| `diff` | 新公式 |
| **`shards`** | 新增，星屑总数 |
| **`required`** | 新增，必需格数（= shortest + 1， redundancy 但校验方便） |
| `unlockSkin` | 保留（已收敛为 premium 三关） |
| **`solution`** | 参考解方向序列（从私密解法表提升为运行时依赖） |

### 8.3 版本与换表

关卡表有 version hash（`computeVersion` 取内容 SHA-256 前 12 位），新表 hash 必然不同 → **可平滑换表**：服务端同时挂新旧两表，按客户端版本分发。

旧客户端遇到新表会读不懂（新 `CellType`），所以必须是**强制更新**或**按版本分流**。建议：`levelTable.version` 里带 schema 版本号（如 `v2-<hash>`），服务端据此决定给哪张表。

## 10. 验收门禁

生成 1000 关后必须全过：

| # | 指标 | 门槛 |
|---|---|---|
| 1 | 每关必需格连通 | 100% |
| 2 | `\|B − W\| ≤ 1`（第一定律） | 100% |
| 3 | 参考解合法且覆盖全部必需格 | 100% |
| 4 | 参考解方向序列能无损回放出格子序列 | 100% |
| 5 | 无星屑时存在覆盖全部必需格的路径 | 100%（由 `P_base` 构造保证） |
| 6 | 有星屑时存在「必需格 ∪ 星屑格」的路径 | 100%（由 `P_full` 构造保证） |
| 7 | 死端数 `D ≤ 2` | 100% |
| 8 | 解数上界：世界一、二 ≥ 4；世界五~七 ≤ 4 占比 ≥ 60% | 见下 |
| 9 | 无重复布局（同尺寸 + 同机制配置下 grid 不重复） | 100% |
| 10 | 世界内难度单调不降（滑动窗口均值） | 100% |
| 11 | 1000 关生成总耗时 | < 120s |
| 12 | 单关最坏生成耗时 | < 2s |

第 8 条的「解数上界」用**有界枚举**（DFS 找到 9 条即停）估计。精确计数哈密顿路径是 #P 难，我们不追求精确，只区分「≤2 / 3~8 / >8」三档。

> v1 的教训：规格 02 §4.4 里「相邻档 diff 增量 ≥ 3」「步数增量 ≥ 1」两条指标与 0–100 / 8–21 的量纲直接矛盾，属规格内部不自洽。v2 的门禁全部改为**可判定的布尔条件**，不再用不可达的增量指标。

## 11. 实施计划

| 阶段 | 内容 | 产出 |
|---|---|---|
| 0 | 数据层：`CellType` 重编号、`codec` 改位布局、`Level` 加字段、schema 版本号 | 新旧表可共存 |

## 12. 开放问题

1. **星屑方案**：本文采纳「绕道插入法」（§3.3）。备选是「顺序必经星屑」（时序约束）。前者更友好且撑起星级，后者更难。若后期觉得不够难，可在世界七叠加后者。
2. **冰面**：滑行 + 覆盖约束叠加后，生成时的可解性验证会明显变重。若阶段 3 发现预算撑不住，冰面可以降级为「只在世界七的后半段出现」或直接砍掉。
3. **参考解入库**：20 KB 的体积换来 O(1) 提示与免搜索校验，判断是划算的。若关卡表体积成为瓶颈（微信端首包），可改为「参考解单独一张表，按需拉取」。
4. **难度公式权重**：§6.2 的六个权重是先验值，第一次全量生成后必须用实测回填。不要把它当成已校准的数值。
5. **`shortest` 字段**：cover 模式下它是常量，保留只为兼容与展示。若后端改造彻底，可以删掉。
6. **重跑时机**：`tools/level-gen.ts` 的 `skinForLevel` 已收敛为 premium 三关（200/500/900），但**要重跑才生效**；在此之前旧表的 3/8/15…关仍带 `unlockSkin`，服务端照发。阶段 6 一并解决。
