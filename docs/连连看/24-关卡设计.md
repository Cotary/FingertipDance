# 关卡设计规格（Cover 模式 v2）

> **地位**：本文件是关卡设计的**现行唯一真相源**。
> `14-数值与难度曲线.md` 降级为**历史参考**（记录 v1 的实测校准过程），其 §7 的改版草案已被本文取代。
> 冲突时以本文为准。

## 0. 为什么重写

v1 的关卡被判定「差点意思」，不是数值没调好，是**三条结构性病根**：

| # | 病根 | 证据 |
|---|---|---|
| 1 | 1000 关是同一个谜题的放大版 | `generator.ts` 的 `attemptGenerate` 是**先造一条 START→END 正解路径，再把阻挡块撒在路径之外**。阻挡块永远不影响解法，只把路径外的空间堵掉一部分。玩家永远在做同一件事：「从一堆看起来一样的空格里找出唯一那条路」 |
| 2 | 难度只有量的堆砌，没有质的变化 | 旋钮只有三个：盘面变大（6×6→11×11）、转弯变多（`minTurns` 1→7）、单向块变多 |
| 3 | 设计好的分段一点没进 UI | `SEGMENTS` 的 7 段、`skinForLevel` 的奖励关、每 100 关大关，在地图上全被抹平成一条无差别直线 |

附带发现：`computeDiff` 把 `blocks` 当**正**贡献（权重 0.30），但阻挡块只放在路径外——块越多，路径外的干扰格越少，玩家反而越好找路。**这个权重方向是反的**。

v2 的解法不是调这三个旋钮，而是**换玩法约束**：从「START→END 找路」改成「走完所有格子」。

## 1. 玩法定义

### 1.1 通关条件

> **走完所有「必需格」，且路径不自交。起点与终点由玩家自选。**

即经典的**哈密顿路径**（一笔画）。与 v1 的对比：

| | v1 (Path) | v2 (Cover) |
|---|---|---|
| 通关 | 从 START 拖到 END | 覆盖全部必需格 |
| 起点 | 固定 START 格 | **任意必需格** |
| 终点 | 固定 END 格 | **任意**（路径自然终止处） |
| 未走完 | 不算通关 | 不算通关 |
| 步数 | 8~19（可变） | = 必需格数 − 1（恒定） |

`CellType.START` / `CellType.END` **不再存在**。棋盘上没有起终点标记，玩家的第一次触摸就是起点。

### 1.2 起终点自由度 = 死端数量

「刚开局不限制起终点，后面逐步收紧」不能用配置项实现，它是**棋盘拓扑的必然结果**：

- **度 = 1 的格子（死端）必然是路径的端点**——它只有一个邻居，走进去就出不来，只能是最后一格；从它出发则只能是第一格。
- 因此死端数量 `D` 直接决定起点自由度：

| D | 含义 | 玩家感知 |
|---|---|---|
| 0 | 无死端 | **完全自由**：随便从哪开始都行 |
| 1 | 一个端点被钉死 | 必须从那个尖角开始（或结束） |
| 2 | 两个端点都被钉死 | 起终点固定 = v1 的体验 |
| ≥3 | **无解** | 生成时必须拒绝 |

这就是难度主轴的第一条：**`D` 从 0 爬到 2，约束从无到有**。它是可构造、可验证的，不需要额外字段。

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| 必需格 | 必须被路径覆盖的格子（`BRICK` / `ICE` / `KEY` / `GATE` / `ONEWAY` / `PORTAL`） |
| 空洞 `VOID` | 这块地方**没有格子**。塑造棋盘轮廓 |
| 石障 `BLOCK` | 格子存在但不可进入。保持轮廓完整，在盘内制造绕行 |
| 星屑格 `SHARD` | 必需格的一种。带编号，必须**按编号顺序**经过 |
| 度 `deg(v)` | 格子 `v` 的可进入邻居数 |
| 死端 | `deg = 1` 的必需格 |
| 走廊 | `deg = 2` 的必需格。路径经过它时两个邻居都被强制使用 |
| 分叉 | `deg ≥ 3` 的必需格。玩家在此处有选择 |
| 隘口 | 路径**被迫**通过的唯一通道 |
| 诱饵 | 走进去之后剩余图不再连通的分支 |

`VOID` 与 `BLOCK` 在**求解层完全等价**（都不可进入、不计入必需格），区别只在渲染：空洞让轮廓不规则，石障是盘内一块可见的深色黏土。

## 2. 棋盘

### 2.1 第一定律：棋盘染色奇偶性

把格子按 `(x + y) % 2` 染成黑白。路径黑白交替，因此覆盖全部必需格的路径存在必须满足：

```
|黑格数 − 白格数| ≤ 1
```

且：

| 条件 | 结论 |
|---|---|
| `\|B − W\| ≥ 2` | **无解**，生成时必须拒绝 |
| `\|B − W\| = 0` | 两个端点必为一黑一白 |
| `|B| = |W| + 1` | 两个端点都是黑格 |
| `|W| = |B| + 1` | 两个端点都是白格 |

**这是设计不规则棋盘时的物理定律**。挖洞不能随手挖——每挖一个格子就翻转一次奇偶差。它是 O(area) 的**前置过滤**，比跑一次哈密顿路径搜索便宜几个数量级，所有轮廓构造都必须先过这一关。

> 推论：挖洞要**成对挖**（一黑一白），否则奇偶差失控。这是形状库设计的硬约束。

### 2.2 第二定律：连通性

必需格集合必须**四邻接连通**，否则不可能一条路径走完。同样是 O(area) 前置过滤。

注意：这条对**所有必需格**成立（星屑也是必需格，纳入连通性检查）。

### 2.3 尺寸：随难度阶梯增长（不再设硬上限）

上一版把尺寸上限收到 9×9，理由是「11×11 要拖 120 步」。这个判断**错了**——它把「步数」当成了操作负担。cover 模式下玩家的决策单元是**转弯和分叉**，不是格子：

- 一次拖动里，直线段是**连续滑过**的，中间不产生决策。玩家只在转弯处、分叉处动脑。
- 121 格的蛇形盘只需约 10 次转向，比 49 格的迷宫（30 次转向 + 8 个分叉）简单得多。

所以**格子数量不是瓶颈，转弯数 + 分叉数才是**。尺寸随难度阶梯增长（6×6 → 11×11），唯一真正的约束是**单局时长**——用这个反推尺寸上限，而不是拍一个 9×9。

| 世界 | 尺寸 | 必需格数（约） |
|---|---|---|
| 一 | 5×5 | 25 |
| 二 | 6×6 | 36 |
| 三 | 7×7 | 49 |
| 四 | 8×8 | 64 |
| 五 | 8×8 → 9×9 | 64 → 81 |
| 六 | 9×9 | 81 |
| 七 | 10×10 → 11×11 | 100 → 121 |

> **trade-off 要摊开**：尺寸涨 = 步数线性涨 = 单局时长涨，且生成时 121 格的哈密顿搜索比 81 格慢。解法是把「单局时长目标」设为 tuning 参数（[PLACEHOLDER]：休闲目标 60~90 秒），阶段 6 实测后据此定每世界的尺寸上限。如果测出来玩家 121 格要 3 分钟，就把世界七的尺寸压回 10×10。

### 2.4 轮廓形状库

从满矩形出发，按 `voidPattern` 挖。每次挖完立即检查**第一定律 + 第二定律**，不过就回滚重试。

| 模式 | 做法 | 出现世界 |
|---|---|---|
| `solid` | 不挖 | 一 |
| `corner` | 挖 1~4 个角（2×2 或 L 形） | 二 |
| `hole` | 挖 1~2 个内部洞（2×2 / 1×3） | 三 |
| `island` | 挖一条「河」把盘面分开，留 1~2 座桥 | 四 |
| `cross` / `ring` / `lshape` | 预设布尔掩码 | 五 |
| `scatter` | 随机撒 3~6 个单格洞（必须成对保持奇偶） | 六 |
| `composite` | 上面任意两种叠加 | 七 |

`BLOCK`（石障）用于**保持轮廓是矩形**但在盘内制造绕行——它和挖洞的效果相同，但视觉上是「盘内有一块石头」而不是「盘缺了一块」。世界二、三以石障为主，世界四之后以空洞为主（轮廓辨识度更强）。

## 3. 机制系统

### 3.1 总表

机制**随世界依次登场**，且新机制首次登场时：盘面取该世界的**下限**尺寸、其他机制全部关闭。v1 的毛病是机制随机叠加，玩家学不明白。

| 机制 | 类型 | 效果 | 登场 | 求解状态 |
|---|---|---|---|---|
| 单向门 | `ONEWAY` | 离开方向被箭头定死 | 世界二（13） | 不变，出边减少 |
| 星屑 | `SHARD` | 编号必经，按顺序经过 | 世界三（33） | 见 §3.3 |
| 钥匙与门 | `KEY` / `GATE` | 取了钥匙才能进门 | 世界四（65） | `(idx, keyMask)`，×2^k |
| 传送门 | `PORTAL` | 成对格子，进 A 出 B | 世界五（153） | 不变，多一条边 |
| 隘口与诱饵 | 不加格子，改生成算法 | 必经隘口 / 看着通其实不通 | 世界六（405） | 不变 |
| 冰面 | `ICE` | 踩上去滑到撞墙才停 | 世界七（705） | 见 §3.7 |

### 3.2 单向门 `ONEWAY`

**语义改为「允许的离开方向」**（v1 是「进入方向必须等于箭头」，两者在自避路径下几乎等价，但箭头的视觉直觉是「往这边走」）。

实现上等价于「该格只有一条出边」——**BFS 状态空间完全不变**，只是边变少。零求解成本。

放置：只能放在**构造好的哈密顿路径上**，箭头 = 该处路径的离开方向。这样保证解一定存在。

### 3.3 星屑 `SHARD`（顺序必经）

**用户定的规则是「所有出现的格子都必须走完、不能回头」**。这条规则直接否定了「可选绕道格」——星屑如果是可选的，就和「必须走完」矛盾。所以星屑只能是**必需格**，那它的作用就只剩一种：**按编号顺序经过**。

- 星屑格是必需格（必走），带编号 `1 / 2 / 3`（`group` 字段）。
- 约束：经过顺序必须是 `1 → 2 → 3`。先踩 2 再踩 1，就是死路。

**求解状态**：`(idx, 已收集进度)`，进度 `0..3` → 状态数 ×4。与钥匙门的状态扩展同构，BFS 完全可行。

**构造**：在哈密顿路径 `P` 上选 3 个位置，**按它们在 `P` 上的先后顺序编号** 1/2/3。这样 `P` 天然满足顺序约束，不需要额外验证「有解」。

- 星屑位置必须选 `deg ≥ 2` 的格子：死端只能是路径端点，而编号 2 的星屑在路径中间，放进死端就出不来了。

**难度旋钮**：星屑在 `P` 上**分布越分散**（1 在前 1/4、2 在中、3 在后 1/4），约束越强——其它哈密顿路径几乎不可能还满足这个顺序，唯一解率因此上升。数量从 1 个逐步加到 3 个。

**与「不能回头」的交互**：顺序约束和自避约束是同向的——两者都在压缩解空间。它是钥匙门（「先 A 后 B」）的加强版：星屑是「先 1 再 2 再 3」的链。

> 原「绕道插入法」作废：它依赖「星屑是可选的」，与「全部走完」冲突。记录在此，不再保留。

### 3.4 钥匙与门 `KEY` / `GATE`

`KEY(v, k)` 是必需格，走过即拾取钥匙 `k`；`GATE(v, k)` 是必需格，未持有钥匙 `k` 时不可进入。

cover 模式下钥匙格和门格**都必走**，所以真正的约束是**时序**：必须先经过钥匙再经过门。这是真实的规划难度，不是信息隐藏。

- 求解状态 `(idx, keyMask)`，`k ≤ 3` → 状态数 ×8。BFS 可行。
- 构造：在构造好的路径 `P` 上选位置 `i` 放门，在 `i` **之前**的位置放钥匙。`P` 自动合法。
- 门用 `group` 字段（2 bit）记钥匙编号，最多 4 组。

### 3.5 传送门 `PORTAL`

成对格子 `A`、`B`（`group` 相同），**在图上额外加一条边** `A↔B`（几何上不相邻也能连）。

- 求解状态空间**完全不变**（只是多一条边），零额外成本。
- 视觉冲击力最强：路径在某处断开，从另一处冒出来。
- 它会彻底改变图的连通性，创造出几何上不可能的拓扑——这是后期关卡「眼前一亮」的来源。
- 构造：`growPath` 时把传送边当成普通边使用。

### 3.6 隘口与诱饵（不加格子，改生成算法）

这是**最重要也最便宜**的一条。v1 的阻挡块只撒在路径外，所以「难」纯粹是信息隐藏；v2 让难来自设计：

- **隘口**：把某个格子塑造成 `deg = 2`，且它的两个邻居路径上必须连续经过——形成必经通道。长走廊串起来就是一条「独木桥」。
- **诱饵**：在分叉处造一条分支，走进去之后剩余未访问格**不再连通**（或奇偶被破坏）。

诱饵可以量化：**诱饵深度** = 走进去多少步才发现走不通。生成后遍历所有 `deg ≥ 3` 的格子，模拟「先走该分支」，检查剩余连通性，即可自动标注。

难度旋钮因此变成**分叉数 `B`**（`deg ≥ 3` 的格子数）和**诱饵深度**，而不是 v1 的阻挡块数。

### 3.7 冰面 `ICE`

**规则**：`ICE` 是必需格。踩上后沿**进入方向**滑行，直到下一格是边界 / `VOID` / `BLOCK` 才停（停在撞墙前的最后一格）。滑行途中经过的所有格子都算「已走」，**不允许滑过已走格**（否则这条滑动非法）。

**为什么它天然契合「不能回头」**：滑动是单向的，滑过即走过，和自避约束同向。它把「逐格决策」压缩成「整段冲刺」——玩家要预判的不是一步，而是一整条直线扫过哪些格子。

**求解**：状态空间**不变**（仍是格子）。滑动结果由 `(ICE, 方向)` 唯一确定，生成时**预计算每块冰 4 个方向的滑行终点 + 扫过的格子集合**，BFS/回溯时查表。真正变复杂的是**生成**，不是求解。

**生成（关键约束）**：冰面只能放在哈密顿路径 `P` 的**直线段**上。如果 `P` 里有一段连续同方向的格子 `c0 → c1 → c2 → c3`，把 `c1`（或 `c0`）设为 `ICE`，玩家沿 `P` 的方向进入 `c1` 后滑到 `c3` 停下——正好覆盖这一段，`P` 仍是合法解。

**必须防的错误**：玩家从**错误方向**进入冰面，滑动会扫过 `P` 之外的格子或直接出盘。这正是冰面的难度来源——但生成时得保证「错误方向滑动」要么撞墙无害、要么成为诱饵，**不能出现「滑一下就无解且玩家无从预判」的死局**。验收时对每块冰的 4 个方向都做一次「滑动合法性 + 剩余连通性」检查。

**难度与代价的诚实评估**：
- 好玩：冰面是七个机制里唯一改变「移动粒度」的，视觉和手感的新鲜度最高。
- 代价：滑行 + 覆盖约束叠加后，可解性验证从「逐格」变成「逐段」，生成器复杂度明显上升；`ICE` 会让「唯一解」的构造更难（玩家可能用滑行抄近路）。
- 决策：**做**，排在机制接入的最后（阶段 3 末尾），且若门禁显示冰面关卡的生成成功率撑不住预算，允许降级为「世界七后半段才出现」。

**边界情况（要实现，不能留空）**：
1. 冰面撞冰面：**继续滑**（冰不是墙，是滑道）。连续多块冰 = 一条长滑道。
2. 滑行撞 `GATE`：门没开 → 停在门前；门开了 → **停在门后一格**（门是「墙」的语义，滑行到门即止，不穿门）。
3. 滑行扫过 `KEY` / `SHARD` / `PORTAL`：照常拾取 / 计时序 / 触发传送。传送门**打断滑行**——进 A 立即出现在 B，滑动终止。
4. 冰面在棋盘角落：进入方向若朝盘外，直接撞边界停下（无移动，等价于普通格）。

## 4. 生成算法

### 4.1 总流程（已实现，2026-11-02）

```
generateCoverLevel(idx, seed):
  wp = worldOf(idx)                            # 尺寸 / 切尾区间 / 死端目标 / 难度范围
  for attempt in 1..MAX_ATTEMPT(40):
    rng = mulberry32(levelSeed(seed, idx) + attempt * 7919)
    P  = randomHamiltonian(w, h, rng)          # §4.2：满矩形上构造，可解性 100%
    jCut = rng.int(cutRange)                   # 切尾格数
    iCut = rng.int(0, min(8, jCut) + 1)        # 切头格数（小）
    cells = P[iCut .. len-jCut]                # 棋盘 = 路径中段 = 参考解
    cells = symTransform(cells, t)             # 8 种旋转/镜像（保相邻保哈密顿性）
    # 拓扑筛选：死端 D ∈ 目标区间（起终点自由度）、turns ≤ maxTurns
    # 难度对齐：|diff − targetDiff(idx)| ≤ 8 → 接受；否则记录最优重试
  return best
```

关键：**v1 是「随机撒块 → 求解验证」，v2 是「构造路径 → 反推合法性」**。哈密顿路径是 NP 难，不能靠随机撒完再验证；**「有解」是构造的副产品，参考解就是构造出的路径本身**。

> 实施中发现「先挖洞再在 S 上搜路径」依然踩了 v1 的坑：随机挖洞的可解率只有 ~27%（22/30 个 9×9 散洞盘无解）。切尾法把可解性变成 100%，形状多样性由双端切（i×j 组合）+ 8 对称 + 段重建打乱承担。

### 4.2 满矩形哈密顿路径构造（已实现）

满矩形上的哈密顿路径**不需要搜索**——直接用构造 + 局部变换：

1. **基线**：蛇形（8 种：4 角 × 2 方向）或螺旋（2 种：正/反），随机选。
2. **段重建打乱**：随机选一段 [i..j]（长 3~16），固定两个端点，在段内做随机 DFS 重连。子问题 ≤ 18 格，秒解；候选顺序随机，路径形态（转弯数）快速发散。循环 w×h×10 次。

两个踩过的坑，记录在此：

- **不能用 2-opt 式「反转任意段」**：随机两点在网格上几何相邻的概率 ~(2/n)²，接受率几乎为 0，混合不动。
- **段重建的 DFS 候选必须是几何邻接**：`cur±1` 在行首/行尾会跨行；候选必须按坐标生成。
- **纯确定性 Warnsdorff 会让满矩形的解全部趋同成蛇形**，布局指纹大量重复；随机序是多样性的前提。

### 4.3 死端（起终点自由度）的构造

死端 `D` 由切尾形状自然产生：满矩形的角格（度 2）不会变死端，但切尾若把某边格的两个同排邻居都切掉，它就变成度 1 的死端。实测分布：小切尾 D=0 占 ~90%；大切尾（26~38 格）D=1 占 ~30%。

**D=2 放弃**：两个死端要求「n 奇时同色、n 偶时异色」等一串精细约束，且对 v2 玩法「起终点固定」反而退回 v1 的体感。**D 从 0 → 1 已经实现了「完全自由 → 一个端点钉死」的收紧**。世界参数全部为 D ∈ [0,0] 或 [0,1]。

### 4.4 机制注入（下一轮）

全部遵循一条铁律：**机制只能加在已构造好的路径 `P` 上，且加完 `P` 仍然合法**。这样「有解」永远不用验证。

- `ONEWAY`：箭头 = `P` 在该处的离开方向。
- `SHARD`：在 `P` 上选 3 个位置，按 `P` 的先后顺序编号 1/2/3（§3.3）。
- `KEY/GATE`：门在位置 `i`，钥匙在 `i` 之前。
- `PORTAL`：把 `(A,B)` 当作 `P` 上允许的一条边。
- `ICE`：整段滑行纳入 `P`（§3.7）。

### 4.5 退化策略

若某关连续 `MAX_ATTEMPT` 次失败，按序降级：减少机制数量 → 简化轮廓 → 缩小尺寸 → 蛇形保底。保证流水线不崩（v1 已有 `fallbackLevel`，v2 保留同机制）。

## 5. 求解、提示与校验

### 5.1 参考解必须入库

cover 模式下「给提示」意味着从当前线头出发找一条覆盖剩余所有格的路径——这是一个 NP 难子问题，运行时求解不可接受。

**生成时把参考解存进关卡表**。编码：

```
起点索引（1~2 字节） + 每步方向 2 bit
```

以 121 格（11×11）为例：120 步 × 2 bit = **30 字节**；1000 关 ≈ 30 KB。压缩后可忽略。

v1 已经有 `SolutionTableFile`（私密解法表），v2 把它从「调试用」提升为**运行时依赖**。

这一条带来三个收益：

1. **提示是 O(1) 查表**，且保证一定正确（不会给出走不通的提示）。
2. **服务端校验不需要跑求解器**（见 §5.3）。
3. **关卡质量可离线全量复核**。

### 5.2 提示

`findHint` 改为：从参考解中定位玩家当前路径的最后一次匹配，返回后续 1~2 步。若玩家已偏离参考解（走岔了），提示「这一步之后无解」，并高亮第一个分歧点。

> 玩家走岔后，参考解不一定能接回去——此时更实用的做法是提示「撤销到某个分叉点」，而不是硬给一条新路径。

### 5.3 服务端成绩校验

v1 的 `isPathLegal` 要求 `path[0] === START`、`path[last] === END`。v2 改为：

1. 路径不自交、每步四邻接、不进入 `VOID`/`BLOCK`、尊重 `ONEWAY`/`GATE`/`PORTAL`/`ICE` 规则；
2. 覆盖**全部必需格**（用 bitmask，O(len)）；
3. `steps === requiredCount − 1`（星屑是必需格，不额外加步数；防篡改）。

不需要搜索，纯线性扫描。

### 5.4 ⚠️ 星级规则必须重写

v1 的 `StarOf(steps, shortest)`：

```go
ratio := float64(steps) / float64(shortest)
case ratio <= 1.15: return 3
```

在 cover 模式下它**彻底失效**：`steps` 恒等于 `必需格数 − 1`（星屑也是必需格，绕路已不存在），`ratio ≡ 1.0` 永远 3 星——星级变成摆设。

同时 `shortest` 在 cover 模式下恒等于 `必需格数 − 1`，是个常量字段，不再携带信息。

新规则见 §7。它同时影响 `server/internal/games/line/stars.go` 与 `src/ui/hud.ts`（两处阈值必须一致，v1 已有这个约定）。

## 6. 难度体系

### 6.1 六个维度

难度不再由单一 `diff` 驱动，而是六维**逐维解锁**：

| 维度 | 由松到紧 |
|---|---|
| 棋盘尺寸 | 5×5 → 11×11（随难度阶梯，上限由单局时长反推） |
| 轮廓复杂度 | 满矩形 → 挖角 → 挖洞 → 岛屿 → 不规则 → 复合 |
| **死端数 `D`** | 0（起终点自由）→ 1 → 2（起终点固定） |
| **分叉数 `B`** | 少（走廊化、近乎唯一解）→ 多（选择爆炸） |
| 机制 | 无 → 单向门 → 星屑 → 钥匙门 → 传送门 → 隘口诱饵 → 冰面 |
| 诱饵深度 | 无 → 一眼看穿 → 走 3~5 步才发现是死路 |

v1 的 `blocks` 维度**删除**（cover 模式下 `VOID`/`BLOCK` 已并入轮廓复杂度，不再单独计分）——顺带消除了 §0 里那个方向搞反的权重。

### 6.2 难度公式

#### v3 当前公式（已落地，`src/core/cover/v3/metrics.ts`）

```
diff = 100 * sizeBaseline(required) * (0.60 + 0.55 * structureTerm)

sizeBaseline = ((required − 10) / 111)^0.8 * 1.15
structureTerm = 0.35 * uniqTerm      # 解数越少越难（核心信号）
              + 0.30 * turnTerm      # 参考解转弯数 / 50
              + 0.15 * topologyTerm  # 最长强制走廊占比 / 0.35
              + 0.12 * mechTerm      # 世界配置
              + 0.08 * baitTerm      # 最深诱饵深度 / 6
```

**两段式结构的理由**：

- **规模是跨世界的主难度轴**。4×4 和 11×11 的难度差远大于拓扑差异。
  没有规模项，早期世界的难度分会全部顶到 40+，根本压不进目标区间。
- **结构是同世界内的区分轴**。同一世界盘面尺寸几乎不变，
  所以真正把这一关和那一关分开的是 `structureTerm` —— 编排器就是按它排序的。

指数 0.8 塑造曲线形状：没有它，12 格的小盘会被评得过高（「一眼看完」）、
大盘评得过低。

**v2 公式（历史参考）**：

```
diff = 100 * (
    0.12 * sizeTerm       # |必需格| 在 20..121 上的归一
  + 0.22 * turnTerm       # 参考解转弯数 / 36
  + 0.16 * deadEndTerm    # D=0 → 0.0 / D=1 → 0.5
  + 0.20 * mechTerm       # 机制种类加权 + 数量
  + 0.14 * shapeTerm      # 切掉格占比 / 0.45
  + 0.16 * baitTerm       # 最深诱饵深度 / 6
)
```

v2 的实测校准（2026-11-02，无机制版）偏差 4.80。两点修正记录在此：

- 「分叉数（静态度 ≥3）」**不适合做难度**：满矩形里这种格子占一大半，但蛇形路径只有 ~10 次转弯，玩家毫无压力。**转弯数是决策负担的果，直接采它**。
- `blocks`（障碍数）**删除** —— cover 模式下障碍已是轮廓复杂度的一部分，且方向是反的（障碍越多玩家反而越好找路）。

> **v2 → v3 的量纲变化**：两套公式都是 0–100，但内部结构完全不同。
> 所以 **v2 的难度目标值不能直接套到 v3**（实测偏差 8.7，门禁要求 ≤ 8）。
> v3 的难度目标一律用**实测分位带**（见 §6.3 表格「v3 难度目标」列），
> 由 `pool.ts` 的 `calibrateTargets` 按池子实测分布**二次校准**。

`targetDiff` 的目标曲线保持「段内缓升」的形状，并**跨世界单调**：
每个世界的目标下限被抬到上一个世界的目标上限（`generate.ts` 的 `targetDiff`），
保证世界边界处目标难度**衔接而非回落**。

## 7. 星级

### 7.1 为什么必须重定义

cover 模式下 `steps ≡ 必需格数 − 1`，`StarOf` 恒等于 3 星——星级失效。星屑现在是必经（不是绕路收集），不能再当星级维度。唯一剩下的、能反映「技术好坏」的信号是**重来次数**。

### 7.2 新规则：一气呵成

| 星 | 条件 |
|---|---|
| 3 | 通关，且**零重来** |
| 2 | 通关，重来 1~2 次 |
| 1 | 通关 |

- 「重来」定义：松手时未通关，`path` 被清空 → `undos += 1`。拖动中的回退（pop）不计。
- 高手与新手的分水岭就是「规划一次成 vs 反复试」，这是 cover 模式最诚实的技巧信号。
- 阈值 [PLACEHOLDER]：2 星 = 1~2 次、1 星 = ≥3 次，需 playtest 验证。若后期关卡对休闲玩家太苛刻，可放宽到「3 星 ≤ 1 次重来」。

### 7.3 数据结构与后端改动

| 位置 | 改动 |
|---|---|
| 关卡表 | `shards` 从 grid 里的 `SHARD` 格子统计，无需单独字段 |
| 上报 | 新增 `undos`（重来次数） |
| DB | `ALTER TABLE level_records ADD COLUMN undos INT NOT NULL DEFAULT 0;` |
| `stars.go` | `StarOf(undos int) int`，替换现版本（单参数，比 v1 还简单） |
| `hud.ts` | `starOf` 同步，两处阈值必须一致 |
| `shortest` | 保留字段但语义退化为「必需格数 − 1」，仅用于展示与兼容 |

## 8. 数据结构与迁移

### 8.1 `CellType` 重新编号

`codec.ts` 现在每格 1 字节：`bit7` oneway 标志 / `bit6..4` dir / `bit3..1` type（3 bit，只够 8 种）。新类型需要 9 种，且 `dir` 只要 2 bit：

```
byte = (type << 4) | (dir << 2) | group
  type  4 bit  (0..15)
  dir   2 bit  (0..3)
  group 2 bit  (0..3)   传送门配对号 / 钥匙-门编号
```

| 值 | 类型 | 说明 |
|---|---|---|
| 0 | `VOID` | 空洞 |
| 1 | `BRICK` | 必需格 |
| 2 | `BLOCK` | 石障 |
| 3 | `ONEWAY` | 单向门（`dir` = 允许的离开方向） |
| 4 | `SHARD` | 星屑（编号必经，`group` = 编号 1..3） |
| 5 | `KEY` | 钥匙（`group` = 钥匙号） |
| 6 | `GATE` | 门（`group` = 钥匙号） |
| 7 | `PORTAL` | 传送门（`group` = 配对号） |
| 8 | `ICE` | 冰面（必需格的变体） |

`START` / `END` **删除**。

### 8.2 `Level` 字段

| 字段 | 变化 |
|---|---|
| `w` / `h` | 保留 |
| `grid` | 新编码 |
| `shortest` | 语义退化为 `必需格数 − 1` |
| `turns` | 保留（参考解的转弯数） |
| `blocks` / `oneways` | 保留（统计用） |
| `diff` | 新公式 |
| **`required`** | 新增，必需格数（= shortest + 1，冗余但校验方便）；星屑从 `grid` 统计，不单设字段 |
| `unlockSkin` | 保留（已收敛为 premium 三关） |
| **`solution`** | 参考解方向序列（从私密解法表提升为运行时依赖） |

### 8.3 版本与换表

关卡表有 version hash（`computeVersion` 取内容 SHA-256 前 12 位），新表 hash 必然不同 → **可平滑换表**：服务端同时挂新旧两表，按客户端版本分发。

旧客户端遇到新表会读不懂（新 `CellType`），所以必须是**强制更新**或**按版本分流**。建议：`levelTable.version` 里带 schema 版本号（如 `v2-<hash>`），服务端据此决定给哪张表。

## 10. 验收门禁

生成 1000 关后必须全过：

| # | 指标 | 门槛 |
|---|---|---|
| 1 | 每关必需格连通 | 100% |
| 2 | `\|B − W\| ≤ 1`（第一定律） | 100% |
| 3 | 参考解合法且覆盖全部必需格（星屑也是必需格） | 100% |
| 4 | 参考解方向序列能无损回放出格子序列 | 100% |
| 5 | 星屑在参考解上按编号顺序出现 | 100%（由构造保证） |
| 6 | 死端数 `D ≤ 2` | 100% |
| 7 | 解数上界：世界一、二 ≥ 4；世界五~七 ≤ 4 占比 ≥ 60% | 见下 |
| 8 | 无重复布局（同尺寸 + 同机制配置下 grid 不重复） | 100% |
| 9 | 世界内难度单调不降（滑动窗口均值） | 100% |
| 10 | 1000 关生成总耗时 | < 120s |
| 11 | 单关最坏生成耗时 | < 2s |
| 12 | 每块冰 4 个方向的滑动均合法（扫过格不越界、剩余必需格仍连通） | 100% |
| 13 | **同 seed 重复生产产出完全相同的关卡**（后台任务可复现） | 100% |

第 7 条的「解数上界」用**有界枚举**（DFS 找到 9 条即停）估计。精确计数哈密顿路径是 #P 难，我们不追求精确，只区分「≤2 / 3~8 / >8」三档。

### 10.1 v3 已自动化的门禁

`tools/cover-gen-v3.ts` 在写表前跑完下列检查，**任一失败即 exit 1**：

| # | 门禁项 | 判定 |
|---|---|---|
| 1 | 解回放校验全部通过 | `verifyLevel` 逐关回放 |
| 2 | 棋盘全表去重 | 指纹集合大小 == 关数 |
| 3 | 平均难度偏差 ≤ 8 | 对照**校准后**的目标（§6.2） |
| 4 | 规模随世界单调不降 | 各世界 `required` 最大值不降 |
| 5 | 世界内难度单调不降 | 相邻关 `diff` 回落 ≤ 8 分 |
| 6 | 关卡含障碍 | `required < w*h` 占比 ≥ 80% |
| 7 | 机制覆盖 | 机制世界内 100% |
| 8 | 客户端表不含解 | 工具层强制（两张表分离） |
| 9 | 1000 关生成总耗时 < 120s | 墙钟 |
| 10 | 单关最坏生成耗时 < 2s | 每关 `genMs` |

**第 13 条（确定性）** 由 `test/cover-v3.test.ts` 的确定性用例覆盖，
生产时无法自检（要跑两遍）。它是**墙钟预算的替代品** ——
所有生成预算必须用**步数**而非毫秒，否则同 seed 在不同机器上产出不同盘面。

> v1 的教训：规格 02 §4.4 里「相邻档 diff 增量 ≥ 3」「步数增量 ≥ 1」两条指标与 0–100 / 8–21 的量纲直接矛盾，属规格内部不自洽。v2 的门禁全部改为**可判定的布尔条件**，不再用不可达的增量指标。

## 11.5 v3 生成器（已落地）

### 11.5.1 架构

```
tools/cover-gen-v3.ts          ← 生产入口（后台任务调用）
  └─ core/cover/v3/pool.ts      ← 两段式：建池 → 全局编排
       ├─ generate.ts           ← 单关候选（世界参数 + 难度目标）
       │    ├─ design.ts        ← 正向形状设计（11 个家族）
       │    ├─ carve.ts         ← 挖洞 & 验证（可解性由构造保证）
       │    ├─ solver.ts        ← 哈密顿路径搜索（Warnsdorff + 三剪枝）
       │    ├─ solcount.ts      ← 解数估计（采样法）
       │    ├─ metrics.ts       ← 度量与难度评分
       │    └─ rules.ts         ← 规则集与回放
       └─ codec.ts             ← 位布局编码

产出两张表：
  data/levels-v3.json         含参考解 → 只放服务端
  data/levels-v3-client.json  不含解 → 客户端用
```

**两段式的理由**：生成是「随机搜索 + 验证」，产出分布不均；排序是确定性组合优化。
分开后，编排策略可以反复调整而不重跑生成（实测生成 1000 关 ~90s，
编排只占几秒）。

### 11.5.2 关键设计决策

| 决策 | 做法 | 理由 |
|---|---|---|
| **可解性** | 设计阶段就验证（`requireSolvable`），解**带出来**给 carve 复用 | 同一张盘只解一次；省掉「从满矩形挖」的回退路径（那条要 300~700ms） |
| **端点固定** | 先自由求解得到路径 `P`，再**钉住 `P` 的首尾** | 可解性由构造保证；端点奇偶自动满足；零额外搜索 |
| **洞单位** | 只用**奇偶中性**单位（骨牌 2 格 / 2×2 块 4 格） | 每单位 1 黑 1 白 → `\|B−W\| ≤ 1` 恒成立（§2.1 第一定律） |
| **小盘重复** | 加 `domino` 家族 + **禁止「零洞满盘」** | 4×4/5×5 的形状空间太小，满矩形会导致全表同一指纹 |
| **形状族回退** | 随机顺序逐个试家族，第一个成功就用 | 某些家族在小盘上**必然**失败（挖不出 2 格），不该耗死重试 |
| **难度单调** | **全局**编排（跨世界），每槽只挑 `diff ≥ 上一关` 的候选 | 逐世界独立编排时，世界边界会掉 19 分 |
| **去重优先级** | **唯一性 > 单调性** | 重复棋盘玩家看得见；2 分难度回落玩家察觉不到 |
| **难度带宽** | 候选偏离目标 > 6 分就不考虑 | 形状多样性奖励（最多 24 分）会带偏难度曲线 |
| **目标校准** | 按**池子实测分位带**（p10~p90）二次校准 | 静态先验值与实测系统性偏高 3~14 分，够不到 |
| **确定性** | 所有预算用**步数**，不用墙钟 | 墙钟依赖机器速度 → 同 seed 在不同机器产出不同盘面 |

## 12. 开放问题

1. **星屑方案**：已定「顺序必经」（§3.3），绕道插入法作废。
2. **冰面**：已定「做」（§3.7）。保留的降级通道：若门禁显示生成成功率撑不住预算，降级为「世界七后半段才出现」。
3. **参考解入库**：约 30 KB 的体积换来 O(1) 提示与免搜索校验，判断是划算的。若关卡表体积成为瓶颈（微信端首包），可改为「参考解单独一张表，按需拉取」。
4. **难度公式权重**：v3 已按实测校准（§6.2 / §6.3 / §11.5.3）。若后续调整公式权重，必须**重跑全量并回填 `WORLDS[].diffRange`** —— 它是校准后的实测值，不是手写的先验值。
5. **`shortest` 字段**：cover 模式下它是常量，保留只为兼容与展示。若后端改造彻底，可以删掉。
6. **重跑时机**：`tools/level-gen.ts` 的 `skinForLevel` 已收敛为 premium 三关（200/500/900），但**要重跑才生效**；在此之前旧表的 3/8/15…关仍带 `unlockSkin`，服务端照发。阶段 6 一并解决。
7. **v3 门禁 #7 / #12 尚未自动化**：解数上界分档（世界一、二 ≥ 4；世界五~七 ≤ 4 占比 ≥ 60%）与冰面 4 方向滑动合法性，目前靠构造保证但未写成门禁项。补齐时注意「解数」是**采样估计**，判定要用分档而非精确计数。
