# 关卡生成算法

> 生成器 / 求解器唯一真相源在 `games/line/src/core/`，Go 侧**不实现**求解器。

## 1. 目标

- 每关必须可解（求解器保证，生成后二次校验）
- 难度随关号**单调递增**（`targetDiff` 单调不减，见 §4）
- 同种子可复现（分享挑战 + 服务端成绩校验的前提）

## 2. 流程

```
generateLevel(idx, globalSeed)
  └─ curveFor(idx)        → 分段参数（尺寸/阻挡/单向/转弯/开放比）
  └─ levelSeed(seed, idx) → 每关独立种子（FNV-1a 派生）
  └─ mulberry32(seed)     → 确定性 RNG（禁 Math.random）
  └─ 尝试 ≤ 40 次：
       attemptGenerate
         ├─ 摆 START（左/上边）/ END（右/下边，曼哈顿距离 ≥ minPathLen）
         ├─ growPath     → 造正解路径（绕行满足 minPathLen + minTurns）
         ├─ 放 ONEWAY    → 路径中段，箭头 = 离开方向
         ├─ 放 BLOCK     → 逐个放置 + 可达性验证（放完仍可达才保留）
         └─ 返回关卡
       solve(grid)       → 校验可解 + 步数达标
       narrowBranches    → 分叉太多时收窄（尽力而为，不强求唯一解）
       computeDiff       → 计算难度分
       |diff - target| ≤ 6 → 直接返回
       adjust            → 偏差 6~12 时微调（加/减阻挡）
  └─ fallbackLevel       → 极端兜底（一条直线，保证可解）
```

## 3. 求解器设计

- **状态 = (格子, 进入方向)**：单向块（ONEWAY）使进入方向成为状态的一部分，`key = idx * 4 + dir`
- **BFS + 多前驱 + DFS 枚举**：记录每个状态的所有最短前驱，从终点 DFS 回溯枚举最多 `maxPaths=8` 条最短路径，用于唯一性判定
- **单一实现，三处复用**：生成校验 / 客户端提示（`findHint`）/ 服务端成绩校验（`isPathLegal`）

## 4. 难度公式

见 `core/curve.ts`：

```
diff = 100 * (
    0.30 * clamp01(blocks / (w*h*0.45)) +
    0.15 * clamp01(oneways / (w*h*0.25)) +
    0.25 * clamp01(turns / 8) +
    0.20 * clamp01((1 - openRatio) / 0.55) +
    0.10 * clamp01(1 - uniqueness)
)
```

- `uniqueness = pathCount <= 1 ? 1 : clamp01(1 - log2(pathCount)/6)`
- 注意：`1 - uniqueness` 使**唯一解不额外加分、多解加分**，与 GDD「越唯一越好」措辞表面相悖；「唯一解占比」实为独立质量门禁（§4.4），不并入难度分。

### targetDiff（目标难度曲线）

- 1~10 关：线性 5 → 15
- 11~1000 关：**平方根曲线** 15 → 85（前快后慢，贴合 `computeDiff` 实际输出上限 ~84）
- 每 10 关 +8 小高峰；每 100 关 +4 大关

> **规格冲突记录**：规格 02 §4.3 写「分段线性 15→92」，但实测 `computeDiff` 输出上限约 84，线性 15→92 会造成后期系统性负偏差（331 处异常）。故按实测改为平方根 15→85。详见 T07 遗留问题。

## 7. 遗留问题

- 「相邻档平均 diff 增量 ∈ [3,12]」「相邻档平均步数增量 ∈ [1,5]」两条判定标准**数学上不可满足**：diff 全程仅升 ~70 分（99 档 → 均增 ~0.7/档），步数全程仅升 ~11 步（均增 ~0.1/档），与「每档 +3~12」矛盾。属规格 02 §4.4 与 §4.3 的**内部不自洽**，详见 T07 任务书遗留问题小节。
