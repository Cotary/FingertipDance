# 33 · 地图重设计：从「表格」到「山路」

> 触发：玩家反馈「画面太死板」「从第一关拖到最后一关要一直划，希望右侧优化」。
> 改的是 `games/line/src/ui/mapview.ts`（整页重写）+ `main.ts` 的输入层。

---

## 一、上一版到底死板在哪

上一版是**蛇形网格**：4 列 × 250 行，同一行的节点 y 完全相等，路径全是水平直线
加 90° 折返，行距恒定 248。数据上很整齐，看起来却像一张表格，原因有三条，缺一不可：

| # | 现象 | 为什么读起来「死」 |
|---|---|---|
| 1 | 整屏没有一个斜的元素 | 视线找不到方向，只能从上读到下，像在看清单 |
| 2 | 90% 面积是「11 个同款深蓝圆片」 | 未解锁的关卡是**砖**（浮在板上的深色块），读作「十一堵墙」；主角反而被淹掉 |
| 3 | 行间 90px 纯色空带，一屏三条 | 底色再好看，空着就是空的 |

一句话：**整齐 ≠ 有秩序**。等距 + 直角 + 同款，是「表格」的三个特征。

## 二、新几何：一条蜿蜒的山道

> ⚠️ **本节的 x 公式已经过时**。这里记的是 2026-11-01 的第一版（纯正弦），
> 2026-11-17 被 `39-地图路线右上化.md` 换成了「基线 + 非对称三角波折返」。
> **改地图路线请看 39**，本节只作历史留档。

```
x = CENTER_X + sin(i·0.95)·198 + sin(i·2.41 + 0.7)·20
y = FIRST_NODE_Y + i·116 + sin(i·1.73)·10 + 门数·96
```

| 参数 | 值 | 理由 |
|---|---|---|
| `WAVE_AMP` / `WAVE_K` | 198 / 0.95 | 一屏 8 关里约有 **1.5 个弯**。周期再长会退化成一条直斜线，再短就成了弹簧 |
| 副波 | 20px，2.41 rad/关 | 主波两个拐点之间本来是**笔直的斜线**（一眼就是正弦图像）；副波频率和主波不整除，同一条坡上也有起伏 |
| `NODE_STEP` | 116 | 8 关填一屏。旧版 15 关/屏，看的是清单；新版看的是细节 |
| y 抖动 | ±10 | 行距恒定 = 每一关「一样重」。96 的下界仍然远大于两个节点的半径和 |
| 路径 | Catmull-Rom → 三次贝塞尔，张力 1/7 | 折返变成弯，直角消失。张力比标准 1/6 再收一点，急弯不过冲 |

两条硬约束（`test/mapview.test.ts` 锁住）：

1. 节点必须落在 `[40, 656]`：右边 656 之后是导轨的手势区。
2. 世界门必须夹在两关**中间**，不能和任何节点重叠。

## 三、未解锁 = 坑，不是砖

凹坑用的是棋盘上「没走过的格子」那套语言：**这里将来会有东西**，而不是**这里堵着**。

画法三件套：`#CFB191` 的圆底 → 径向渐变内阴影（渐变中心**压在下方**，上沿自然更暗，
这是坑被光照出来的方式）→ 下沿一道亮唇（少了它，坑会变成一块脏斑）。

视觉重量只有深色圆片的十分之一，山道因此能一直延伸出去 —— 这是「一屏十一个深蓝点」的正解。

## 四、七个世界有身份

| 世界 | 主色 | 地形 |
|---|---|---|
| 苗圃 | land 嫩绿 | 破土的两片叶 |
| 石溪 | blue 石蓝 | 三颗被水磨圆的石头 |
| 苔原 | mint 深绿 | 一撮被风吹斜的草 |
| 熔炉 | terracotta 陶红 | 几点没烧完的火星 |
| 深井 | boardDark 沉蓝 | 石缝里的晶簇 |
| 云阶 | cream 米白 | 三层软云 |
| 星穹 | mustard 金 | 四芒星 |

- 地形点缀每关 1~2 个、低透明度，专门填「行间空带」，但绝不抢节点。
- 世界门用同一套色：罗马数字徽章 + 世界名 + 区间 + 底部内嵌进度条。
- 世界地层（一条 5% 透明度的色带）让「换区」有体感，而不是只有一行字。

**已走的路**是陶土管（暗面下移 5px 露厚度 + 上缘提亮），按世界主色混 16% —— 保留陶土
一半，就是「同一条土路，颜色随地层变」。**未走的路**是一串石子（线宽 8 + 圆头 + `[1,15]`
虚线 = 点），读作「路还没铺到」。

## 五、右侧导轨：一次性跳几十关

1000 关 = **11.5 万像素**。只靠甩指要划四十多屏 —— 这是「拖不动」的根因，
不是手指甩得不够狠。

| 部件 | 作用 |
|---|---|
| 轨道（7px，比例映射） | 全长 = 全部关卡，拖 1px ≈ 1.14 关 |
| 滑块（15px / 拖动时 22px） | 拖它移动；宽度跟着手指变，别被自己的影子挡住 |
| 世界色条（横穿轨道 9×3） | 轨道在哪一段换了世界。**替代了原来的罗马数字**：前四个世界只占 13% 的轨道，四个数字会叠成「II III IV」一坨黑 |
| 金色小圆点 | 当前关在导轨上的位置，点它 = 缓动跳回自己 |
| 拖动浮标 | 「第 N 关 · 世界 X-Y」，读数比滑块位置重要得多 |

判定顺序：**先滑块，再当前点，最后色条**。反过来会出现「想拖滑块，手指偏两像素被弹到另一个世界」。

热区左边界 656 是算出来的：节点最右到 617，再往左就开始吃节点边缘的点击；
而 686 在 375 宽的手机上只剩 24px，拇指按不准。656 给出约 47 CSS px。

## 六、甩指 + 「回到当前」

- **惯性**：`onMove` 里做指数平滑的速度估计（0.6/0.4），抬手时交给 `fling`（px/ms），
  每帧 `v *= e^(-dt/320)`。低于 0.18 不算甩 —— 轻飘飘一次点击不该让地图滑走。
- **缓动**：点世界色条 / 「回到当前」时设 `scrollTarget`，走 `1-e^(-dt/72)`。
  直接赋值会让画面瞬移，玩家丢失「我走了多远」的空间感。
- **回到当前**：只在当前关滚出屏幕时出现的浮标（常态下不该多一个按钮）。

## 七、标题跟的是「视野」不是「进度」

有导轨之后一拖就是 50 关。如果标题永远写「第 38 关 / 苔原」，玩家看着 85 关却被告知
自己在苔原 —— 标题就成了谎话。

规则：**当前关还在视野里 → 写当前关**（进地图的默认视角就是这个）；
**已经滚远了 → 写视野中心那一关**。「我在哪一关」交给吸底的「继续第 N 关」和导轨上的金点。

## 八、踩的坑

| 坑 | 表现 | 结论 |
|---|---|---|
| `traceTrail` 忘了减 `scrollY` | 路径**完全看不见**，但节点正常 | 世界坐标 → 屏幕坐标必须在建路径时算，画完再 translate 无效。排查花了半小时：颜色从品红试到纯绿都不变，说明根本不是颜色问题 |
| 世界主色混 42% | 路变成米棕色，和背景只差一档亮度 | 混色 16% 是上限。陶土是对比度的锚 |
| 罗马数字写在导轨上 | II III IV 叠成一坨黑 | 密集区域只画色条不画字；位置真≠读得出 |
| 标题压在节点上 | 世界名像「字上沾了个圆点」 | 遮罩实心段拉到 192（盖过标题 174） |
| 导轨热区 686 | 375 屏上只剩 24px | 按「节点最右 + 半径」反算，656 |
| 浮标右缘 662 | 压到导轨上 | 646 |

## 九、验收

- `test/mapview.test.ts` 28 条：节点不出界 / 相邻不重叠 / y 严格单调（二分依赖）/
  蜿蜒但不出高频 / 世界划分与 cover 生成器一致 / 门夹在两关中间 / 一屏 8~14 关 /
  甩指会停且不越界 / 缓动会到点 / 滑块始终在轨道内 / 拖到底 = 最后一关 /
  比例线性 / 滑块优先于色条 / 当前点落在滑块里
- 332 用例全过，`tsc` 干净，build 446.88KB / gzip 97.97KB
- 实拍（画廊）：`?p=map&lv=38|64|150|460|705`（`&off=` 模拟拖远，`&scrub=1` 停在拖导轨那一帧）
- 实拍（真 App 的输入）：`tools/app-drive.html` —— iframe 装载 `/` 后往 canvas 派发真的
  PointerEvent，走的是和手指同一条链路。`?drag=1` 验「一拖跳 644 关」，`?fling=1` 验
  「划 300px 靠惯性滑出 1400px」
