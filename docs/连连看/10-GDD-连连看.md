# 10 — GDD（连连看 · 路径连线）

> 正式版游戏设计文档。用于：内部对齐、软著申请材料、提审简介。
> 玩法规格的**判定细节**以 `01-GDD.md` 为准，本文件是面向非技术人员的完整描述。

---

## 1. 游戏概述

| 项 | 内容 |
|---|---|
| 名称 | 连连看 · 路径连线 |
| 类型 | 休闲益智 / 路径连线 |
| 平台 | 微信小游戏（主），Web（开发预览） |
| 引擎 | 原生 Canvas 2D + TypeScript（无游戏引擎） |
| 视角 | 竖屏单手 |
| 单局时长 | 30–90 秒 |
| 目标用户 | 碎片时间玩家，全年龄 |

**一句话玩法**：从绿色起点按住手指，沿上下左右一格一格拖到红色终点，路过的方块会被点亮。

---

## 2. 核心循环

```
启动 → 大厅主页（当前关卡 / 皮肤数 / 继续游戏）
   → 底部导航切换：主页 · 地图 · 皮肤 · 排行 · 我的
      → 从主页「开始」或地图点节点进入关卡
         → 拖动连线 → 抵达终点 → 通关演出 + 星级结算
            → 回到大厅（进度条前进 + 皮肤解锁 + 分享入口亮起）
   → 下一关 → 难度递增 → 1000 关
```

**长期目标**：通关 1000 关，收集全部皮肤，登上全区排行榜第一。

> 大厅外壳（5 个页面 + 底部导航 + 双主题）见 `21-大厅与导航规格.md`，
> 是对「启动直接进关卡」裸循环的补齐，不改变任何玩法规则。

## 3. 玩法规则

### 3.1 棋盘
- 矩形网格，尺寸随关号从 6×6 递增到 11×11
- 格子类型：**起点**（绿圆）、**终点**（红圆）、**砖块**（可通行，点亮）、**阻挡块**（不可通行，深色带叉）、**单向块**（只能按箭头方向进入，带箭头）

### 3.2 连线
- 手指按在起点上开始
- 只能移动到**上下左右相邻**的一格
- 拖到非相邻格 = **断线**：线头回退一格，已点亮的砖块保持点亮，屏幕抖动 + 提示音。**不扣分、不失败**
- 走过的砖块可以再次经过，不会熄灭

### 3.3 单向块
- 只能沿箭头方向**进入**；离开方向不受限制
- 视觉上箭头指向 = 流向

### 3.4 胜负
- **抵达终点 = 通关**
- 松手时未到终点 → 这次连线作废，重新开始（**没有"失败"这个状态**）
- 通关后：终点辉光 + 路径波次点亮 + 音效 + 振动

### 3.5 星级
| 星级 | 条件（步数 ÷ 理论最短步数） |
|---|---|
| ★★★ | ≤ 1.15 |
| ★★ | ≤ 1.5 |
| ★ | 其他 |

## 4. 系统设计

### 4.1 关卡系统
- **1000 关**，**所有人看到完全相同**（服务端权威下发，保证公平）
- 关卡由种子化生成器离线批量产出，每一关都经过求解器验证**保证可解**
- 关卡表带版本号，改表后全端自动对齐
- 难度曲线分 7 段递增，每 10 关一个"卡点关"，每 100 关一个"大关"

### 4.2 皮肤系统（16 种）
- 皮肤 = 砖块外观，**全部程序化生成**（Canvas 实时绘制，零图片资源）
- 纹理：纯色 / 木纹 / 大理石 / 金属拉丝 / 冰晶 / 霓虹 / 黄金 / 星尘 / 星河
- 解锁方式：
  - **默认**：原木、薄荷
  - **通关解锁**：石墨、青岩、藕粉、琥珀、大理石、金属拉丝、冰晶、霓虹
  - **里程碑**：黄金（200 关）、星尘（500 关）、星河（900 关）
  - **看广告**：玫瑰、深海、余烬

### 4.3 进度与反馈
- HUD 常驻显示「当前关卡 / 皮肤收集数」
- 底部进度条实时填充
- 通关瞬间：皮肤解锁卡片弹入 + 进度条填充动画 + 分享按钮高亮

### 4.4 排行榜
- **总榜**：按最高关卡数排序，同关卡比总用时（服务端 Redis 实现）
- **好友榜**：微信开放数据域（免后端、即时、拿得到好友关系）
- **好友进度面板**：好友数 / 好友平均进度 / 好友最高进度 / 我的名次

### 4.5 分享挑战
- 通关后可分享「我卡在第 N 关，你能连过去吗？」
- 好友点开直接进入同一关（关卡统一，无需额外数据）
- 成绩提交服务端比对，赢的双方都有正反馈
- 自动生成分享海报（程序化渲染 750×1334）

### 4.6 提示与跳过
| 功能 | 规则 | 广告 |
|---|---|---|
| 提示 | 高亮接下来 1–3 步的正确格子 | 每关首次需看广告，之后免费 |
| 跳过 | 直接判定通关 | 需看广告，每关每天限 1 次 |

### 4.7 大厅与导航（App 外壳）
底部固定 5 个页签，任何大厅页面都可一键互跳；进入关卡后导航栏隐藏，交给游戏内 HUD。

| 页面 | 核心内容 | 主要交互 |
|---|---|---|
| **主页** | 玩家条（头像/昵称/等级/皮肤计数）、3D 星球 + 卫星关卡节点、吉祥物气泡、总进度条、开始按钮 | 点「开始」进当前关；点卫星节点直接跳该关 |
| **地图** | 1000 关纵向节点路线，每 10 关一个红旗里程碑，节点显示星级 | 拖动滚动（虚拟滚动只渲染可视区）；点击节点进关，未解锁弹提示 |
| **皮肤** | 16 套皮肤网格 + 解锁条件 + 当前装备标记 | 点击装备/查看解锁方式 |
| **排行** | 总榜 + 好友榜双 Tab，前三名金银铜徽章，底部吸底「我的名次」 | 切 Tab、翻页 |
| **我的** | 蓝卡头图、2×2 统计（最高关/总步数/总用时/看广告次数）、皮肤收藏墙、4 个功能行（分享/音效/振动/清缓存） | 开关类即时生效 |

**双主题**：大厅为亮色卡通（背景 `#EEF3FF`），游戏内为深色（背景 `#141824`），
两套色板集中在 `ui/theme.ts`，禁止页面内写死颜色。

**星级**：结算页显示 ★1~3，依据步数 ÷ 理论最短步数；客户端 `ui/hud.ts` 的 `starOf()`
与服务端 `stars.go` 的 `StarOf()` 是同一组阈值的两份实现，由两端单测互相锁死。

## 5. 技术方案

### 5.1 架构
```
客户端 (TypeScript + Canvas)  ←→  Go 后端 (PostgreSQL + Redis)
        │                              │
   core/ 纯逻辑层              关卡表(权威) / 进度校验 / 排行榜 / 好友
   render/ Canvas 绘制
   platform/ 平台适配
```

### 5.2 关卡生成（核心技术点）
```
1. 用带朝向的随机游走造一条"正解路径"，强制达到指定转弯数
2. 沿路径放置单向块（箭头方向 = 该处的离开方向，保证正解不被挡）
3. 路径外撒阻挡块（不围死起点，满足开放面积比下限）
4. 求解器体检：
   无解        → 重新生成
   步数太短    → 重新生成
   等价解太多  → 在分叉点放阻挡块收窄，重验
5. 计算难度分，与目标曲线偏差 > 6 → 微调（加/减阻挡块）
6. 采纳
```

**求解器状态 = (格子, 进入方向)** —— 单向块让"进入方向"成为状态的一部分，这是与普通 BFS 的关键差异。求解器**只有一份实现**，在三个地方复用：
- 关卡表流水线：验证可解
- 客户端：提示功能
- 服务端：成绩校验（用预存的 `shortest` 字段 + 朴素路径校验，不重复跑 BFS）

### 5.3 防作弊
服务端对每次成绩上报做完整校验：路径 4 邻接、阻挡块不可穿越、单向块方向、起终点匹配、步数 ≥ 理论最短、用时下限。任一不通过即拒绝入库。

### 5.4 美术方案
零图片资源。所有砖块、按钮、界面、海报均由 Canvas 2D 程序化绘制，纹理用确定性噪声函数生成。好处：包体极小、可任意缩放、随时换色。

## 6. 变现设计（纯 IAA，不做内购）

| 广告位 | 触发 | 说明 |
|---|---|---|
| 激励视频 15s | 首次提示 / 跳过 / 广告解锁皮肤 | 核心收入。15s 完播率显著高于 30s |
| 插屏 | 关卡结算页 | 补量，60 秒频控 |
| Banner | 皮肤页 | 补量，不遮挡操作 |

**原则**：不主动打断、失败兜底发放、中途退出不惩罚不批评。

> 个人主体拿不到版号（周期 9–15 月），因此**只做 IAA，零版号成本**。

- **扁平几何 + 圆角方块 + 细描边**

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 关卡质量参差 | 生成流水线强制求解器体检 + 去重 + 难度分布报告 + 上线前人工抽检 50 关 |
| 玩法太简单导致秒退 | 手感阶段 5 人试玩；必要时加「收集宝石」「颜色匹配」「步数限制」变体（只改求解器与生成器，不动物理层） |
| 备案/审核卡进度 | 域名备案与软著提前 1–3 周启动 |
| 广告不可用（冷启动） | 降级策略：无广告期用签到送皮肤碎片维持留存 |
| 后端写太重 | 只做 8 个接口、5 张写表，不做微服务、不做实时 |

## 10. 后续可扩展玩法

1. **收集式**：路径必须途经所有宝石才能到终点
2. **颜色匹配**：只能走到同色砖块，需按顺序切色
3. **步数限制**：限定最大步数，制造紧张感
4. **每日挑战**：服务端每天生成一个固定种子关卡，所有人同一关

> 这四条**只需改求解器的目标判定 + 生成器的装饰规则**，不动物理层与渲染层。

## 11. 附录：术语

| 术语 | 含义 |
|---|---|
| 正解路径 | 生成器构造的那条合法路径 |
| 理论最短步数 | 求解器 BFS 算出的最短路径长度 |
| 等价解 | 长度相同的最短路径有多条（越多关卡越"水"） |
| 开放面积比 | 可通行格数 ÷ 总格数 |
| 大关 | 每 100 关，相对同段更绕但不那么憋屈 |
| 种子 | 关卡生成的随机源，决定关卡布局 |
