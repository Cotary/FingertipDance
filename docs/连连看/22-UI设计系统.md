## 1. 为什么要重做

T23 补完大厅后，视觉上存在两个硬伤：

| 问题 | 表现 | 根因 |
|---|---|---|
| **风格分裂** | 大厅是浅蓝扁平（`#EEF3FF`），进关卡突然变深色扁平（`#141824`），像两个 App | 双主题 `LOBBY_THEME` / `GAME_THEME` 各自为政 |
| **不够卡通** | 纯色块 + 直角边 + 细字，没有「玩具感」 | 只有 `roundRect + fill` 一种画法，没有体积、光泽、描边 |

改版方向完全对齐用户参考图（`连连看/微信图片_*.jpg`）：
**深色星空底 + 高饱和糖果色 + 厚圆角果冻质感 + 发光**。

---

## 2. 五条设计原则

1. **一个底色**：全应用共用一套夜空渐变，只在层级上区分（背景 < 玻璃卡 < 糖果块）。
2. **一切可点的东西都是「软糖」**：厚底边 + 顶面渐变 + 顶部高光，按下去会下沉。
3. **面用玻璃，块用糖果**：信息承载用半透明玻璃（不抢戏），行动点用高饱和糖果（必须抓眼）。
4. **粗字 + 白描边**：标题一律 `800` 字重，彩底上的文字用同色族的 `dark` 描边，保证任何底色都读得清。
5. **装饰只用几何**：不引入任何图片 / 字体文件 / SVG，星点、锁、奖杯、房子全部路径绘制（微信移植零成本前提）。

## 3. 设计 token（`src/ui/theme.ts`）

### 3.1 颜色

```ts
THEME = {
  skyTop: '#2E2078', skyMid: '#1B1252', skyBottom: '#0B0824',  // 夜空竖向渐变
  bg: '#1B1252', bgLight: '#0B0824', ridge: '#120C3A',          // 主色 / 山影
  glass: 'rgba(255,255,255,0.09)', glassEdge: 'rgba(255,255,255,0.20)',
  panel: '#2A2270', border: 'rgba(255,255,255,0.20)',
  text: '#FFFFFF', subText: '#A9A6E0',
  blue: '#4FC3F7', success: '#7ED957', accent: '#FF6B6B',
  yellow: '#FFD54F', purple: '#B388FF', shadow: 'rgba(6,3,26,0.45)',
}
```

`GAME_THEME` / `LOBBY_THEME` 是 `THEME` 的**别名（同一对象）**，保留是为了不破坏既有 import；
新代码一律用 `THEME`。

### 3.2 糖果色轮 `CANDY`

每个色是四层结构，缺一层就画不出果冻感：

```ts
type CandyColor = { base: string; light: string; dark: string; glow: string }
```

| 键 | base（顶面） | light（高光） | dark（厚底边 / 描边） |
|---|---|---|---|
| `blue` | `#4FC3F7` | `#B3E9FF` | `#1B78C0` |
| `green` | `#7ED957` | `#CDF7B0` | `#3E9A2A` |
| `orange` | `#FFA940` | `#FFD79B` | `#C96A00` |
| `pink` | `#FF6B9D` | `#FFBBD2` | `#BF2C60` |
| `purple` | `#B388FF` | `#DCC7FF` | `#6B3FCB` |
| `gold` | `#FFD54F` | `#FFEFB0` | `#C99400` |
| `coral` | `#FF6B6B` | `#FFB5B5` | `#BE2F2F` |

**语义分配**（不要随便换，玩家靠颜色记功能）：

| 场景 | 用色 |
|---|---|
| 主行动（开始 / 下一关 / 再试一次） | `green` |
| 次级行动（分享 / 翻页 / 返回） | `blue` |
| 皮肤 / 高级内容 / 好友榜 | `purple` |
| 排行榜总榜 Tab / 橙色强调 | `orange` |
| 星级 / 里程碑 / 等级 | `gold` |
| 危险（断线提示 / 惜败 / 终点） | `coral` |
| 起点 / 当前关 | `green` |

### 3.3 圆角 `R` / 间距 `SP` / 字重 `W`

```ts
R  = { sm: 16, md: 24, lg: 32, xl: 44 }        // 只允许这四档
SP = { xs: 8, sm: 16, md: 24, lg: 32, xl: 48 } // 8pt 基准
W  = { regular: 500, mid: 600, bold: 800 }     // 卡通靠粗字撑骨架
```

字号阶梯：`20 / 22 / 24 / 26 / 28 / 32 / 36 / 40 / 48`（设计坐标，等于实际像素 / 2）。

## 4. 绘制原语（`src/ui/draw.ts`）

页面**不允许**自己 `roundRect + fill` 画按钮或卡片，一律调用这些原语 —— 这是「风格一致」的强制执行点。

| 原语 | 用途 | 关键参数 |
|---|---|---|
| `nightSky(ctx, now)` | 全屏夜空：渐变 + 72 颗呼吸星 + 6 颗十字亮星 + 两层山影 | 只在 `frame()` 调一次 |
| `jelly(ctx, x, y, w, h, candy, opts)` | **果冻按钮**：厚底边 + 顶面渐变 + 顶部高光 + 内侧压暗 + 白边 + 描边文字 | `radius / depth / pressed / label / fontSize` |
| `glass(ctx, x, y, w, h, r, opts)` | **玻璃卡片**：半透明白底 + 边光 + 顶部内高光 | `fill / edge / inner / shadow` |
| `pill(ctx, x, y, w, h, candy, label, size)` | 胶囊徽章（Lv、关号、皮肤数） | — |
| `strokeText(ctx, text, x, y, size, opts)` | 描边文字（先描边后填色） | `fill / stroke / strokeWidth / align / baseline` |
| `candyStar / starPath / starRow` | 立体五角星（不用 ★ 字符，跨端一致） | `R / filled / stars` |
| `halo(ctx, cx, cy, r, color)` | 径向光晕（星球、当前关、按钮背光） | — |
| `font(size, weight)` / `mix(hex, to, k)` | 字体简写 / 颜色混合 | — |

### 4.1 果冻按钮的解剖（最重要的一个组件）

```
        ┌──────────────────────┐  ← 白边 rgba(255,255,255,.34) 2px
        │ ▓▓▓ 顶部高光 30% ▓▓▓ │  ← 高度 36%，圆角内缩
        │      base 顶面        │  ← 竖向渐变 light→base→base
        │─── 内侧压暗 10% ─────│
        └──────────────────────┘
        ██████████████████████   ← 厚底边 = candy.dark，下移 depth(≈h×10%)
```

按下时：整体下沉 `depth × 0.75`，厚底边相应变薄 —— 视觉上就是「按扁了一颗软糖」。

### 4.2 描边文字为什么用 `alphabetic` 基线

`strokeText` 内部固定 `textBaseline = 'alphabetic'`，再按字号手动补偿 `dy`（middle → `0.36em`）。

原因：Canvas 的 `middle` 与 SVG 的 `central` 视觉位置不一致，会导致「离线预览看着居中、真机偏下」。
统一用 alphabetic 后，**浏览器实测与离线 SVG 预览完全对齐**，改一处两边都对。

## 5. 组件规范

### 5.1 按钮三态

| kind | 视觉 | 用于 |
|---|---|---|
| `primary` | 果冻，默认 `green` | 屏幕唯一主行动 |
| `secondary` | 果冻，默认 `blue`，可用 `tone` 覆盖 | 并列次级行动 |
| `ghost` | 玻璃半透明 + 白字（无厚底边） | 返回、提示、跳过等轻量操作 |

`Button` 接口新增可选 `tone?: CandyKey`，用来在同一 kind 下换色（如结算页 `next=green / share=blue / skins=purple`）。

**触控区**：设计坐标 ≥ 88×88 → 实际 ≥ 44×44 pt，满足移动端最小点击区。

### 5.2 玻璃卡片

- 承载信息（玩家条、统计卡、列表行、气泡、好友面板）
- 默认 `shadow: true` → 下方 6px 深色同形投影（**不用 `shadowBlur`**，微信 canvas 上逐像素开销大）
- 卡片之间间距 ≥ 12，同组卡片圆角一致（列表行 `22`，主卡 `28~32`）

### 5.3 星级

- 用 `candyStar` 路径绘制，实心金色 / 空心中性玻璃
- 结算页用 `starRow`（中间那颗大 14%，形成主次）
- 地图节点下方用小号三星（`R = 10`），间距 `2.4R`

### 5.4 锁

未解锁内容统一「深紫实心 + 关号 + 右下小锁」或「玻璃格 + 居中大锁」；
**不用 🔒 emoji**（Windows/微信渲染不一致）。

### 5.5 棋盘

| 元素 | 规格 |
|---|---|
| 棋盘底板 | `rgba(9,5,30,0.80)` 圆角 34，四周外扩 14 —— 挡住星空，避免星星透过格子成噪点（0.62 仍漏星点） |
| 未点亮砖块 | `rgba(255,255,255,0.13)` + 2px 边光 `0.22`，`r = 0.20×格宽`。**可通行格必须一眼看出边界**，不要低于 0.12 |
| 点亮砖块 | 皮肤纹理 + 底部厚度（下移 6%）+ 顶部光泽（26%）+ 白贴纸边 |
| 阻挡块 | `rgba(12,7,38,0.94)` + 白叉（`lineWidth = 0.075×格宽`） |
| 单向块 | 同未点亮底 + 橙色淡描边 + 橙色粗箭头 |
| 起点 / 终点 | 糖果圆片（厚底边 + 竖向渐变 + 高光 + 白描边 + **深色实心字**），绿 / 珊瑚。三条硬规则见下 |
| 路径 | 三层：外发光 30%格宽 → 糖果渐变主线 18% → 白芯 6%，转折点加白「糖珠」 |

### 5.x 起终点圆片的三条硬规则

1. **层序**：`drawBoard()` 只给起终格铺一层底板，糖果圆片由 `drawEndpoints()` 在 `drawTrail()` **之后**叠上去。
   连线从格心出发，圆片先画就会被线头横穿，字直接被压在下面 —— 这是最初「起/终 糊成一团」的真正原因，不是字号问题。
2. **字色**：深色实心字（绿格用 `#3E9A2A`、珊瑚格用 `#BE2F2F`），**不描边**。
   「起」「终」笔画密集，叠深色描边会把内部空隙填死；圆片顶面本就偏浅（`light` 打头），深色字对比足够。
3. **高光位置**：`cy - 0.62r`、`ry = 0.16r`、alpha `0.32` —— 必须压在圆的上缘。
   原先落在中部（`cy - 0.45r`, `ry 0.24r`, alpha `0.45`）会直接把字的上半截洗白。

### 5.y 进度条的可见性

- **轨道必须比底色亮**：用 `rgba(255,255,255,0.13)`，不要用 `rgba(10,6,35,0.5)` 这类深色 —— 在深色面板/夜空上等于隐形。
- **加进度头**：填充末端画一颗白色圆珠（`r = h × 0.34`）。早期关卡（37/1000 = 3.7%）填充只有十几像素，没有珠子就只剩一个看不清的小点。
- 结算页细条 `420×14`，游戏内底条 `650×18`。

## 7. 可读性规则

1. **任何文字压在糖果色上**：`fill = #FFFFFF`，`stroke = candy.dark`，`strokeWidth ≈ 0.14×字号`。
2. **任何文字压在夜空上**：`fill = #FFFFFF`（主）或 `#A9A6E0`（次），深色描边 `rgba(8,4,30,0.5)`，宽度 `0.1×字号`。
3. **一片区域内文字不超过三级**（标题 / 主信息 / 辅助），字号差 ≥ 6。
4. **同级信息对齐同一基线网格**：卡片内标签 `+32`、数值 `+68`、列表行主文 `+32`、副文 `+61`。
5. **装饰不得压住内容**：星空、山影、光晕一律先画，内容后画。
