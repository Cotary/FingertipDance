## 硬性约束

- **不要动 `games/line/src/core/` 下的任何文件**。关卡生成器、求解器、难度曲线是本项目的核心资产，本任务一个字都不改。
- **不要改数据库表结构**（`server/migrations/001_init.sql`）。只新增一个只读 GET 接口。
- **不要引入任何图片 / 字体 / SVG 资源**。所有美术必须是 Canvas 2D 程序化绘制，这是微信小游戏零成本移植的前提。
- **不许用 `any`**，不许用 `enum`（用 `as const` 对象）。
- 不许在 `src/`（除 `platform/wechat.ts`）出现 `wx.` 字面量。
- 不要顺手做 T23 之外的东西。总榜周榜、周趋势图、真实 3D 星球都不在本次范围。

## 执行方式

严格按任务书的 Step 1 → Step 10 顺序做，每个 Step 做完立刻验证，不要攒到最后一起改。

关键提示：任务书第 11 节（`main.ts` 大改造）是本任务的核心，**要逐条改而不是整文件重写**。改完后全局搜 `phase ===` 和 `phase !==` 逐个核对，因为 phase 从 5 个值扩到了 8 个值，很容易漏改。

后端：

**验收命令必须真的跑，输出贴出来。没跑过的步骤视为未完成。**

3. 汇报：做了什么、验收命令输出、遇到的问题、哪些步骤需要人工补做

## 遇到这些情况立刻停下并报告（不要自己硬扛）

- `npm install` / `go mod download` 网络错误
- Docker 起不来（后端联调需要）
- 同一个问题连续三次修不好
- 发现主任务书的代码骨架有编译错误或与现有代码签名不符 —— 说明是任务书的问题，记下来并在「遗留问题」表追加一行，然后按现有代码签名做合理调整继续
