### 6.1 昵称头像授权引导 ✅

原来是「我的 → 昵称头像」一个入口，玩家不知道有这回事，分享出去的卡片写着「玩家」。

**为什么不做启动弹窗**：微信 `getUserProfile` 必须由**用户手势**触发，启动时自动调只会失败；而且首屏就问"要不要把头像给我们"，玩家还没玩过任何东西。

**做成三条触达**：

| 时机 | 形式 | 为什么在这里 |
|---|---|---|
| 刚走完引导、回大厅 | toast 指路 | 刚学完、即将开第一关，意愿最高 |
| 大厅底部 | 可忽略的提示条 | 想填就点，不填不碍事 |
| 第一次点分享 | toast 提醒一次 | 唯一「不填就会后悔」的地方（卡片写「玩家」） |

**关键取舍**：提示条与「分享挑战」条**共用同一个槽位**，不同时出现。这一屏纵向间隙加起来只有 103px（CTA→世界卡 32、世界卡→分享条 28、分享条→底注 43），而一条提示要 84 —— 叠加必然压住金色主 CTA（实测过，无尽征途卡直接盖住「继续第 038 关」）。分享入口还有两处（我的页、结算页），换掉一条不会让功能消失。

判据用 `avatar` 而不是 `nickname`：服务端对新用户下发空昵称，而客户端默认昵称是「玩家」，用昵称判会恒为"已填"。

**验证**：`test/profile-prompt.test.ts`（10 条）+ 画廊 `?p=home` 截图核对。

## 八、机制首见说明卡（2026-11-23 凌晨）

补上了第七节里「正式关首次遇到机制时补提示卡」那条。

### 为什么不是让运营逐关配置

1000 关的机制分布由生成器决定，实测首现位置：

| 机制 | 首现关卡 | 出现在多少关 |
|---|---|---|
| 单向门 | **第 13 关** | 616 |
| 星屑 | 第 33 关 | 628 |
| 钥匙 / 门 | 第 65 关 | 88 |
| 传送门 | 第 153 关 | 252 |
| 冰面 | 第 705 关 | 296 |

让运营为 1000 关逐条标「这关弹什么」既做不完，也会和关卡表版本脱节 ——
换了版本、机制提前了，配置还停在老位置，于是提示卡在该出现时不出现。

**所以首现位置由客户端解码 `grid` 自动推导**，运营只管一个总开关。

### 配置项

`/admin/config` → 功能开关 → **机制首见说明**（`features.mechIntro`，默认开）。

关掉则一张都不弹。它是「自动推导」的唯一人工闸门：万一某次关卡表更新让
提示集中弹出，有一个一键关掉的口子。

### 规则

| 情况 | 行为 |
|---|---|
| 第 13 关首次遇到单向门 | 弹「单向门」卡 |
| 同一关有两种新机制（第 65 关钥匙+门） | **只弹一张**，其余顺延到之后遇到它的关 |
| 两种机制是「钥匙 + 门」 | 算**一族**，共用一张卡，见过一个就不再为另一个弹 |
| 引导教过的 5 种 | 引导走完即标记已见 —— 否则第 33 关会再讲一遍星屑 |
| 引导关内 | 不弹（本来就在教） |
| 挑战模式 | 不弹（打断"来比一比"的意图） |
| 玩家直接点棋盘开始拖线 | 卡片立即让位（它不是模态） |
| 5 秒没动 | 自动淡出 |

**为什么单向门是最重要的一条**：它第 13 关就出现，而引导里**没有教**
（和传送门一起出现时玩家分不清"走不过去"的原因是箭头还是传送）。
这条功能一半的价值在它身上。
