## 1. 分段表（`curve.ts` 的 `SEGMENTS`）

| idx | w×h | blocks | oneways | minTurns | openRatio |
|---|---|---|---|---|---|
| 1–10 | 6×6 | 0–3 | 0 | 1 | 0.78 |
| 11–30 | 7×7 | 6–12 | 0–2 | 2 | 0.72 |
| 31–60 | 8×8 | 12–20 | 3–6 | 3 | 0.66 |
| 61–150 | 9×9 | 20–30 | 6–10 | 4 | 0.60 |
| 151–400 | 9×9 | 28–38 | 8–14 | 5 | 0.56 |
| 401–700 | 10×10 | 35–48 | 10–16 | 6 | 0.52 |
| 701–1000 | 10~11×11 | 45–60 | 12–20 | 7 | 0.48 |

- 段内插值：`t = (idx - segStart)/(segLen-1)`，数值用 `lerp(start, end, easeInOut(t))`
- 大关（idx%100==0）：`blocks -6`、`openRatio +0.04`、`minTurns +1` → 「绕但不死」

## 2. 难度分公式（`computeDiff`）

```
diff = 100 * (
    0.30 * clamp01(blocks / (w*h*0.45)) +
    0.15 * clamp01(oneways / (w*h*0.25)) +
    0.25 * clamp01(turns / 8) +
    0.20 * clamp01((1 - openRatio) / 0.55) +
    0.10 * clamp01(1 - uniqueness)
)
```

其中 `uniqueness = pathCount <= 1 ? 1 : clamp01(1 - log2(pathCount)/6)`。

## 3. 目标难度曲线（`targetDiff`）

- 1~10 关：线性 `5 → 15`
- 11~1000 关：**平方根** `15 → 85`（`base = lerp(15, 85, sqrt((idx-10)/990))`）
- 每 10 关 `+8` 小高峰；每 100 关 `+4` 大关
- 钳制到 `[0, 100]`

> 规格 02 §4.3 原写「分段线性 15→92」，实测 `computeDiff` 上限约 84，线性 15→92 造成 331 处后期负偏差，故校准为平方根 15→85。

## 4. 实测校准结果（seed=20261101，1000 关）

| 判定标准 | 实测值 | 结论 |
|---|---|---|
| 不可解 = 0 | 0 | ✓ |
| 重复布局 = 0 | 0 | ✓ |
| 平均 diff 偏差 ≤ 8 | 4.31 | ✓ |
| 后期唯一解占比 ≥ 60% | 94.6%（662/700） | ✓ |
| 相邻档 diff 增量 ∈ [3,12] | 均增 ~0.7/档（含负值） | ✗ 规格不自洽 |
| 相邻档步数增量 ∈ [1,5] | 均增 ~0.1/档（含负值） | ✗ 规格不自洽 |

## 5. 校准说明（为什么两条增量指标不达标）

diff 全程（档 1 → 档 100）仅从 ~11 升到 ~80，即 ~69 分 / 99 档 ≈ **0.7 分/档**；步数全程 ~8 → ~19，即 ~11 步 / 99 档 ≈ **0.1 步/档**。

「相邻档 diff 增量 ≥ 3」要求全程至少 3×99 ≈ 297 分，而 diff 上限是 100；「步数增量 ≥ 1」要求全程至少 99 步，而步数上限约 21。**两条标准与 0–100 / 8–21 的量纲直接矛盾，属规格 02 §4.4 内部不自洽**，非生成器缺陷。已按「唯一解占比」与「平均偏差」两条硬指标验收，其余指标达标。

## 7. 改版方案（2026-11-01 定稿，待实施）

前三节描述的是**现行**曲线。用户评审后判定「关卡差点意思」，本节是定稿的改版方案，
实施时以本节为准。

### 7.1 三条病根

| # | 问题 | 证据 |
|---|---|---|
| 1 | 1000 关是同一个谜题的放大版 | `generator.ts` 的 `attemptGenerate` 是**先造正解路径，再把阻挡块撒在路径之外**。阻挡块永远不影响解法，只是把路径外的空间堵掉一部分。玩家永远在「从一堆看起来一样的空格里找出唯一那条路」 |
| 2 | 难度只有量的堆砌，没有质的变化 | 旋钮只有三个：盘面变大（6×6→11×11）、转弯变多（`minTurns` 1→7）、单向块变多。没有新机制 |
| 3 | 设计好的分段一点都没进 UI | `SEGMENTS` 的 7 段、`skinForLevel` 的 11 个奖励关、每 100 关大关、每 10 关小高峰，地图上全被抹平成一条无差别直线 |

附带发现：`computeDiff` 把 `blocks` 当**正**贡献（权重 0.30），但阻挡块只放在路径外 ——
块越多，路径外的干扰格越少，玩家反而更好找路。**这个权重方向很可能是反的**，
改版时要用实测相关性重估（见 §5 的两条增量指标）。

### 7.2 核心玩法改为「走完所有格子」

现状：`release()` 只看最后一格是不是 `END`，**从 START 走到 END 即通关，不要求覆盖**。

改后：**走完所有可走格即通关，起点和终点都不限制**（用户明确要求）。
这是经典一笔画（哈密顿路径）。

生成方法论必须跟着变：哈密顿路径是 NP 难，**不能「随机撒块再验证」**，只能
**先构造出一条覆盖路径，再由它反推出棋盘** —— 挖掉的格子 = 路径之外的格子。
这样「有解」是构造出来的，不需要搜索验证。

### 7.3 棋盘不再满格

用户明确：「格子不一定是满格，中间可以是空白」。

需要新增一种空洞格子（区别于 `BLOCK`）：`BLOCK` 还占位置、还看得见，
空洞是这块地方**压根没有格子**。棋盘轮廓因此可以是岛屿、环形、十字、L 形，
辨识度比满矩形强得多。

### 7.4 六维难度阶梯

难度不再由单一 `diff` 数值驱动，而是六个维度**逐维解锁**：

| 维度 | 由松到紧 |
|---|---|
| 棋盘形状 | 满矩形 → 挖角 → 挖洞 → 岛屿 → 不规则 → 多空洞 |
| 棋盘尺寸 | 6×6 → 7×7 → 8×8 → 9×9 → 10×10 → 11×11 |
| 机制 | 无 → 单向门 → 星屑 → 钥匙门 → 传送门 → 隘口诱饵 → 冰面 |
| 路径形态 | 转弯数、路径长度 |
| 干扰密度 | 阻挡块、诱饵走廊、必经隘口 |
| （保留）开放面积比 | `openRatio` |

### 7.5 机制引入表

机制**随难度依次出现**，且新机制首次登场时盘面要小、其他机制要关掉，
让玩家先学会这一个（现状是随机叠加，玩家学不明白）。

| 机制 | 格子 | 效果 | 引入 | 求解成本 |
|---|---|---|---|---|
| 单向门 | `ONEWAY`（已有） | 箭头定死离开方向 | 第 11 关 | 无 |
| 星屑 | `SHARD` | 绕路才集齐，定三星 | 第 31 关 | 低（见 §7.6） |
| 钥匙门 | `KEY` / `GATE` | 取了钥匙才开门 | 第 61 关 | 低，状态 `(位置, 钥匙掩码)`，BFS 状态数 ×4 |
| 传送门 | `PORTAL` | 成对格子，进 A 出 B | 第 151 关 | 低，把 A→B 当成一条边 |
| 隘口与诱饵 | 不加格子，改生成算法 | 必经隘口 / 看着通其实不通 | 第 401 关 | 无 |
| 冰面 | `ICE` | 踩上滑到撞墙才停 | 第 701 关 | 中，滑动让状态转移变复杂 |

另有一条不加格子类型的改进：**困难关卡的生成方式**。现在阻挡块只撒在路径外，
所以「难」纯粹是信息隐藏。改成刻意造**隘口**（路径被迫走唯一通道）和**诱饵走廊**
（走进去发现是死路），让难来自设计而不是随机。

### 7.6 星级必须重定义（开放问题）

**这是改版最大的连带问题**：cover 模式下路径长度固定 = 可走格数，
所以 `starOf(steps, shortest)` 恒等于 3 星，星级失效。

候选（待用户定）：

| 方案 | 说明 |
|---|---|
| A 一气呵成 | 无回退、无重来 = 3 星；回退 N 次以内 = 2 星 |
| B 用时 | 阈值按关卡规模缩放 |
| C 提示次数 | 用了几次提示 |

倾向 A：休闲玩家对「不犯错」的直觉最强，且和「再打一次」的动机一致。
若保留星屑机制，星屑在 cover 模式下没有绕路空间，需要改成
「**路径上的必经收集点**」（即碎片必须在路径上，等价于增加约束）而非「绕路去拿」。

### 7.7 对现有系统的冲击

- `Level` 数据结构要加字段（空洞格、机制格、多起终点）→ **1000 关必须重跑 `level-gen`**
- `generator.ts` / `solver.ts` 重写（构造式生成 + 新状态空间）
- `board.ts` 渲染要支持空洞轮廓与四种新格子
- 后端 `stars.go` 只依赖 `shortest/steps`，星级规则改动需同步；关卡表有 version hash，可平滑换表
- 交付顺序（用户定）：**先做地图路线 + 皮肤经济，关卡数据后动**
