## 3. 有哪些玩法

### 3.1 核心规则：铺满全盘

> **走完所有必需格，路径不自交。起点和终点按关卡拓扑决定（见下表）。**

| 项 | 规则 |
|---|---|
| 起手 | 任意必需格都能起手（没有 START 标记）；钉了起点时只能从该格起 |
| 移动 | 四邻接拖动，走过的格不能再走 |
| 通关 | 覆盖**全部**必需格；钉了终点时，线头还必须正好落在终点 |
| **终点** | **只能最后一步踩上**。还有别的格没走时，终点和石障一样进不去（见下） |
| 失败 | 松手时未铺满 → 路径清空，`重来次数 +1` |
| 进度 | HUD 显示 `已铺 52 / 86`、`剩 34`、`下一个 ★2` |

#### 终点为什么必须"像石障一样挡住"

`END` 格本身是可走格，但它的语义是**整条线的收尾**。

早先规则层完全不看 `rs.endAt`，于是 END 和普通砖没区别：玩家可以中途踩上去、
再走开，走完整盘才发现"线头不在终点"，这一笔白费 —— 反馈来得太晚。

石障（BLOCK）的反馈是**立刻**的：根本进不去，玩家当场换路。终点的反馈必须同样早。
所以规则层把 END 做成一道**只在最后一格才开的门**：
`visited` 已覆盖 `n-1` 格时才允许进入。

> 1000 关里 848 关有固定终点，**参考解的 END 全部在末位（848/848）** ——
> 数据一直按这个语义生成，只是规则层没执行。

钉死规则来自拓扑（`D` = 死端数）：`D=0` 完全自由、`D=1` 钉住一端、`D=2` 起终点都固定、`D≥3` 无解。

|---|---|---|---|---|---|
| 一 苗圃 | 1–12 | 5×5 | 21–23 | 教学：铺满 | 13–17 |
| 二 石溪 | 13–32 | 6×6 | 30–34 | 单向门 | 24–29 |
| 三 苔原 | 33–64 | 7×7 | 39–47 | 星屑（顺序） | 35–43 |
| 四 熔炉 | 65–152 | 8×8 | 54–62 | 钥匙与门 | 50–55 |
| 五 深井 | 153–404 | 8×8→9×9 | 61–79 | 传送门 | 56–74 |

### 3.3 六种机制

| 机制 | 规则 | 出现规模 |
|---|---|---|
| **单向门** | 离开方向被箭头钉死，只能往箭头指的方向走 | 616 关 / 2,157 格 |
| **星屑** | 编号 1→2→3，必须按顺序经过；它是必需格，不是可选收集品 | 628 关 / 1,749 格 |
| **钥匙与门** | 先拿钥匙才能进门；两者都必走，难在**时序** | 88 关（成对 176+176 格） |
| **传送门** | 成对格子，进 A 立刻出 B；连线在 A 中心断、B 中心接（不画跨格弧线），两端靠实环/虚环区分 | 252 关 / 504 格 |
| **冰面** | 踩上沿进入方向滑到撞墙；撞冰继续滑，撞门停在门前，传送打断滑行 | 296 关 / 888 格 |
| **隘口与诱饵** | 不加格子，靠形状与拓扑制造「必经独木桥」和「看着通其实不通」 | 融入世界六、七 |

### 3.4 星级：一气呵成

步数恒等于「必需格数 − 1」，所以旧的「步数比最短步数」恒为 3 星、彻底失效。
新规则只看**重来次数**：

| 星 | 条件 |
|---|---|
| ★★★ | 通关且**零重来** |
| ★★ | 重来 1–2 次 |
| ★ | 通关（含重来 ≥3 次） |
| 0 星 | 看广告跳过（跳过不算打过，地图上不点亮） |

### 3.5 辅助与商业化

| 玩法 | 规则 |
|---|---|
| **提示** | 实时求解剩余盘面，给后续 1–2 步；每关第一次提示需看激励视频，之后免费 |
| **跳过** | 看激励视频跳关，每关每天限一次；推进进度但**不给星、不发皮肤** |
| **插屏** | 结算页 500ms 后展示，带频控 |
| **皮肤** | 16 套（默认 2 / 广告解锁 11 / 里程碑 3），Canvas 程序化纹理，无图片资源 |
| **分享挑战** | 分享链接带关卡号 + 重来次数；好友打开后同关竞速，按重来次数判胜负 |
| **大厅** | 主页 / 地图 / 排行榜 / 好友 / 我的，5 Tab |

### 3.6 关卡地图

蛇形四列路线铺 1000 个节点，七个世界各有一道世界门（罗马数字 I–VII）；
每个世界的末关插旗，皮肤奖励关（200/500/900）在地图上标记；

## 4. 关卡设计是怎么样的

### 4.1 两条硬定律（先于一切）

| 定律 | 内容 | 作用 |
|---|---|---|
| **奇偶律** | 按 `(x+y)%2` 黑白染色，必须满足 `|黑 − 白| ≤ 1` | O(area) 前置过滤；挖洞必须成对挖 |
| **连通律** | 所有必需格四邻接必须连通 | 同样 O(area) 前置过滤 |

外加一条拓扑结论：**死端（度 1）数量 `D` 直接决定起终点自由度**。
`D=0` 完全自由、`D=1` 钉住一端、`D=2` 起终点都固定、`D≥3` 无解。
当前表：`D=0` 32 关（世界一二）、`D=1` 120 关（世界三四）、`D=2` 848 关（世界五~七）。

### 4.2 生成算法：构造优先，不是随机试

```
随机搜索生成候选（正向设计形状）
  → 设计阶段就验证可解，并把解带出来
  → 洞只用「奇偶中性单位」：骨牌 2 格 / 2×2 块 4 格
  → 先自由求解得到路径 P，再钉住 P 的首尾
  → 机制只加在 P 上，加完 P 仍合法
  → 可解性 100%，参考解 = 构造出的那条路径
再到编排层（pool.ts）：
  建池 → 全局排序 → 每槽挑 diff ≥ 上一关且盘面不重复的候选
```

关键取舍：

- **v1 的老路「先造路径再把障碍撒在路径外」被废弃**——障碍不影响解法，只制造信息隐藏；
- **「随机挖洞再搜路径」也试过并废弃**——9×9 散洞盘可解率仅 ~27%；
- **确定性求解器会让盘面趋同**（全是蛇形），必须随机序 + 多基线 + 段重建打乱；
- **预算用步数不用毫秒**，否则同 seed 在不同机器上产出不同盘面。

### 4.3 难度模型（v3）

```
diff = 100 × sizeBaseline(必需格数) × (0.60 + 0.55 × structureTerm)

structureTerm = 0.35 × 解数项（越少越难）
              + 0.30 × 转弯数项
              + 0.15 × 最长强制走廊占比
              + 0.12 × 机制项
              + 0.08 × 最深诱饵深度
```

两段式的理由：**规模是跨世界的主轴，结构是同世界内的区分轴**。
指数 0.8 用来压小盘（否则 12 格小盘会被评得过高）。

目标值不是手写的，而是**按池子实测分位带（p10~p90）二次校准**——
v2 的旧目标直接套到 v3 会系统性偏高 3~14 分，够不到。

### 4.4 验收门禁与实测

| 门禁 | 门槛 | 实测 |
|---|---|---|
| 解回放校验 | 100% | 100% |
| 全表去重 | 100% | 1000/1000 |
| 平均难度偏差 | ≤ 8 | **3.22** |
| 规模随世界单调不降 | 100% | 通过 |
| 世界内难度单调不降 | 100% | 通过（最大回落 0） |
| 含障碍关卡 | ≥ 80% | 100% |
| 机制覆盖 | 机制世界 100% | 988 关含机制 |
| 生成总耗时 | < 120s | ~95s |
| 单关最坏耗时 | < 2s | ~90ms |
| 同 seed 复现 | 100% | 单测覆盖 |

### 4.5 数据结构（两张表）

- `data/levels-v3.json` — **含参考解**，只放服务端；
- `data/levels-v3-client.json` — 不含解，打包进客户端（~330 KB）；
- 每格 1 字节：`type(4bit) | dir(2bit) | group(2bit)`，支持 9 种格子；
- 参考解 = 起点 + 每步 2bit，121 格约 30 字节。

服务端校验不跑求解器：线性扫描「不自交 / 四邻接 / 守法 / 覆盖全部必需格 / 步数 = 必需格−1」。
